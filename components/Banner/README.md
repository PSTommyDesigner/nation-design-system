# Banner

แถบแจ้งที่อยู่ในสายเนื้อหา บอกสถานะที่ยังค้างอยู่ และคาอยู่จนกว่าจะกดปิดหรือจนกว่าเรื่องนั้นจะจบ ตรงกับไฟล์ออกแบบหน้า **19 Toasts and Banners**

สเปคขนาดทุกค่าอยู่ที่ `tokens/scale/banner.mjs` และออกมาเป็น CSS variable ที่ `tokens/output/css/variables.css` ไฟล์ในโฟลเดอร์นี้ไม่มีค่าขนาดหรือสีของตัวเอง

## ใช้ตัวไหน Banner หรือ Toast

| โจทย์ | ใช้ตัวไหน | เพราะอะไร |
|---|---|---|
| สถานะที่ยังค้างอยู่ของหน้า เช่น ระบบจะปิดปรับปรุงคืนนี้ | `Banner` | ต้องอยู่ให้เห็นตลอดที่เรื่องนั้นยังไม่จบ |
| สรุปข้อผิดพลาดของฟอร์มตอนกดส่ง | `Banner` | ต้องย้ายโฟกัสมาได้ และต้องอยู่จนผู้ใช้แก้เสร็จ |
| ผลของปุ่มที่ผู้ใช้เพิ่งกด เช่น บันทึกข่าวแล้ว | `Toast` | เป็นเรื่องที่จบแล้ว ไม่ต้องคาไว้ให้เกะกะ |

ความต่าง 3 ข้อที่สำคัญ

- Banner อยู่ในสายเนื้อหา Toast ลอยทับเนื้อหา
- Banner ไม่หายเอง Toast หายเอง (ยกเว้นชนิด `error`)
- Banner ไม่มีเงา Toast มีเงา `shadows/bottom/md`

## Usage

```tsx
import { Banner } from '@/components/Banner';

// ระดับหน้า กว้างเต็มจอ มุมโค้ง 0
<Banner
  level="page"
  type="warning"
  title="ระบบจะปิดปรับปรุงคืนนี้"
  description="ตั้งแต่ 23:00 ถึง 01:00 จะบันทึกข่าวไม่ได้ชั่วคราว"
  onClose={() => setShown(false)}
/>

// ระดับกล่องเนื้อหา มีมุมโค้ง ใช้เป็นสรุปข้อผิดพลาดของฟอร์ม
const bannerRef = useRef<HTMLDivElement>(null);

<Banner
  ref={bannerRef}
  type="error"
  title="กรอกข้อมูลไม่ครบ"
  description="ยังขาดหัวข้อข่าวและหมวด"
  announce
  showClose={false}
  action={{ label: 'ไปที่ช่องแรกที่ขาด', onClick: focusFirstError }}
/>

// ย้ายโฟกัสมาที่แถบตอนกดส่งแล้วไม่ผ่าน
bannerRef.current?.focus();
```

## Props

| prop | ค่าเริ่มต้น | หน้าที่ |
|---|---|---|
| `title` | จำเป็น | หัวข้อ บรรทัดแรกของแถบ |
| `type` | `default` | `default` `brand` `error` `warning` `success` |
| `size` | `md` | `xs` ถึง `xl` |
| `level` | `section` | `page` กว้างเต็มมุมโค้ง 0 หรือ `section` อยู่ในกล่องเนื้อหา |
| `description` | | ข้อความรอง อยู่ใต้หัวข้อ |
| `showIcon` | `true` | แสดงไอคอนบอกชนิด |
| `showDescription` | แสดงเมื่อมี `description` | แสดงข้อความรอง |
| `showAction` | แสดงเมื่อมี `action` | แสดงปุ่มกระทำ |
| `showClose` | `true` | แสดงปุ่มปิด |
| `icon` | ไอคอนประจำชนิด | ใช้ไอคอนอื่นแทน รับได้เฉพาะชื่อจากชุดไอคอนของ DS |
| `action` | | ปุ่มกระทำ มีได้ปุ่มเดียว รับ `label` `onClick` และ `icon` ตัวปุ่มคือ `LinkButton` ตระกูล neutral |
| `onClose` | | เรียกเมื่อกดปุ่มปิด แถบไม่หายเอง ต้องกดปิดเท่านั้น |
| `closeLabel` | `ปิดแถบแจ้ง` | ชื่อปุ่มปิดที่โปรแกรมอ่านหน้าจอจะอ่าน |
| `announce` | `false` | ประกาศให้โปรแกรมอ่านหน้าจอ ดูหัวข้อการเข้าถึง |
| `announcement` | จาก `title` และ `description` | ข้อความที่จะประกาศ ใช้เมื่อหัวข้อไม่ใช่ข้อความล้วน |

ส่ง `ref` ได้ เพื่อเรียก `focus()` จากข้างนอก

## 2 ระดับ

ต่างกันที่มุมโค้งอย่างเดียว ไม่ได้ต่างกันที่สี วิธีแยกแบบนี้เป็นของ Fluent 2 และไม่ต้องเพิ่มแกนสีให้ระบบ

| ระดับ | มุมโค้ง | ใช้ที่ไหน |
|---|---|---|
| `page` | `--ntg-banner-radius-page` คือ 0 | บนสุดของหน้า ยืนเต็มความกว้างจนชนขอบจอทั้งสองข้าง ถ้าใส่มุมโค้งจะเห็นสีพื้นหลังโผล่ที่มุมแล้วดูเหมือนวางผิดที่ |
| `section` | `--ntg-banner-radius-section-{size}` คือ 8 ถึง 24 | ในกล่องเนื้อหา กว้างเท่าคอลัมน์ที่มันอยู่ |

## สี 5 ชนิด

ชุดเดียวกับ Toast ทุกค่า ทรงเดียวคือพื้นสีอ่อน หัวข้อกับข้อความรองเป็นสีเทาเข้มทุกชนิด ไอคอนใช้ขั้น 700 ของตระกูลนั้น

| ชนิด | พื้นหลัง | ไอคอน |
|---|---|---|
| `default` | `--ntg-color-background-general-secondary` | `--ntg-icon-general-primary` |
| `brand` | `--ntg-color-background-brand-primary` | `--ntg-icon-brand-on-subtle` |
| `error` | `--ntg-color-background-system-error-primary` | `--ntg-icon-system-error-on-subtle` |
| `warning` | `--ntg-color-background-system-warning-primary` | `--ntg-icon-system-warning-on-subtle` |
| `success` | `--ntg-color-background-system-success-primary` | `--ntg-icon-system-success-on-subtle` |

หัวข้อใช้ `--ntg-color-text-general-heading` ข้อความรองใช้ `--ntg-color-text-general-text` ปุ่มปิดใช้ `--ntg-icon-general-secondary`

ไม่มีชนิด `info` ผู้ใช้ตัดสินแล้วว่าไม่เอา

## ตัวอักษรตามขนาด

ใช้ preset เท่านั้น ไม่มีการประกอบคอมโบเอง ชุดเดียวกับ Toast ทุกขั้น เพื่อให้สองตัวนี้วางคู่กันแล้วตัวอักษรเท่ากัน

| ขนาด | หัวข้อ | ข้อความรอง |
|---|---|---|
| `xs` | `label/sm` | `body/xs` |
| `sm` | `label/md` | `body/xs` |
| `md` | `label/lg` | `body/sm` |
| `lg` | `label/xl` | `body/md` |
| `xl` | `title/lg` | `body/lg` |

## การเข้าถึง

- ตัวแถบเป็น `role="group"` พร้อม `aria-labelledby` ที่ชี้ไปหัวข้อ ตามที่ Fluent 2 ทำกับ MessageBar
- **live region แยกออกจากกล่องที่มองเห็น** ถ้าใส่ `aria-live` หรือ `role` ลงบนกล่องที่มองเห็น โปรแกรมอ่านหน้าจอจะอ่านสองรอบ รอบแรกตอน live region เปลี่ยน รอบสองตอนผู้ใช้เลื่อนไปเจอแถบนั้น Base Web เขียนเหตุผลไว้ในโค้ด และ Fluent 2 กับ Radix แยกออกมาแบบเดียวกัน
- `default` กับ `brand` ใช้ `polite` ส่วน `error` `warning` `success` ใช้ `assertive`
- **`announce` ค่าเริ่มต้นเป็น `false`** ต่างจาก Toast โดยตั้งใจ เพราะแถบในสายเนื้อหามักอยู่ที่หน้าตั้งแต่โหลดเสร็จ ไม่ใช่ของที่เพิ่งเกิด ถ้าประกาศทุกใบตอนโหลด ผู้ใช้จะได้ฟังของที่ไม่ได้เพิ่งเปลี่ยน เปิดเป็น `true` เมื่อแถบนั้นโผล่มาจากการกระทำของผู้ใช้
- **แถบรับโฟกัสจากการสั่งในโค้ดได้** ตั้ง `tabIndex={-1}` ไว้แล้ว ส่ง `ref` เข้ามาแล้วเรียก `focus()` ได้ ต่างจาก Toast ที่ห้ามแย่งโฟกัส เพราะแถบใช้เป็นสรุปข้อผิดพลาดของฟอร์ม ซึ่งต้องย้ายโฟกัสมาเมื่อกดส่ง Primer ตั้ง `tabIndex: -1` ที่ `section` และ Polaris เปิดเมธอด `focus()` ให้เรียกจากข้างนอกเหมือนกัน
- ตัวแถบไม่มีวงแหวนโฟกัสของตัวเอง เพราะไม่อยู่ในลำดับ Tab ของหน้า วงแหวนจึงไม่มีใครได้เห็น ส่วนปุ่มปิดและปุ่มกระทำมีวงแหวนของตัวเองอยู่แล้ว
- **ปุ่มปิดเป็นพี่น้องของกลุ่มข้อความ ไม่ใช่ลูกของมัน** React Aria ระบุว่าลำดับใน DOM มีผลกับสิ่งที่ผู้ใช้ได้ยิน
- **พื้นที่แตะของปุ่มปิดไม่ต่ำกว่า 44** ตามเกณฑ์ WCAG 2.5.5 ขยายด้วย pseudo element ไม่ได้ขยายกล่องจริง

## ข้อควรระวัง

- **ห้ามใส่เงา** เงาสื่อว่าของชิ้นนั้นลอยอยู่เหนือหน้า ซึ่งขัดกับความหมายของแถบในสายเนื้อหา และไม่มีเจ้าไหนในงานวิจัยใส่เงาให้แถบแบบนี้ ของเดิมในไฟล์ออกแบบใส่ `shadows/bottom/xs` ไว้ และถูกถอดออกแล้ว
- **ห้ามตั้งความกว้างและความสูง** ความกว้างมาจากกรอบแม่เสมอ ความสูงมาจากเนื้อหา ถ้าตรึงไว้ ข้อความที่ตัดหลายบรรทัดจะล้นออกนอกแถบ
- **ไม่มีสถานะ disabled ที่ตัวแถบ** สถานะอยู่ที่ปุ่มข้างในเท่านั้น
- **ปุ่มกระทำมีได้ปุ่มเดียว** และอยู่ใต้ข้อความเสมอ ไม่ใช่ท้ายแถวเดียวกัน ของเดิมวางไว้ท้ายแถว ซึ่งพอข้อความยาวหลายบรรทัดปุ่มจะลอยอยู่กลางอากาศ
- **ปุ่มกระทำต้องเป็น `LinkButton` ตระกูล neutral เท่านั้น** ห้ามเปลี่ยนไปใช้ปุ่มชนิดอื่น เพราะในไฟล์ออกแบบหน้า 19 ปุ่มกระทำของทุกแบบเป็น instance ของชุด `link-button` ตระกูล Neutral Button ถ้าโค้ดใช้ปุ่มชนิดอื่น สองฝั่งจะอ้างคนละชิ้นงาน
- **ปุ่มกระทำไม่ไล่สีตามชนิดของแถบ** เหตุผลข้อแรกคือไอคอนกับพื้นหลังบอกชนิดอยู่แล้ว ปุ่มไม่ต้องย้ำอีกชั้น ข้อสองคือตระกูลสีของปุ่มไม่มี warning และ success ให้จับคู่
- **ไม่มี token ระยะเยื้อง** เพราะไอคอนอยู่คอลัมน์ของตัวเอง ข้อความรองและปุ่มกระทำจึงตรงแนวกับหัวข้อเองอยู่แล้ว
- **แถบระดับ `page` ต้องวางนอกกรอบที่มีระยะขอบ** ไม่งั้นมุมโค้ง 0 จะไม่ชนขอบจอและดูเหมือนวางผิดที่

## ยังไม่มีในรุ่นนี้

- **ภาพเข้าออก** แถบในสายเนื้อหาไม่ได้โผล่มาทับอะไร จึงยังไม่ได้ทำภาพเคลื่อนไหวให้
- **หลายปุ่มกระทำ** ตัดสินแล้วว่ามีได้ปุ่มเดียว
- **โหมดมืด** ยังไม่มีแผนทำทั้งระบบ
