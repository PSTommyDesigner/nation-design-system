# components/

Open this file before editing code in `components/`.
To use a component in a screen, read `context/components/AGENTS.md` and the component's spec instead.

## What a component folder holds
| File | What it is | Edit by hand? |
| --- | --- | --- |
| `<Name>.tsx` | The React component. Props, defaults and a header comment with its rules | Yes |
| `index.ts` | Exports | Yes |
| `<Name>.base.css` | How it is drawn. No token names at all. Every value comes from local `--<short>-*` variables | Yes |
| `<Name>.module.css` | Generated: `.base.css` plus the values from the Figma spec | MUST NOT |
| `<Name>.stories.tsx` | Storybook stories | Yes |
| `README.md` | Usage and props table, mostly in Thai | Yes |

- When a folder has `<Name>.base.css`, its `.module.css` is generated by `scripts/generate-component-css.mjs` from `tokens/figma-layers/<id>.json`. The generated file's header says what to edit
  - Change how it is drawn: edit `<Name>.base.css`, then run `npm run css:generate -- <id>`
  - Change a value (spacing, color and so on): change it in the Figma page, then run `npm run figma:layers -- <id>` and `npm run css:generate -- <id>`
- Every color, spacing, radius and size comes from `--ntg-` CSS variables. No hard-coded values
- Hover, focus and disabled come from CSS pseudo-classes and native attributes, not from props
- The library doesn't load fonts. The project that uses it loads Prompt and Sarabun (Storybook loads them in `.storybook/preview-head.html`)

## Props and Figma
- Prop names differ from Figma names on purpose (`default-gray` in Figma is `defaultGray` in code). The map is written by hand in `tokens/figma-components.json`. Anything meant to have no match goes in `accepted` with the reason
- After changing a component's axes or properties in Figma, MUST update `tokens/figma-components.json`, then run `npm run verify:api` (set 2026-10-15. All components were captured on 2026-10-19; before that only Tag was)
  - This gate compares the variant axes and component properties in the Figma file with the real props in the `.tsx`. It catches both missing props and missing values on an axis
  - Why it exists: Figma once gained `left-icon` (3,465 variants) and the `icon-tag` set (1,575 variants) while `components/Tag` supported none of it, and no gate warned
  - `file` and `propsType` point at a sub-component that lives in another component's file, for example `AvatarGroup` in `Avatar.tsx`
  - `axesFromSetNames` is an axis that Figma doesn't build as an axis but splits into sets with different names (for example `semi-rounded-badge` and `pill-badge`). Code folds it into one prop. Write this axis yourself when you capture data, or the gate won't see shapes the code doesn't support yet
  - MUST NOT guess what a property means from its name. Open the set's children first. On 2026-10-19 `leading-icon-swap` on page 22 was read as an icon before the text. It was really the icon of the icon-only set
- A component that has a size formula MUST have code here. See `npm run verify:coverage` in `tokens/AGENTS.md`

## Before you say it's done
- `npm run typecheck` shows 0 errors
- `npm run verify:css` passes, so every generated `.module.css` matches its Figma spec
- `npm run verify:api` passes if props or Figma axes changed
- Check it in a preview (`npm run storybook`, then a screenshot). Don't leave the checking to the user
- New or changed props are in the README props table and in the stories
- The component's entry in `context/design-system.dsds.yaml`, and its spec in `context/components/` if it has one, match the new code. Run `node scripts/check-dsds.mjs`

## New component checklist
1. Ask first. Name it by the Figma set, ending with its type (see `context/workflows/figma-ds-file/`)
2. Size formula in `tokens/scale/<id>.mjs`, registered in `tokens/scale/index.mjs`, then `npm run tokens:build`
3. Effect assigned in Figma (see `context/workflows/figma-ds-file/`)
4. Entry in `tokens/figma-components.json`, then `npm run verify:api` and `npm run verify:coverage`
5. `.tsx`, `index.ts`, `.base.css`, generated `.module.css`, stories, README
6. A stub in `context/design-system.dsds.yaml`, and a spec in `context/components/` copied from `_template.dsds.yaml`
