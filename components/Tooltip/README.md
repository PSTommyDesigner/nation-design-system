# Tooltip

กล่องข้อความสั้นที่โผล่เมื่อชี้หรือโฟกัสที่ตัวกระตุ้น อธิบายว่าของชิ้นนั้นคืออะไรหรือทำอะไร แล้วหายไปเมื่อเลื่อนออก ตรงกับไฟล์ออกแบบหน้า **20 Tooltips**

สเปคขนาดทุกค่าอยู่ที่ `tokens/scale/tooltip.mjs` และออกมาเป็น CSS variable ที่ `tokens/output/css/variables.css` ไฟล์ในโฟลเดอร์นี้ไม่มีค่าขนาดหรือสีของตัวเอง

> **⚠️ ห้ามใส่ข้อมูลที่จำเป็นต่อการใช้งานใน tooltip เพราะผู้ใช้มือถือจะไม่เห็นเลย**
>
> คำใบ้ถูกซ่อนทั้งหมดบนจอสัมผัส ทั้งชั้น CSS และชั้น TypeScript ซึ่งเป็นสิ่งที่ตลาดฝั่งเว็บ 6 เจ้าทำตรงกัน ช่องทางหลักขององค์กรคือมือถือเกิน 70 เปอร์เซ็นต์ แปลว่าข้อมูลที่อยู่ในคำใบ้คือข้อมูลที่ผู้ใช้ส่วนใหญ่ไม่ได้อ่าน ให้ถือว่าคำใบ้เป็นของเสริมสำหรับคนทำงานหลังบ้านที่ใช้เมาส์และคีย์บอร์ดเท่านั้น ข้อมูลที่ขาดไม่ได้ต้องอยู่ในหน้าจริง

## ใช้ตัวไหน Tooltip หรือ Popover

| โจทย์ | ใช้ตัวไหน | เพราะอะไร |
|---|---|---|
| บอกว่าปุ่มไอคอนนี้ชื่ออะไร | `Tooltip` relationship `label` | ปุ่มไม่มีข้อความ คำใบ้คือชื่อของมัน |
| เติมคำอธิบายให้ปุ่มที่มีชื่ออยู่แล้ว | `Tooltip` relationship `description` | เป็นข้อมูลเสริม ไม่ใช่ชื่อ |
| มีลิงก์ ปุ่ม หรือช่องกรอกข้างใน | popover | คำใบ้ไม่รับของที่กดได้ ดูหัวข้อถัดไป |
| ต้องเปิดด้วยการคลิกแล้วค้างไว้ให้อ่าน | popover | คำใบ้ปิดเมื่อเลื่อนตัวชี้ออก |
| ข้อความยาวเป็นย่อหน้า มีหัวข้อย่อย | popover | คำใบ้มีได้ 2 บรรทัดความหมาย คือข้อความหลักกับข้อความรอง |

สรุปสั้น คำใบ้กระตุ้นด้วยการชี้หรือโฟกัส มีแต่ตัวหนังสือ และกดอะไรข้างในไม่ได้ ของที่กระตุ้นด้วยการคลิกและมีของที่กดได้ข้างในเป็นของอีกชิ้นหนึ่ง

**ห้ามใส่ลิงก์หรือปุ่มข้างในคำใบ้** ผู้ใช้คีย์บอร์ดและผู้ใช้จอสัมผัสเข้าถึงของที่กดได้ในคำใบ้ไม่ได้เลย W3C ห้ามข้อนี้ และ DS 5 เจ้าเขียนห้ามตรง ๆ และ Gestalt เคยทำแล้วประกาศถอนออกเพราะเข้าถึงไม่ได้ **ถ้าต้องมีของที่กดได้ ให้ใช้ popover** ที่นี่บังคับ 2 ชั้น

1. ชั้นชนิดข้อมูล `title` กับ `description` รับเฉพาะ `string` ไม่รับ `React.ReactNode`
2. ชั้นเวลาทำงาน ถ้าพบของที่รับโฟกัสได้ในกล่องจะเตือนที่คอนโซลตอนพัฒนา

## Usage

```tsx
import { Tooltip } from '@/components/Tooltip';
import { IconButton } from '@/components/IconButton';
import { Button } from '@/components/Button';
```

### ปุ่มไอคอนล้วน คำใบ้คือชื่อของปุ่ม

```tsx
<Tooltip title="ตัวหนา" relationship="label">
  <button type="button" className="toolbar-button">
    <Icon name="bold" size={16} />
  </button>
</Tooltip>
```

### ปุ่มที่มีชื่ออยู่แล้ว คำใบ้มาเติมข้อมูล

```tsx
<Tooltip
  title="เผยแพร่ทันที"
  description="ข่าวจะขึ้นหน้าแรกภายใน 1 นาที และแจ้งผู้ติดตามทุกคน"
  relationship="description"
  placement="bottom"
>
  <Button family="brand">เผยแพร่</Button>
</Tooltip>
```

### ข้อความซ้ำกับชื่อปุ่มอยู่แล้ว

```tsx
<Tooltip title="บันทึก" relationship="inaccessible">
  <Button family="neutral">บันทึก</Button>
</Tooltip>
```

### ใช้กับ `IconButton` ของ DS

`IconButton` บังคับให้ส่ง `label` แล้วมันตั้ง `aria-label` กับ attribute `title` ของเบราว์เซอร์ให้เองทั้งคู่ เวลาครอบด้วยคำใบ้จึงต้องรู้ 2 ข้อ

1. ใช้ `relationship="inaccessible"` เพราะปุ่มมีชื่ออยู่แล้ว ถ้าใช้ `label` ชื่อจาก `aria-label` จะชนะแล้วข้อความในคำใบ้จะไม่ถูกอ่าน (ที่นี่เตือนให้ตอนพัฒนา)
2. attribute `title` ของเบราว์เซอร์จะโผล่เป็นคำใบ้ของเบราว์เซอร์ซ้อนขึ้นมาอีกกล่อง ซึ่งเป็นกลไกที่ตกข้อ WCAG 1.4.13 ทั้งสามข้อย่อย **ยังแก้ไม่ได้จากฝั่งนี้** ต้องรอให้ `IconButton` เปิดทางให้ปิด `title` ได้ ดูหัวข้อ "ยังไม่มีในรุ่นนี้"

```tsx
<Tooltip title="ตัวเลือกเพิ่มเติม" relationship="inaccessible">
  <IconButton icon="more-vert" label="ตัวเลือกเพิ่มเติม" family="neutral" />
</Tooltip>
```

## Props

| prop | ค่าเริ่มต้น | หน้าที่ |
|---|---|---|
| `title` | จำเป็น | ข้อความของคำใบ้ รับเฉพาะข้อความล้วน |
| `relationship` | **จำเป็น ไม่มีค่าเริ่มต้น** | `label` `description` `inaccessible` ดูหัวข้อการเข้าถึง |
| `children` | จำเป็น | ตัวกระตุ้น เป็น element เดียว คำใบ้เติม aria ให้ตัวนี้ |
| `description` | ไม่มี | ข้อความรอง อยู่ใต้ข้อความหลัก |
| `size` | `md` | `xs` ถึง `xl` |
| `placement` | `top` | 12 ค่า ดูหัวข้อตำแหน่ง |
| `arrow` | `true` | แสดงลูกศรหรือไม่ เป็นสวิตช์แยกจากตำแหน่ง |
| `id` | ระบบคิดให้ | id ของกล่องคำใบ้ ปกติไม่ต้องส่ง |
| `className` | ไม่มี | คลาสเพิ่มของกล่องคำใบ้ |
| `wrapperClassName` | ไม่มี | คลาสเพิ่มของกล่องครอบตัวกระตุ้น ใช้เมื่อต้องจัดผังของตัวกระตุ้น |

## ขนาด 5 ขั้น

ขั้นละเดินตามสูตรใน `tokens/scale/tooltip.mjs` ทุกค่าอ้าง `--ntg-tooltip-*`

| ขั้น | ใช้เมื่อไหร่ | ระยะขอบ | ฐานลูกศร | ระยะจากตัวกระตุ้น | กว้างสูงสุด เดสก์ท็อป | กว้างสูงสุด มือถือ | มุมโค้ง |
|---|---|---|---|---|---|---|---|
| `xs` | แถบเครื่องมือที่หนาแน่นมากในหลังบ้าน | 8 | 8 | 4 | 200 | 160 | 4 |
| `sm` | ความหนาแน่นเท่าที่ DS เจ้าอื่นใช้กัน | 10 | 10 | 5 | 240 | 200 | 6 |
| `md` | ค่าเริ่มต้นของระบบ หลังบ้านทั่วไป | 12 | 12 | 6 | 280 | 240 | 8 |
| `lg` | หน้าที่ตัวอักษรใหญ่กว่าปกติ | 14 | 14 | 7 | 320 | 280 | 10 |
| `xl` | จอใหญ่ระยะไกล เช่นจอในห้องข่าว | 16 | 16 | 8 | 360 | 320 | 12 |

ความสูงลูกศรเป็นครึ่งหนึ่งของฐานเสมอ คือ 4, 5, 6, 7, 8 ตามลำดับ ซึ่งเป็นอัตราส่วน 2 ต่อ 1 เดียวกับ Carbon, Ant, Material และ Spectrum

> **⚠️ ถ้าต้องการความหนาแน่นเท่าที่ตลาดใช้กัน ให้เลือก `sm` ไม่ใช่ `md`**
>
> ตลาดใช้ตัวอักษร 12 ซึ่งในระบบเราคือ `label/sm` จึงตรงกับขั้น `sm` ส่วน `md` เป็นค่าเริ่มต้นของระบบที่ใช้ 14 เหตุผลที่บันไดเดินแบบนี้อยู่ที่หัวไฟล์ `tokens/scale/tooltip.mjs`

## ตัวอักษรตามขนาด

ใช้ preset เท่านั้น ห้ามประกอบเอง ข้อความหลักกับข้อความรองตัวเท่ากันทุกขั้น แยกกันด้วยน้ำหนักอย่างเดียว

| ขั้น | ข้อความหลัก | ข้อความรอง | ขนาดตัวอักษร |
|---|---|---|---|
| `xs` | `label/xs` | `meta/credit` | 10 |
| `sm` | `label/sm` | `body/xs` | 12 |
| `md` | `label/md` | `body/sm` | 14 |
| `lg` | `label/lg` | `body/md` | 16 |
| `xl` | `label/xl` | `body/lg` | 18 |

ขั้น `xs` ใช้ `meta/credit` เพราะเป็น preset น้ำหนักปกติตัวเดียวที่ขนาด 10 ชื่อ CSS variable ของหมวด `meta` แบนชั้นหมวดทิ้งไปแล้ว จึงเป็น `--ntg-typography-*-credit`

## สี ทรงเดียว พื้นเข้ม

| ส่วน | token |
|---|---|
| พื้นกล่องและพื้นลูกศร | `--ntg-color-background-general-solid` |
| ข้อความหลักและข้อความรอง | `--ntg-color-text-general-const-white` |
| เงาของกล่อง | `--ntg-shadows-bottom-md` |
| ลูกศร | ไม่มีเงา |
| ชั้นการวางซ้อน | `--ntg-layer-floating` |

**ไม่มีแกนโหมดมืด** สีพลิกเองตามโหมดของตัวแปร ถ้าทำแกนเพิ่มจะมีกล่องที่สีไม่ตรงกับโหมดของหน้าที่มันอยู่

ข้อความรองใช้สีขาวเหมือนข้อความหลัก **ไม่ใช่เทาอ่อน** ของเดิมในไฟล์ออกแบบใช้เทาอ่อนบนพื้นเข้มซึ่งได้คอนทราสต์ 3.79 ไม่ผ่านเกณฑ์ 4.5 ของ WCAG 1.4.3

ปรับชั้นการวางซ้อนจากข้างนอกได้ด้วยการตั้ง `--tooltip-layer` ไม่ต้องแก้ไฟล์ CSS

## ตำแหน่ง

`placement` รับ 12 ค่า คือ `top` `top-start` `top-end` `bottom` `bottom-start` `bottom-end` `left` `left-start` `left-end` `right` `right-start` `right-end`

> **ชื่อหมายถึงที่ที่กล่องไปอยู่เทียบกับตัวกระตุ้น ไม่ใช่ทิศที่ลูกศรชี้** `placement="top"` คือกล่องอยู่เหนือตัวกระตุ้น และลูกศรชี้ลง ของเดิมในไฟล์ออกแบบตั้งชื่อตามทิศของลูกศรซึ่งกลับทางกับทุกเจ้าในตลาด

**ที่วาดไว้ในไฟล์ออกแบบหน้า 20 มี 4 ค่า** คือแบบจัดกลางของทั้ง 4 แกน อีก 8 ค่าเป็นของฝั่งโค้ด ใช้ได้เลย แต่ไม่มีภาพเทียบในไฟล์ออกแบบ

ระยะจากตัวกระตุ้นถึงขอบกล่องคือ `--ntg-tooltip-offset-*` **นับจากขอบกล่อง ไม่รวมลูกศร** ค่านี้เท่ากับความสูงลูกศรทุกขั้นพอดี แปลว่าปลายลูกศรแตะตัวกระตุ้น และช่องว่างถูกลูกศรปิดสนิท

ตำแหน่งลูกศรของแบบชิดขอบเว้นจากขอบเท่ามุมโค้งของขนาดนั้น เพื่อไม่ให้ลูกศรไปโผล่ตรงส่วนที่มุมโค้งกินไปแล้ว

## กลไกพลิกเมื่อชนขอบจอ สเปค ยังไม่ได้ติดตั้ง

รุ่นนี้วางตำแหน่งด้วย CSS เทียบกับตัวกระตุ้นตรง ๆ **ยังไม่มีกลไกพลิก** กล่องที่ชนขอบจอจะล้นออกไป สเปคที่ตัดสินแล้วสำหรับรอบถัดไปคือลำดับ 3 ขั้น ซึ่งเรียบเรียงจากพารามิเตอร์ของ `flip` และ `shift` ที่ตลาด 14 ใน 15 เจ้าใช้ร่วมกัน

1. **เลื่อนก่อน** ยังอยู่ด้านเดิมแต่เลื่อนไปตามแกนขวางให้พ้นขอบ โดยเผื่อระยะ 8 เท่ากับ `--ntg-size-space-s1-lg`
2. **ถ้าเลื่อนแล้วยังไม่พอ ให้พลิกไปด้านตรงข้าม** คือ `top` ไป `bottom` และ `left` ไป `right`
3. **ถ้าพลิกแล้วก็ยังไม่พอ ให้เลือกด้านที่ล้นน้อยที่สุด** ไม่ใช่กลับไปด้านเดิม

**ตัวที่ตั้งไว้ว่าอยู่บนจะพลิกได้แค่บนกับล่าง ไม่กระโดดไปซ้ายขวาเอง** ข้อนี้เป็นค่าเริ่มต้นของ Floating UI (`fallbackAxisSideDirection` เป็น `none`) และเป็นการตั้งใจ เพื่อไม่ให้ตำแหน่งเดากันไม่ได้

การติดตั้งจริงต้องวัดกรอบจอกับกรอบตัวกระตุ้นตอนทำงาน ซึ่ง CSS ทำไม่ได้ **ยังไม่ติดตั้งไลบรารีจัดตำแหน่งเพิ่มในรอบนี้** ถ้าจะทำต้องขออนุมัติก่อน

## จังหวะเวลา

| เรื่อง | ค่า | มาจากไหน |
|---|---|---|
| หน่วงก่อนโผล่ เมื่อชี้ด้วยตัวชี้ | 300 | ตรงกับ Atlassian และ Untitled UI |
| หน่วงก่อนโผล่ เมื่อโฟกัสด้วยคีย์บอร์ด | 0 | การกด Tab เป็นการตั้งใจอยู่แล้ว ไม่ใช่ตัวชี้ที่ไหลผ่าน วิธีเดียวกับ Spectrum |
| หน่วงก่อนหาย เมื่อตัวชี้ออก | 150 | มัธยฐานของตลาด มีไว้กันการกระพริบตอนย้ายข้ามรอยต่อ |
| หน่วงก่อนหาย เมื่อเลิกโฟกัสหรือกด Escape | 0 | ปิดทันที วิธีเดียวกับ Fluent 2 |
| ช่วงผ่อนผัน | 300 | ตรงกับ `skipDelayDuration` ของ Radix |

ค่าทั้งหมดอยู่ที่ `TOOLTIP_TIMING` ส่งออกมาให้อ่านได้ แต่ไม่มี prop ให้ทับ เพื่อให้ทุกที่ในระบบใช้จังหวะเดียวกัน

**ช่วงผ่อนผันคืออะไร** ถ้ามีคำใบ้ใบไหนในหน้าเพิ่งปิดไปไม่เกิน 300 ใบถัดไปจะเปิดทันทีโดยไม่รอหน่วง และข้ามภาพขาเข้าทิ้งไปด้วย ข้อนี้สำคัญกับแถบเครื่องมือหลังบ้านที่มีปุ่มไอคอนเรียงกัน ถ้าไม่มีกลไกนี้ การไล่ตัวชี้ผ่าน 5 ปุ่มจะต้องรอ 300 ทุกปุ่ม และจะเห็นกล่องเลือนเข้าเลือนออก 5 รอบ ตลาด 6 เจ้าทำกลไกนี้ และทุกเจ้าเก็บเป็นสถานะรวมของหน้าเหมือนกัน

สถานะความอุ่นเป็นตัวแปรระดับโมดูล อ่านได้ด้วย `isTooltipWarm()` และล้างได้ด้วย `resetTooltipWarmth()` สำหรับชุดทดสอบ

**ไม่มีนาฬิกาหายเอง** กล่องอยู่จนกว่าจะเลื่อนตัวชี้ออก เลิกโฟกัส หรือกด Escape ซึ่งเป็นข้อ Persistent ของ WCAG 1.4.13

|---|---|
| เวลาขาเข้าและขาออก | `--ntg-motion-duration-fast` |
| เส้นโค้งขาเข้า | `--ntg-motion-easing-enter` |
| เส้นโค้งขาออก | `--ntg-motion-easing-exit` |
| สิ่งที่เปลี่ยน | ความทึบ บวกเลื่อน 2 จากทิศที่กล่องไปอยู่ |
| ระยะเลื่อน | `--ntg-size-space-s1-xs` ตรงกับ 2 ที่ Untitled UI ใช้ |

ไม่มีการย่อขยาย ซึ่งตรงกับเสียงข้างมากของตลาด คือ 6 เจ้าไม่ย่อขยาย และ 4 เจ้าไม่มีการเคลื่อนไหวเลย

ทิศของการเลื่อนมาจากด้านที่กล่องไปอยู่ ไม่ใช่ทิศคงที่ กล่องที่อยู่ด้านบนจะเลื่อนขึ้น และกล่องที่อยู่ด้านซ้ายจะเลื่อนไปทางซ้าย

เคารพ `prefers-reduced-motion` ปิดภาพทั้งขาเข้าและขาออก และฝั่ง TypeScript ตัดเวลารอภาพขาออกเป็นศูนย์ด้วย ไม่ใช่แค่หยุดภาพ **การหน่วงเวลาเปิดปิดยังอยู่** เพราะการหน่วงไม่ใช่การเคลื่อนไหว แต่เป็นจังหวะที่กันกล่องโผล่เรี่ยราด

## การเข้าถึง

### `relationship` ต้องระบุเสมอ

ไม่มีค่าเริ่มต้นโดยตั้งใจ แบบที่ Fluent 2 ทำ เพราะเลือกผิดแล้วตัวกระตุ้นจะไม่มีชื่อเลย ซึ่งเป็นความผิดพลาดที่มองไม่เห็นจากหน้าจอ

| ค่า | ใช้เมื่อ | ผูกด้วย |
|---|---|---|
| `label` | ตัวกระตุ้นไม่มีชื่อ เช่นปุ่มไอคอนล้วน คำใบ้คือชื่อของมัน | `aria-labelledby` |
| `description` | ตัวกระตุ้นมีชื่ออยู่แล้ว คำใบ้มาเติมข้อมูล | `aria-describedby` |
| `inaccessible` | ข้อความซ้ำกับชื่อปุ่มอยู่แล้ว ถ้าผูกจะได้ฟังซ้ำสองรอบ | ไม่ผูกอะไร |

ถ้ามี `aria-labelledby` หรือ `aria-describedby` อยู่ที่ตัวกระตุ้นแล้ว ระบบต่อ id ของคำใบ้เข้าไปท้ายรายการ ไม่ทับของเดิม

ถ้าตั้ง `label` แต่ตัวกระตุ้นมี `aria-label` อยู่แล้ว จะเตือนที่คอนโซลตอนพัฒนา เพราะชื่อจาก `aria-label` จะชนะแล้วข้อความในคำใบ้จะไม่ถูกอ่าน Primer เตือนข้อนี้ไว้ในโค้ดเหมือนกัน

### `role` กับ `aria-hidden`

กล่องตั้ง `role="tooltip"` และ `aria-hidden="true"` พร้อมกัน ซึ่งไม่ได้ขัดกันเอง `aria-hidden` กันไม่ให้โปรแกรมอ่านหน้าจออ่านกล่องนี้เป็นอีกชิ้นหนึ่ง ส่วนการคิดชื่อและคำอธิบายจาก `aria-labelledby` และ `aria-describedby` ยังอ่านข้อความในกล่องที่ซ่อนอยู่ได้ตามข้อกำหนด จึงไม่ได้ฟังซ้ำสองรอบ Carbon และ Primer ตั้งสองค่านี้คู่กันแบบเดียวกัน

กล่องอยู่ใน DOM ตลอด ปิดการมองเห็นด้วย CSS ไม่ใช่ถอดออกจาก DOM เพราะ `relationship="label"` ชี้ไปที่ id ของกล่องนี้ ถ้าถอดออกตอนปิด ตัวกระตุ้นจะไม่มีชื่อในช่วงที่คำใบ้ยังไม่เปิด ซึ่งคือเวลาเกือบทั้งหมด

### WCAG 1.4.13 Content on Hover or Focus ครบทั้ง 3 ข้อย่อย

| ข้อย่อย | ทำยังไง |
|---|---|
| **Dismissible** | กด Escape ปิดได้ ฟังในเฟส capture แล้วเรียก `stopPropagation()` ทันที เพื่อไม่ให้เหตุการณ์ไหลต่อไปปิด modal หรือแผงข้างที่อยู่ข้างนอกด้วย ซึ่งเป็นบั๊กที่เจอบ่อยเมื่อคำใบ้อยู่ในหน้าต่างซ้อน Carbon กับ Spectrum กับ Fluent ทำเหมือนกันทั้งสามเจ้า |
| **Hoverable** | ย้ายตัวชี้เข้าไปในกล่องได้โดยกล่องไม่หาย **ห้ามใช้ `pointer-events: none`** ซึ่งเป็นสาเหตุที่ตลาด 3 เจ้าตกข้อนี้ ตัวกระตุ้นกับกล่องอยู่ในกล่องครอบเดียวกัน บวกสะพานพื้นที่ปลอดภัยเผื่อ 8 |
| **Persistent** | ไม่มีนาฬิกาหายเอง กล่องอยู่จนกว่าจะเลื่อนออก เลิกโฟกัส หรือกด Escape |

**สะพานพื้นที่ปลอดภัยเผื่อ 8 ไปทางด้านข้างเท่านั้น ไม่เผื่อไปทางตัวกระตุ้น** ด้านที่หันเข้าหาตัวกระตุ้นปิดช่องว่างพอดีเท่า `--ntg-tooltip-offset-*` ถ้าเผื่อเกินไปกว่านั้น สะพานจะไปทับตัวกระตุ้นแล้วกดตัวกระตุ้นไม่ได้ ส่วนระยะเผื่อ 8 ของ Spectrum ย้ายไปอยู่แกนขวาง ซึ่งเป็นทิศที่ตัวชี้ไหลออกจริง

### เปิดด้วยอะไร

- ชี้ด้วยตัวชี้ ยกเว้น `pointerType` เป็น `touch`
- โฟกัสด้วยคีย์บอร์ด **เฉพาะ `:focus-visible`** ถ้าเปิดทุกการโฟกัส การคลิกปุ่มด้วยเมาส์จะทำให้กล่องค้างอยู่หลังคลิก Spectrum กับ Primer จำกัดไว้แบบเดียวกัน

### จอสัมผัส

ซ่อน 2 ชั้น ชั้น CSS ซ่อนด้วย `(hover: none)` และ `(pointer: coarse)` และชั้น TypeScript ไม่รับเหตุการณ์ที่ `pointerType` เป็น `touch` แบบที่ Radix และ Zag ทำ

ตลาดฝั่งเว็บเลือกซ่อน 6 เจ้า และไม่มีเจ้าไหนบนเว็บแปลงเป็นท่ากดค้าง มีแต่ Material 3 ที่แปลง และแปลงได้เพราะอยู่บน Android ที่มีท่ากดค้างเป็นมาตรฐานของระบบปฏิบัติการอยู่แล้ว

## ข้อควรระวัง

- **ห้ามใส่ข้อมูลที่จำเป็นต่อการใช้งานในคำใบ้** ดูกรอบเตือนที่หัวไฟล์นี้
- **ห้ามจำกัดจำนวนบรรทัด และห้ามตัดข้อความด้วยจุดสามจุด** Atlassian ประกาศว่าการตัดข้อความใน tooltip ไม่รองรับการเข้าถึง ข้อความยาวให้ตัดบรรทัดลงมา
- **ห้ามตั้งความกว้างตายตัว** กล่องหดตามเนื้อหาแล้วชนเพดานที่ `max-width` ของเดิมในไฟล์ออกแบบตรึงไว้ที่ 320 ทำให้ข้อความสั้นก็ยังกินกล่องเต็ม
- **`max-width` ตั้ง 2 ที่** คือที่กล่องและที่ตัวข้อความ `--ntg-tooltip-text-max-width-*` เป็นค่าอนุพันธ์ของความกว้างสูงสุดลบระยะขอบสองข้าง ถ้าตั้งแค่ที่กล่อง ข้อความรองจะล้นออกนอกกล่อง ซึ่งเจอมาแล้วตอนประกอบไฟล์ออกแบบ
- **กล่องถูก `overflow: hidden` ของบรรพบุรุษตัดได้** เพราะรุ่นนี้ไม่ใช้ portal ถ้าตัวกระตุ้นอยู่ในกล่องที่ซ่อนส่วนเกิน ให้ย้ายตัวกระตุ้นออกมา หรือรอรุ่นที่มี portal
- **กล่องครอบเป็น `inline-flex`** ไม่ตั้งขนาดให้ตัวเอง ขนาดมาจากตัวกระตุ้น ถ้าตัวกระตุ้นเป็นของที่ต้องยืดเต็มแถว ให้จัดผังผ่าน `wrapperClassName`
- **`children` ต้องเป็น element เดียว** เพราะคำใบ้ต้องเติม aria ให้ element นั้น ส่งข้อความล้วนหรือหลาย element ไม่ได้

## ยังไม่มีในรุ่นนี้

- **กลไกพลิกเมื่อชนขอบจอ** สเปค 3 ขั้นเขียนไว้แล้วในหัวข้อข้างบน การติดตั้งต้องวัดกรอบจอตอนทำงาน ซึ่งต้องขออนุมัติเรื่องไลบรารีจัดตำแหน่งก่อน
- **portal** กล่องอยู่ในสายเนื้อหาเดียวกับตัวกระตุ้น จึงถูกตัดด้วย `overflow: hidden` ได้ และโปรเจกต์นี้ยังไม่มี `react-dom` ในรายการชนิดข้อมูล
- **ปิด attribute `title` ของ `IconButton`** ตอนนี้ `IconButton` ตั้ง `title` ให้เองทุกตัว ทำให้เกิดคำใบ้ของเบราว์เซอร์ซ้อนขึ้นมาอีกกล่อง ต้องแก้ที่ `IconButton` ไม่ใช่ที่นี่
- **การควบคุมจากข้างนอก** ยังไม่มี prop `open` กับ `onOpenChange` ให้สั่งเปิดปิดเอง
- **กลุ่มคำใบ้ที่แชร์จังหวะกันแบบประกาศชัด** ตอนนี้ช่วงผ่อนผันเป็นสถานะรวมของทั้งหน้า ซึ่งพอสำหรับแถบเครื่องมือ แต่ยังไม่มี component กลุ่มแบบ `TooltipGroup` ของ Mantine
- **การปิดเมื่อเลื่อนหน้า** Atlassian ปิดคำใบ้เมื่อผู้ใช้เลื่อนหน้า ที่นี่ยังไม่ทำ
