# Toast

ข้อความแจ้งลอยที่ทับเนื้อหา บอกผลของสิ่งที่เพิ่งเกิดขึ้น แล้วหายไปเอง ตรงกับไฟล์ออกแบบหน้า **19 Toasts and Banners**

สเปคขนาดทุกค่าอยู่ที่ `tokens/scale/toast.mjs` และออกมาเป็น CSS variable ที่ `tokens/output/css/variables.css` ไฟล์ในโฟลเดอร์นี้ไม่มีค่าขนาดหรือสีของตัวเอง

## ใช้ตัวไหน Toast หรือ Banner

| โจทย์ | ใช้ตัวไหน | เพราะอะไร |
|---|---|---|
| ผลของปุ่มที่ผู้ใช้เพิ่งกด เช่น บันทึกข่าวแล้ว | `Toast` | เป็นเรื่องที่จบแล้ว ไม่ต้องคาไว้ให้เกะกะ |
| สถานะที่ยังค้างอยู่ของหน้า เช่น ระบบจะปิดปรับปรุงคืนนี้ | `Banner` | ต้องอยู่ให้เห็นตลอดที่เรื่องนั้นยังไม่จบ |
| สรุปข้อผิดพลาดของฟอร์มตอนกดส่ง | `Banner` | ต้องย้ายโฟกัสมาได้ และต้องอยู่จนผู้ใช้แก้เสร็จ |
| แจ้งว่าการอัปโหลดล้มเหลว | `Toast` ชนิด `error` | เป็นผลของการกระทำ และชนิดนี้ไม่หายเองอยู่แล้ว |

สรุปสั้น Toast ลอยทับเนื้อหาและหายเอง ส่วน Banner อยู่ในสายเนื้อหาและไม่หายเอง

## Usage

ใช้คู่กับ `ToastStack` เมื่อเป็นข้อความแจ้งของจริงในแอป เพราะกองเป็นคนคุมตำแหน่งลอย การซ้อน และการประกาศให้โปรแกรมอ่านหน้าจอ

```tsx
import { ToastStack, type ToastStackItem } from '@/components/Toast';

const [toasts, setToasts] = useState<ToastStackItem[]>([]);

const push = (item: Omit<ToastStackItem, 'id'>) =>
  setToasts((list) => [...list, { ...item, id: crypto.randomUUID() }]);

<ToastStack
  label="ข้อความแจ้งของระบบ"
  items={toasts}
  onDismiss={(id) => setToasts((list) => list.filter((one) => one.id !== id))}
/>

push({ type: 'success', title: 'บันทึกข่าวแล้ว', description: 'ข่าวนี้อยู่ในรายการที่บันทึกไว้' });

push({
  type: 'error',
  title: 'ส่งข่าวไม่สำเร็จ',
  description: 'เครือข่ายขัดข้อง ลองอีกครั้งได้',
  action: { label: 'ลองอีกครั้ง', onClick: retry },
});
```

ใช้ `Toast` เดี่ยว ๆ ได้เมื่อวางในเอกสาร ในหน้าตัวอย่าง หรือในที่ที่คุมตำแหน่งเอง ตัวใบไม่ได้ตั้ง `position` ให้ตัวเอง

```tsx
import { Toast } from '@/components/Toast';

<Toast type="brand" title="มีข่าวใหม่ 12 ข่าว" onClose={() => setOpen(false)} />
```

## Props ของ Toast

| prop | ค่าเริ่มต้น | หน้าที่ |
|---|---|---|
| `title` | จำเป็น | หัวข้อ บรรทัดแรกของข้อความแจ้ง |
| `type` | `default` | `default` `brand` `error` `warning` `success` |
| `size` | `md` | `xs` ถึง `xl` |
| `description` | | ข้อความรอง อยู่ใต้หัวข้อ |
| `showIcon` | `true` | แสดงไอคอนบอกชนิด |
| `showDescription` | แสดงเมื่อมี `description` | แสดงข้อความรอง |
| `showAction` | แสดงเมื่อมี `action` | แสดงปุ่มกระทำ |
| `showClose` | `true` | แสดงปุ่มปิด |
| `icon` | ไอคอนประจำชนิด | ใช้ไอคอนอื่นแทน รับได้เฉพาะชื่อจากชุดไอคอนของ DS |
| `action` | | ปุ่มกระทำ มีได้ปุ่มเดียว รับ `label` `onClick` และ `icon` ตัวปุ่มคือ `LinkButton` ตระกูล neutral |
| `onClose` | | เรียกเมื่อกดปุ่มปิด หรือเมื่อหมดเวลาหายเอง |
| `closeLabel` | `ปิดข้อความแจ้ง` | ชื่อปุ่มปิดที่โปรแกรมอ่านหน้าจอจะอ่าน |
| `duration` | ระบบคิดให้ | เวลาหายเองหน่วยมิลลิวินาที `null` คือไม่หายเอง |
| `announce` | `true` | ประกาศให้โปรแกรมอ่านหน้าจอ `ToastStack` ตั้งเป็น `false` ให้ทุกใบ |
| `announcement` | จาก `title` และ `description` | ข้อความที่จะประกาศ ใช้เมื่อหัวข้อไม่ใช่ข้อความล้วน |
| `as` | `div` | `li` เมื่ออยู่ในกอง `ToastStack` ตั้งให้เอง |
| `leaving` | `false` | กำลังเล่นภาพขาออก `ToastStack` ตั้งให้เอง |

## Props ของ ToastStack

| prop | ค่าเริ่มต้น | หน้าที่ |
|---|---|---|
| `items` | จำเป็น | รายการใบ เรียงจากเก่าไปใหม่ ใบใหม่อยู่ท้ายรายการ |
| `onDismiss` | จำเป็น | เรียกเมื่อใบนั้นควรถูกถอดออก เรียกหลังภาพขาออกเล่นจบ |
| `max` | `3` | จำนวนใบที่ซ้อนได้ ใบที่เกินจะรอจนใบเก่าหาย |
| `label` | `ข้อความแจ้งของระบบ` | ชื่อของกองที่โปรแกรมอ่านหน้าจอจะอ่าน |

## สี 5 ชนิด

ทรงเดียวคือพื้นสีอ่อน หัวข้อกับข้อความรองเป็นสีเทาเข้มทุกชนิด ไอคอนใช้ขั้น 700 ของตระกูลนั้น

| ชนิด | พื้นหลัง | ไอคอน |
|---|---|---|
| `default` | `--ntg-color-background-general-secondary` | `--ntg-icon-general-primary` |
| `brand` | `--ntg-color-background-brand-primary` | `--ntg-icon-brand-on-subtle` |
| `error` | `--ntg-color-background-system-error-primary` | `--ntg-icon-system-error-on-subtle` |
| `warning` | `--ntg-color-background-system-warning-primary` | `--ntg-icon-system-warning-on-subtle` |
| `success` | `--ntg-color-background-system-success-primary` | `--ntg-icon-system-success-on-subtle` |

หัวข้อใช้ `--ntg-color-text-general-heading` ข้อความรองใช้ `--ntg-color-text-general-text` ปุ่มปิดใช้ `--ntg-icon-general-secondary`

ไม่มีชนิด `info` ผู้ใช้ตัดสินแล้วว่าไม่เอา เพราะทับกับ `default` และ `brand`

## ตัวอักษรตามขนาด

ใช้ preset เท่านั้น ไม่มีการประกอบคอมโบเอง ตรงกับตาราง `TITLE_PRESET` และ `SUPPORT_PRESET` ใน `tokens/scale/toast.mjs`

| ขนาด | หัวข้อ | ข้อความรอง |
|---|---|---|
| `xs` | `label/sm` | `body/xs` |
| `sm` | `label/md` | `body/xs` |
| `md` | `label/lg` | `body/sm` |
| `lg` | `label/xl` | `body/md` |
| `xl` | `title/lg` | `body/lg` |

## เวลาหายเอง

| กรณี | เวลา |
|---|---|
| ทั่วไป | 5 วินาที |
| มีปุ่มกระทำ | 10 วินาที เพราะต้องอ่านแล้วตัดสินใจก่อนกด |
| ชนิด `error` | **ไม่หายเอง ต้องกดปิด** |

ชนิด `error` ไม่หายเองเป็นการแตกจากเสียงข้างมากของตลาดโดยตั้งใจ เหตุผลคือ WCAG 2.2.1 Timing Adjustable ระดับ A หน้า Understanding ของข้อนั้นยอมให้ตั้งเวลาได้ถ้าข้อมูลเดียวกันหาได้จากที่อื่น แต่ข้อความแจ้งความผิดพลาดมักเป็นที่เดียวที่ข้อมูลอยู่ ถ้าหายไปผู้ใช้เอากลับมาไม่ได้ จึงตกข้อนั้นทันที รายละเอียดอยู่ที่ `docs/research/toast-banner-component.md` หัวข้อ 8.3

นาฬิกาหยุดนับ 3 กรณี

- เมาส์ชี้อยู่บนใบนั้น
- โฟกัสอยู่ข้างในใบนั้น
- ผู้ใช้เปิด `prefers-reduced-motion`

และตอนนับต่อจะนับจากเวลาที่เหลือ ไม่ใช่เริ่มใหม่จากเต็ม ถ้าเริ่มใหม่ทุกครั้ง ใบนั้นจะไม่มีวันหายเมื่อเมาส์ผ่านไปผ่านมา ซึ่งเป็นกับดักที่ Polaris และ Radix เขียนกำกับไว้ในโค้ดของตัวเอง

ทับเวลาเองได้ด้วย `duration` และส่ง `null` เพื่อสั่งว่าไม่ให้หายเอง

## ตำแหน่งและการซ้อน

| จอ | ตำแหน่ง | ความกว้าง |
|---|---|---|
| เดสก์ท็อป | ล่างขวา | `--ntg-toast-width-{size}` คือ 280 ถึง 440 |
| มือถือ (แคบกว่า 768) | ล่างกลาง | ยืดเต็มจอ เว้นขอบข้างละเท่ากับระยะขอบของขนาดเดียวกัน |

ซ้อนได้ 3 ใบ เป็นรายการ ไม่ใช่ซ้อนไพ่ ใบใหม่เข้าด้านล่าง ใบที่เกิน 3 จะรออยู่จนกว่าใบเก่าจะหาย

## การเข้าถึง

- **live region แยกออกจากกล่องที่มองเห็น** ถ้าใส่ `aria-live` หรือ `role` ลงบนกล่องที่มองเห็น โปรแกรมอ่านหน้าจอจะอ่านสองรอบ รอบแรกตอน live region เปลี่ยน รอบสองตอนผู้ใช้เลื่อนไปเจอกล่องนั้น Base Web เขียนเหตุผลไว้ในโค้ด และ Fluent 2 กับ Radix แยกออกมาแบบเดียวกัน
- `ToastStack` มีช่องประกาศ 2 ช่องแยกตามระดับเสียง `default` กับ `brand` ใช้ `polite` ส่วน `error` `warning` `success` ใช้ `assertive` แยกเป็นสองช่องเพราะถ้าสลับ `aria-live` ของช่องเดียวกลางทาง โปรแกรมอ่านหน้าจอบางตัวจะไม่ประกาศรอบนั้น
- **ไม่ย้ายโฟกัสมาที่ใบตอนมันโผล่** เป็นข้อกำหนดของ W3C ของที่โผล่มาเองโดยผู้ใช้ไม่ได้สั่ง ถ้าแย่งโฟกัสจะทำให้คนที่กำลังพิมพ์อยู่หลุดจากที่เดิม
- **ปุ่มปิดเป็นพี่น้องของกลุ่มข้อความ ไม่ใช่ลูกของมัน** React Aria ระบุว่าลำดับใน DOM มีผลกับสิ่งที่ผู้ใช้ได้ยิน ถ้าปุ่มปิดอยู่ก่อนเนื้อหา จะได้ยินคำว่าปิดก่อนข้อความจริง
- **พื้นที่แตะของปุ่มปิดไม่ต่ำกว่า 44** ตามเกณฑ์ WCAG 2.5.5 ขยายด้วย pseudo element ไม่ได้ขยายกล่องจริง เพราะถ้าขยายกล่องจริงปุ่มจะไปทับข้อความและทับขอบกล่อง

## การเคลื่อนไหว

เวลาและเส้นโค้งอ้าง token ของระบบ ไม่มีค่าที่ประกาศเองในไฟล์นี้แล้ว

| ขา | token เวลา | token เส้นโค้ง | ระยะ |
|---|---|---|---|
| เข้า | `--ntg-motion-duration-default` (250ms) | `--ntg-motion-easing-enter` | เลื่อนขึ้นจากด้านล่าง 50 เปอร์เซ็นต์ บวกจางเข้า |
| ออก | `--ntg-motion-duration-fast` (150ms) | `--ntg-motion-easing-exit` | เลื่อนลง 15 เปอร์เซ็นต์ บวกจางออก |

ขาเข้าใช้ชั้นเวลา default และขาออกใช้ชั้น fast ไม่ใช่ชั้นเดียวกัน เพราะขาออกต้องเร็วกว่าหรือเท่ากับขาเข้า ซึ่งเป็นข้อที่ตลาดทำตรงกันทุกเจ้าในงานวิจัยหัวข้อ 9 ถ้าสลับกันจะรู้สึกว่าใบนั้นไม่ยอมไปตอนกดปิด ส่วนระยะขาออกสั้นกว่าขาเข้าตามที่ Atlassian ทำ เพราะขาออกสายตาไม่ต้องตามไปถึงไหน

ค่าเวลาเดียวกันมีสำเนาอยู่ที่ `TOAST_MOTION` ในฝั่ง TypeScript เพราะ JavaScript อ่าน custom property ของ CSS ตอน render ไม่ได้ แต่ `ToastStack` ต้องรู้เวลาขาออกเพื่อรอภาพเล่นจบก่อนถอดใบออกจากรายการ **ถ้าแก้ token ต้องมาแก้ `TOAST_MOTION` ด้วย**

เมื่อผู้ใช้เปิด `prefers-reduced-motion` ภาพจะถูกปิดทั้งหมด และนาฬิกาหายเองจะหยุดนับด้วย

## ชั้นการวางซ้อน

กองข้อความแจ้งอยู่ที่ `--ntg-layer-notification` (400) ซึ่งเป็นชั้นสูงสุดของระบบ เพราะข้อความแจ้งต้องอยู่เหนือทั้งแผงลอยและชั้นฉากทับ

ถ้าแอปปลายทางมีชั้นที่สูงกว่านี้ ให้ตั้ง `--toast-layer` ทับจากข้างนอก ไม่ต้องแก้ไฟล์ของ component

```css
.my-app-shell { --toast-layer: 9000; }
```

## ข้อควรระวัง

- **ห้ามตั้งความสูง** ความสูงมาจากเนื้อหา ถ้าตรึงไว้ ข้อความที่ตัดหลายบรรทัดจะล้นออกนอกกล่อง
- **ไม่มีสถานะ disabled ที่ตัวกล่อง** สถานะอยู่ที่ปุ่มข้างในเท่านั้น
- **ปุ่มกระทำมีได้ปุ่มเดียว** และอยู่ใต้ข้อความเสมอ ไม่ใช่ท้ายแถวเดียวกัน เพราะกล่องกว้างแค่ 280 ถึง 440 พอวางปุ่มในแถวเดียวกับไอคอนและปุ่มปิด ที่เหลือให้ข้อความจะแคบจนตัดบรรทัดเสียรูป
- **ปุ่มกระทำต้องเป็น `LinkButton` ตระกูล neutral เท่านั้น** ห้ามเปลี่ยนไปใช้ปุ่มชนิดอื่น เพราะในไฟล์ออกแบบหน้า 19 ปุ่มกระทำของทุกแบบเป็น instance ของชุด `link-button` ตระกูล Neutral Button ถ้าโค้ดใช้ปุ่มชนิดอื่น สองฝั่งจะอ้างคนละชิ้นงาน
- **ปุ่มกระทำไม่ไล่สีตามชนิดของกล่อง** เหตุผลข้อแรกคือไอคอนกับพื้นหลังบอกชนิดอยู่แล้ว ปุ่มไม่ต้องย้ำอีกชั้น ข้อสองคือตระกูลสีของปุ่มไม่มี warning และ success ให้จับคู่ ถ้าไล่สีตามชนิดจะต้อง fallback 2 ใน 5 ชนิด ซึ่งไม่สม่ำเสมอ
- **ข้อความเดิมซ้ำสองรอบติดกันจะไม่ถูกประกาศรอบที่สอง** เป็นพฤติกรรมของ live region เอง ถ้าต้องประกาศซ้ำจริง ให้ใส่สิ่งที่ต่างกันลงใน `announcement` เช่นจำนวนครั้ง
- **`items` ของ `ToastStack` ต้องเรียงจากเก่าไปใหม่** เพราะกองหยิบท้ายรายการมาแสดง ถ้าเรียงกลับด้าน ใบใหม่จะไม่ขึ้น
- **จุดตัดมือถือ 768 เขียนเป็นเลขในไฟล์ CSS** เพราะ `@media` อ่าน custom property ไม่ได้ตามข้อกำหนดของ CSS ค่านี้ตรงกับ `--ntg-grid-breakpoint-tablet-v` ถ้าแก้ token ต้องมาแก้บรรทัดนั้นด้วย
