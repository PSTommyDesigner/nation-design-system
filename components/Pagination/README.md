# Pagination

แถบเลือกหน้าสำหรับรายการที่ยาวเกินหนึ่งหน้า ตรงกับไฟล์ออกแบบหน้า **24 Pagination**

สเปคขนาดทุกค่าอยู่ที่ `tokens/scale/pagination.mjs` และออกมาเป็น CSS variable ที่ `tokens/output/css/variables.css` ไฟล์ในโฟลเดอร์นี้ไม่มีค่าขนาดหรือสีของตัวเอง

โฟลเดอร์นี้มีชิ้นงานตัวเดียว คือ `Pagination` เลือกตามขนาดอย่างเดียว ส่วนจำนวนปุ่มเลขเป็นผลของข้อมูล

> **⚠️ ใช้กับหลังบ้านและหน้าค้นหา ไม่ใช่หน้าอ่านข่าว**
>
> สำรวจเว็บในเครือ 12 หน้าเมื่อ 2026-10-12 แล้วพบลิงก์เลขหน้า 0 จุดและ `aria-current` 0 จุด หน้าอ่านข่าวทั้งเครือใช้ปุ่มโหลดเพิ่มหรือเลื่อนไม่สิ้นสุด โจทย์ของคนอ่านข่าวคือไล่ดูเรื่อย ๆ ไม่ใช่กระโดดไปหน้าที่ 7 **ปุ่มโหลดเพิ่มยังไม่มีในระบบ** เปิดการ์ดแยกไว้แล้ว

## ใช้ตัวไหน เลขหน้าหรือปุ่มโหลดเพิ่ม

| โจทย์ | ใช้ตัวไหน | เพราะอะไร |
|---|---|---|
| ตารางข่าวในหลังบ้าน ต้องไล่ตรวจให้ครบทุกแถว | `Pagination` | ต้องรู้ว่าตรวจถึงไหนและเหลืออีกเท่าไหร่ |
| หน้าผลการค้นหา | `Pagination` | ผู้ใช้กระโดดข้ามหน้าและแชร์ลิงก์หน้าที่ N |
| แดชบอร์ดที่สถานะอยู่ในหน่วยความจำของแอป | `Pagination` ส่ง `onPageChange` | ไม่มีที่อยู่เว็บจริงให้ชี้ |
| หน้ารายการข่าวที่คนอ่านไล่ดูเรื่อย ๆ | ปุ่มโหลดเพิ่ม **ยังไม่มีในระบบ** | ไม่มีใครจำว่าอ่านถึงหน้า 7 |

## Usage

```tsx
import { Pagination, focusResultsHeading, pageStatusText } from '@/components/Pagination';
```

### เป็นลิงก์จริง ซึ่งเป็นแบบที่ควรใช้เป็นค่าตั้งต้น

```tsx
<Pagination
  label="ตัวแบ่งหน้ารายการข่าว"
  currentPage={3}
  totalPages={48}
  href={(page) => `/admin/news?page=${page}`}
/>
```

### เป็นปุ่ม เมื่อไม่มีที่อยู่เว็บจริงให้ชี้

```tsx
<Pagination
  label="ตัวแบ่งหน้าตารางยอดขาย"
  currentPage={page}
  totalPages={totalPages}
  size="sm"
  onPageChange={setPage}
/>
```

### ลิงก์จริงบวกการเปลี่ยนหน้าแบบไม่โหลดหน้าใหม่

ส่งทั้งสองอย่างคือได้ `<a href>` ที่บอตค้นหาตามเข้าไปได้และเปิดแท็บใหม่ได้ แต่คลิกธรรมดาจะเรียก `onPageChange` แทนการโหลดหน้าใหม่ คลิกที่กดปุ่ม Ctrl, Cmd, Shift หรือ Alt ค้างและคลิกปุ่มกลางยังเป็นของเบราว์เซอร์ตามปกติ

```tsx
<Pagination
  label="ตัวแบ่งหน้าผลการค้นหา"
  currentPage={page}
  totalPages={totalPages}
  href={(target) => `/search?q=${query}&page=${target}`}
  onPageChange={(target) => {
    router.push(`/search?q=${query}&page=${target}`);
  }}
/>
```

### ปรับจำนวนปุ่มที่แสดง

```tsx
// แผงแคบ เอาแค่หน้าแรก หน้าปัจจุบัน และหน้าสุดท้าย ได้ห้าปุ่ม
<Pagination
  label="ตัวแบ่งหน้าแผงด้านข้าง"
  currentPage={page}
  totalPages={totalPages}
  size="xs"
  siblingCount={0}
  onPageChange={setPage}
/>

// จอใหญ่ ตรึงสองหน้าหัวท้ายและเพื่อนบ้านข้างละสองหน้า ได้สิบเอ็ดปุ่ม
<Pagination
  label="ตัวแบ่งหน้ารายการบทความ"
  currentPage={page}
  totalPages={totalPages}
  size="lg"
  siblingCount={2}
  boundaryCount={2}
  onPageChange={setPage}
/>
```

## Props

| prop | ค่าเริ่มต้น | หน้าที่ |
|---|---|---|
| `currentPage` | **จำเป็น** | หน้าปัจจุบัน นับจาก 1 ค่าที่หลุดช่วงจะถูกตัดเข้าช่วงพร้อมเตือนตอนพัฒนา |
| `totalPages` | **จำเป็น** | จำนวนหน้าทั้งหมด ต่ำกว่า 1 คือไม่วาดแถบและเตือนตอนพัฒนา |
| `label` | **จำเป็น ไม่มีค่าเริ่มต้น** | ชื่อของ `<nav>` ไปเป็น `aria-label` ไม่ได้แสดงบนจอ |
| `href` | ไม่มี | คืนที่อยู่เว็บของหน้าที่ N ส่งแล้วได้ `<a href>` |
| `onPageChange` | ไม่มี | ตัวรับเมื่อเปลี่ยนหน้า ไม่ส่ง `href` คือได้ `<button>` |
| `size` | `md` | `xs` ถึง `xl` |
| `siblingCount` | `1` | จำนวนหน้าข้างหน้าปัจจุบันต่อข้าง |
| `boundaryCount` | `1` | จำนวนหน้าที่ตรึงไว้ที่หัวและท้ายแถว ต่ำกว่า 1 ไม่ได้ |
| `previousLabel` | `Previous` | ชื่อปุ่มก่อนหน้า |
| `nextLabel` | `Next` | ชื่อปุ่มถัดไป |
| `className` | ไม่มี | คลาสเพิ่มของ `<nav>` ใช้ปรับการจัดวาง เช่นชิดซ้ายแทนกึ่งกลาง |

> **⚠️ ต้องส่ง `href` หรือ `onPageChange` อย่างน้อยหนึ่งอย่าง ชนิดข้อมูลเป็นคนบังคับ**
>
> ไม่ส่งทั้งคู่จะตรวจไม่ผ่านตั้งแต่ตอนเขียนโค้ด และถ้าเรียกจากจาวาสคริปต์ล้วนจะเตือนที่คอนโซลตอนพัฒนา ที่ไม่ตั้งค่าเริ่มต้นเป็น `<button>` ให้เงียบ ๆ เพราะการเลือกแทนคนเขียนโค้ดจะทำให้เสียความสามารถในการแชร์ที่อยู่เว็บของหน้าที่ N ไปโดยไม่มีใครรู้ตัว **ตัวแบ่งหน้าที่เปลี่ยนที่อยู่เว็บต้องเป็นลิงก์เสมอ** ปุ่มใช้ได้เฉพาะที่ไม่มีที่อยู่เว็บจริงให้ชี้

> **⚠️ ไม่มี prop ความกว้าง และจะไม่มี**
>
> แถบยืดเต็มกรอบแม่เสมอ ของเดิมในไฟล์ออกแบบตรึงไว้ที่ 1440 กับ 375 ซึ่งเป็นค่าที่ไม่ได้คุมอะไรจริง พอวางในคอลัมน์ที่แคบกว่าแล้วเลข 1 กับหน้าสุดท้ายจะถูกตัดหาย อยากให้สั้นลงให้ไปจำกัดที่กรอบแม่

> **⚠️ ไม่มี prop ขนาดจอ และจะไม่มี**
>
> ของเดิมเอาขนาดจอมาทำเป็นแกน จึงมีทุกแบบคูณสอง การตอบสนองต่อขนาดจอเป็นเรื่องของ layout ไม่ใช่รูปทรงของชิ้นงาน แถวขึ้นบรรทัดใหม่เองเมื่อที่ไม่พอ และข้อความของลูกศรซ่อนเองเมื่อจอแคบกว่า 768

## ขนาด 5 ขั้น

ขั้นละเดินตามสูตรใน `tokens/scale/pagination.mjs` ทุกค่าอ้าง `--ntg-pagination-*`

| ขั้น | ใช้เมื่อไหร่ | ความสูง | กว้างขั้นต่ำ | ระยะขอบซ้ายขวา | ช่องไฟ | ช่องไฟระหว่างกลุ่ม | มุมโค้ง | เกณฑ์พื้นที่กด |
|---|---|---:|---:|---:|---:|---:|---:|---|
| `xs` | หลังบ้านที่แน่นมาก | 24 | 24 | 4 | 2 | 12 | 6 | ผ่าน AA แบบไม่มีระยะเผื่อ |
| `sm` | ใต้ตารางในหลังบ้านทั่วไป | 32 | 32 | 6 | 3 | 16 | 7 | ผ่าน AA ไม่ผ่าน AAA |
| `md` | ค่าเริ่มต้นของระบบ | 40 | 40 | 8 | 4 | 20 | 8 | ผ่าน AA ไม่ผ่าน AAA |
| `lg` | หน้ารายการที่เป็นเนื้อหาหลัก | 48 | 48 | 10 | 5 | 24 | 9 | ผ่านทั้ง AA และ AAA |
| `xl` | จอใหญ่ระยะไกล | 56 | 56 | 12 | 6 | 28 | 10 | ผ่านทั้ง AA และ AAA |

> **⚠️ ขนาด `xs` ที่ 24 อยู่ติดเพดานขั้นต่ำพอดี ห้ามใช้บนหน้าอ่านข่าว**
>
> เกณฑ์ WCAG ข้อ 2.5.8 ระดับ AA กำหนด 24 คูณ 24 และข้อ 2.5.5 ระดับ AAA กำหนด 44 คูณ 44 ขนาด `xs` จึงผ่าน AA แบบไม่มีระยะเผื่อเลย ถ้าวางชิดของอื่นหรือมีพื้นที่กดซ้อนกันจะตกเกณฑ์ทันที ใช้ได้เฉพาะหลังบ้านที่แน่นจริง เพราะผู้ใช้มือถือของเราเกิน 70 เปอร์เซ็นต์และกลุ่มเป้าหมายถึงอายุ 55 (ตัดสิน 2026-10-12)

> **⚠️ ความสูงกับมุมโค้งยืมของกลางมาทั้งก้อน ห้ามแก้ที่สูตรของหน้านี้**
>
> ปุ่มเลขหน้าเป็นปุ่มสี่เหลี่ยมจัตุรัสซึ่งเป็นของชนิดเดียวกับปุ่มไอคอนในหน้า 12 ความสูงจึงอ่านจากความสูงกลางของระบบและมุมโค้งอ่านจากสูตรมุมโค้งปุ่ม `tokens/scale/pagination.mjs` มีด่านตรวจเทียบกับของกลางตรง ๆ ถ้าใครแก้ข้างใดข้างหนึ่ง ตัวสร้าง token จะหยุดทำงานทันที

> **⚠️ ปุ่มก่อนหน้าถัดไปไม่ได้ใช้ `Button` ของ DS เพราะ `Button` เป็นปุ่มอย่างเดียว เปลี่ยนเป็นลิงก์ไม่ได้**
>
> ตัวแบ่งหน้าต้องเป็นลิงก์จริงที่มีที่อยู่เว็บ เพื่อให้แชร์ได้ กดย้อนกลับได้ และบอตค้นหาตามเข้าไปได้ แต่ `components/Button/Button.tsx` render เป็น `<button>` อย่างเดียว ยังไม่มี prop ให้เปลี่ยนชนิดของ element จึงใช้ที่นี่ไม่ได้
>
> **เหตุผลนี้ไม่เกี่ยวกับความสูง** ซึ่งเคยเขียนไว้ผิดแล้วแก้เมื่อ 2026-10-12 ความจริงคือ `--ntg-button-size-*` กับ `--ntg-pagination-height-*` เท่ากันทุกขั้น คือ 24 32 40 48 56 และ `Button.module.css` ก็ตั้ง `height` จากตัวแปรนั้นตรง ๆ อยู่แล้ว
>
> ที่นี่จึงใช้สไตล์ชุดเดียวกับปุ่มเลข แล้วยืมสีกับขนาดไอคอนจากชุดปุ่มกลางของระบบ **ถ้าวันหนึ่ง `Button` รองรับการเปลี่ยนชนิด element ได้ ให้กลับมาใช้ของกลางแทน**

> **⚠️ ปุ่มเลขใช้ความกว้างขั้นต่ำ ไม่ใช่ความกว้างตายตัว**
>
> ปุ่มเป็นจัตุรัสเมื่อเลขหลักเดียว แล้วกว้างขึ้นเองเมื่อเลขยาวขึ้น หมวดข่าวของเราทะลุ 2,278 หน้าได้จริง ถ้าตรึงเป็นจัตุรัสเลขจะล้นออกนอกกล่อง

## ตัวอักษรตามขนาด

ใช้ preset เท่านั้น ห้ามประกอบเอง ของเดิมใช้ 14 ทุกขนาดเพราะไม่มีแกนขนาด

| ขั้น | preset | ขนาดตัวอักษร |
|---|---|---|
| `xs` | `label/xs` | 10 |
| `sm` | `label/sm` | 12 |
| `md` | `label/md` | 14 |
| `lg` | `label/lg` | 16 |
| `xl` | `label/xl` | 18 |

ปุ่มเลขตั้ง `font-variant-numeric: tabular-nums` ถ้าไม่ตั้ง ความกว้างของปุ่มจะเปลี่ยนตามรูปร่างของเลขแต่ละตัว แล้วแถวจะขยับไปมาระหว่างหน้าที่มีจำนวนหลักเท่ากัน

## สี

| ส่วน | token |
|---|---|
| ข้อความ ปกติ | `--ntg-button-color-brand-gray-text-tertiary-default` |
| พื้นหลัง ตอนชี้และตอนกด | `--ntg-button-color-brand-gray-background-tertiary-hover` |
| ข้อความ ตอนชี้และตอนกด | `--ntg-button-color-brand-gray-text-tertiary-hover` |
| ข้อความ ตอนปิดใช้งาน | `--ntg-button-color-brand-gray-text-tertiary-disabled` |
| พื้นหลัง หน้าปัจจุบัน | `--ntg-color-background-brand-primary-alt` |
| ข้อความ หน้าปัจจุบัน | `--ntg-color-text-brand-primary` |
| วงแหวนโฟกัส | `--ntg-focused-ring-default` |

ตอนปกติไม่มีพื้นหลัง แถบแบ่งหน้าเป็นของแบนที่ฝังอยู่ในเนื้อหา **ไม่มีเงาโดยตั้งใจ** เหมือนแท็กและแถบความคืบหน้า

**สภาพหน้าปัจจุบันแยกจากสภาพชี้ให้เห็นชัด** ซึ่งต่างจากของเดิมที่รวมสองอย่างเป็นค่าเดียวชื่อ `Hover/active` และต่างจาก Untitled UI ที่ใช้สีเดียวกันจนแยกด้วยตาไม่ออก หน้าปัจจุบันจึงไม่ตอบสนองการชี้

**สีตอนกดใช้ชุดเดียวกับตอนชี้** ตามที่เอกสารหน้า 24 หัวข้อ 4.4 ตัดสินไว้ ระบบมี token ชุด pressed อยู่แต่หน้านี้เลือกไม่ใช้ เพราะแถบแบ่งหน้าไม่มีพื้นหลังตอนปกติ การไล่สีสามขั้นจึงไม่ได้สื่ออะไรเพิ่ม

## สูตรเลือกเลขหน้า

ค่าเริ่มต้น `siblingCount 1` กับ `boundaryCount 1` ให้ **เจ็ดปุ่ม** คือหน้าแรก จุดไข่ปลา สามหน้ารอบหน้าปัจจุบัน จุดไข่ปลา และหน้าสุดท้าย ตรงกับ MUI, Mantine และ Untitled UI

จำนวนปุ่มคงที่ที่ `boundaryCount × 2 + siblingCount × 2 + 3` เสมอ ไม่กระตุกเวลาผู้ใช้เดินหน้าไปทีละหน้า ถ้าจำนวนหน้าทั้งหมดไม่เกินจำนวนนั้นก็แสดงทุกหน้าไปเลย

| จำนวนหน้า | หน้าปัจจุบัน | ผลที่ได้ |
|---:|---:|---|
| 7 | 4 | `1 2 3 4 5 6 7` |
| 8 | 5 | `1 … 4 5 6 7 8` |
| 10 | 1 | `1 2 3 4 5 … 10` |
| 10 | 5 | `1 … 4 5 6 … 10` |
| 2,278 | 1,139 | `1 … 1138 1139 1140 … 2278` |

> **⚠️ จุดไข่ปลาที่บังหน้าเดียวจะกลายเป็นเลขหน้านั้นแทน**
>
> ดูที่แถว 8 หน้า ฝั่งขวาได้ `6 7 8` ไม่ใช่ `6 … 8` เพราะจุดไข่ปลาจองที่เท่าปุ่มเลขหนึ่งปุ่มอยู่แล้ว การเอาจุดสามจุดไปทับเลขหนึ่งตัวคือการแลกของที่กดได้กับของที่กดไม่ได้ในพื้นที่เท่ากัน ซึ่งไม่ได้อะไรกลับมา **Zag เป็นเจ้าเดียวในตลาดที่ทำขั้นนี้** และ `buildPageItems` ของเราให้ผลตรงกับ Zag ทุกกรณีที่ 1 ถึง 60 หน้า

สูตรนี้แยกเป็นฟังก์ชันบริสุทธิ์ `buildPageItems` เรียกตรงได้โดยไม่ต้องมี DOM เผื่อให้ที่ใช้งานเอาไปทำแถบแบบอื่นที่ยังอยากได้ชุดเลขเดียวกัน

## โครง markup ที่ได้

```html
<nav aria-label="ตัวแบ่งหน้ารายการข่าว">
  <ul>
    <li><a href="/news?page=2" rel="prev"><svg></svg><span>Previous</span></a></li>
    <li><a href="/news?page=1">1</a></li>
    <li aria-hidden="true"><span>…</span></li>
    <li><a href="/news?page=2">2</a></li>
    <li><a href="/news?page=3" aria-current="page">3</a></li>
    <li><a href="/news?page=4">4</a></li>
    <li aria-hidden="true"><span>…</span></li>
    <li><a href="/news?page=48">48</a></li>
    <li><a href="/news?page=4" rel="next"><span>Next</span><svg></svg></a></li>
  </ul>
</nav>
```

ยึดตาม W3C Design System และ GOV.UK Design System เพราะ **มาตรฐาน WAI-ARIA APG ไม่มี pattern ของตัวแบ่งหน้า** ไล่สารบัญทั้ง 33 pattern แล้วไม่มี

## การเข้าถึง

| สิ่งที่ต้องมี | ทำยังไง | ใครรับผิดชอบ |
|---|---|---|
| กล่องนอกสุดเป็น `<nav>` ที่มีชื่อ | ส่ง `label` | component ทำให้ แต่ต้องส่งชื่อมา |
| รายการเป็น `<ul>` กับ `<li>` | โปรแกรมอ่านหน้าจอจะบอกได้ว่ามีกี่รายการ | component ทำให้ |
| แต่ละหน้าเป็นลิงก์จริง | ส่ง `href` | คนเขียนโค้ด |
| `aria-current="page"` ตัวเดียวต่อชุด | สไตล์ผูกกับ `[aria-current="page"]` ไม่ใช่คลาสแยก | component ทำให้ |
| จุดไข่ปลาซ่อนและกดไม่ได้ | `<li aria-hidden="true">` ครอบ `<span>` | component ทำให้ |
| ลูกศรที่มีแต่ไอคอนต้องมีชื่อ | ข้อความซ่อนด้วยสูตรที่ยังอยู่ในต้นไม้การเข้าถึง | component ทำให้ |
| **ย้ายโฟกัสไปหัวข้อผลลัพธ์** | `focusResultsHeading` | **คนเขียนโค้ด** |
| **พื้นที่ประกาศแบบ polite** | `pageStatusText` | **คนเขียนโค้ด** |

### หลังเปลี่ยนหน้า ต้องทำสองอย่างนี้เอง

> **⚠️ component ทำสองอย่างนี้ให้ไม่ได้ และตั้งใจไม่ทำ**
>
> component ไม่รู้ว่าผลลัพธ์อยู่อิลิเมนต์ไหน ไม่รู้ว่าข้อมูลชุดใหม่มาถึงเมื่อไหร่ และพื้นที่ประกาศต้องอยู่ติด DOM ตลอดเวลาตั้งแต่หน้าถูกสร้าง ไม่ใช่เพิ่งใส่เข้าไปตอนต้องการ เพราะอิลิเมนต์ที่เพิ่งเข้า DOM มักไม่ถูกประกาศ ที่ของมันจึงอยู่ข้างผลลัพธ์ ไม่ใช่ข้างตัวแบ่งหน้า **ถ้าไม่ทำสองอย่างนี้ ผู้ใช้โปรแกรมอ่านหน้าจอจะไม่รู้เลยว่ามีอะไรเปลี่ยน** เพราะโฟกัสค้างอยู่ที่ปุ่มเดิมและเนื้อหาที่เปลี่ยนอยู่นอกสายตา
>
> กรณีที่โหลดหน้าใหม่จริง (ส่ง `href` อย่างเดียว ไม่ส่ง `onPageChange`) ไม่ต้องทำอะไรเพิ่ม เบราว์เซอร์รีเซ็ตโฟกัสให้เอง

```tsx
function NewsList() {
  const [page, setPage] = React.useState(1);
  const headingRef = React.useRef<HTMLHeadingElement>(null);
  const { items, totalPages, totalItems, firstItem, lastItem } = useNews(page);

  return (
    <section>
      {/* หัวข้อผลลัพธ์ รับโฟกัสได้แต่ไม่อยู่ในลำดับ tab */}
      <h2 ref={headingRef} tabIndex={-1}>
        ผลการค้นหา
      </h2>

      {/*
        พื้นที่ประกาศ อยู่ติด DOM ตลอดเวลา ไม่ใช่สร้างใหม่ตอนเปลี่ยนหน้า
        ซ่อนด้วยสูตรที่ยังอยู่ในต้นไม้การเข้าถึง ห้ามใช้ display none
      */}
      <p role="status" aria-live="polite" className={visuallyHidden}>
        {pageStatusText({ currentPage: page, totalPages, firstItem, lastItem, totalItems })}
      </p>

      <ul>{items.map((item) => <li key={item.id}>{item.title}</li>)}</ul>

      <Pagination
        label="ตัวแบ่งหน้าผลการค้นหา"
        currentPage={page}
        totalPages={totalPages}
        href={(target) => `/search?page=${target}`}
        onPageChange={(target) => {
          setPage(target);
          // เรียกหลังข้อมูลชุดใหม่ขึ้นจอแล้ว ถ้าโหลดแบบ async ให้ย้ายไปเรียกใน effect
          focusResultsHeading(headingRef.current);
        }}
      />
    </section>
  );
}
```

### จุดไข่ปลา

ซ่อนจากโปรแกรมอ่านหน้าจอและกดไม่ได้ เพราะจุดไข่ปลาไม่ใช่ปลายทาง ไม่พาผู้ใช้ไปไหน การอ่านว่า จุด จุด จุด คือเสียงรบกวนล้วน ข้อมูลที่จุดไข่ปลาสื่อด้วยตาเดินทางผ่านชื่อของ `<nav>` กับข้อความบอกตำแหน่งแทน ซึ่งบอกครบกว่าจุดสามจุด

ตั้ง `aria-hidden` ที่ `<li>` เพื่อให้จำนวนรายการที่โปรแกรมอ่านหน้าจอนับได้ตรงกับของที่กดได้จริง **ที่นี่ทำดีกว่าต้นแบบ** เพราะ W3C Design System ใช้ `<a class="ellipsis">` ซึ่งเป็นลิงก์ไม่มีปลายทาง และ GOV.UK ใช้ `<li>` เปล่า ทั้งสองไม่ได้ใส่ `aria-hidden`

### ปุ่มก่อนหน้าและถัดไป

- **ชื่อไม่หายไม่ว่าจอกว้างเท่าไหร่** จอแคบกว่า 768 จะซ่อนข้อความด้วยสูตรที่ยังอยู่ในต้นไม้การเข้าถึง ข้อความยังเป็นที่มาของชื่อปุ่มเสมอ จึงไม่ต้องใส่ `aria-label` ซ้อนอีกชั้น
- **สุดทางแล้วปิดใช้งาน ไม่ใช่ซ่อน** ถ้าซ่อนแถวจะกระตุกและผู้ใช้จะหาปุ่มไม่เจอ โหมดปุ่มใช้ `disabled` ของ HTML โหมดลิงก์ใช้ `aria-disabled="true"` บวกถอด `href` ออก เพราะลิงก์ที่ไม่มีปลายทางคือลิงก์ที่หลอกผู้ใช้
- ทั้งสองโหมดถอดชิ้นที่ปิดใช้งานออกจากลำดับ tab เพื่อให้พฤติกรรมของลิงก์กับปุ่มตรงกัน
- ลิงก์ก่อนหน้าและถัดไปใส่ `rel="prev"` กับ `rel="next"` ตามแนวทาง GOV.UK

## ข้อควรระวัง

- **ห้ามตรึงความกว้างของแถบ** แถบต้องยืดเต็มกรอบแม่เสมอ ไปจำกัดที่กรอบแม่แทน
- **ห้ามใช้ `onPageChange` อย่างเดียวเมื่อหน้านั้นมีที่อยู่เว็บจริง** จะเสียการแชร์ลิงก์ ปุ่มย้อนกลับของเบราว์เซอร์ การเปิดแท็บใหม่ และบอตค้นหา กรณี BBC ที่ใช้ `<button>` คือตัวอย่างที่ไม่ควรเอาอย่าง
- **ห้ามลืมย้ายโฟกัสและพื้นที่ประกาศ** เมื่อเปลี่ยนหน้าแบบไม่โหลดหน้าใหม่
- **ห้ามใช้ขนาด `xs` บนหน้าอ่านข่าว** และห้ามใช้แถบนี้แทนปุ่มโหลดเพิ่มบนหน้าอ่านข่าว
- **ห้ามเขียนค่าขนาดหรือสีลงในโค้ดที่เรียกใช้** ต้องการปรับให้ไปแก้ที่ `tokens/scale/pagination.mjs` แล้วรัน `npm run tokens:build`
- **ห้ามวาดแถบใหม่เอง** เพื่อให้ได้จำนวนปุ่มที่ต้องการ ใช้ `siblingCount` กับ `boundaryCount`
- `totalPages` เท่ากับ 1 จะยังวาดแถบที่มีปุ่มเดียวและลูกศรปิดใช้งานทั้งสองข้าง ถ้าไม่ต้องการให้แสดงเลยให้ตัดสินที่ฝั่งผู้ใช้ เพราะเกณฑ์ว่าจะซ่อนเมื่อไหร่เป็นเรื่องของหน้านั้น ไม่ใช่ของชิ้นงาน

## ยังไม่มีในรุ่นนี้

| เรื่อง | สถานะ |
|---|---|
| ปุ่มโหลดเพิ่มสำหรับหน้าอ่านข่าว | **ยังไม่มี** เปิดการ์ดแยกไว้แล้ว เป็นสิ่งที่เว็บในเครือใช้จริงแต่ระบบยังไม่มีให้ |
| ช่องกระโดดไปหน้าที่ต้องการ และตัวเลือกจำนวนแถวต่อหน้า | ยังไม่ทำ งานวิจัยเสนอไว้สำหรับหลังบ้าน |
| ข้อความ แสดง X ถึง Y จาก Z บนจอ | ยังไม่ทำ ตอนนี้มีเฉพาะฝั่งโปรแกรมอ่านหน้าจอผ่าน `pageStatusText` |
| แกนสีและทรงวงกลม | **ตัดสินว่าไม่ทำ** ไฟล์ออกแบบหน้า 24 มีชุดสีเดียวทรงเดียว |
| แกนขนาดจอ | **ตัดสินว่าไม่ทำ** การตอบสนองต่อจอเป็นเรื่องของ layout (ตัดสิน 2026-10-09) |
| สภาพกดที่แยกจากสภาพชี้ | **ตัดสินว่าไม่ทำ** ตามเอกสารหน้า 24 หัวข้อ 4.4 |
| โหมดมืด | ยังไม่มีแผนทั้งระบบ |
| Code Connect ระหว่างชุดในไฟล์ออกแบบกับ component นี้ | ยังไม่ผูก |
