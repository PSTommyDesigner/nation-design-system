# 10 Frame Nation Design System

| ฟิลด์ | รายละเอียด |
|---|---|
| **Title** | 10 Frame (ภาพแทนรูปภาพและวีดีโอ) |
| **Description** | ชุด mockup-media แกน kind (image, video) size (xs ถึง xl) และ ratio (16:9, 4:3, 1:1, 9:16) รวม 40 แบบ |
| **Target Audience** | Designer เลือกกรอบตอนจัดหน้า, Developer ทำสัดส่วนให้ตรงในโค้ด, Content เตรียมภาพให้ตรงสัดส่วน |

## 2. วัตถุประสงค์ (Objective & Business Logic)

- **เป้าหมาย:** ให้ทุกหน้าจอใช้ชุดสัดส่วนเดียวกัน ภาพในเว็บจึงเรียงเป็นระเบียบและไม่มีแถวเบี้ยว
- **Business logic:** เว็บข่าวมีภาพเป็นองค์ประกอบหลัก ถ้าแต่ละหน้าใช้สัดส่วนของตัวเอง กริดจะพังทันทีที่เอาการ์ดหลายชนิดมาวางเรียงกัน
- **คุณค่า:** ทีมคอนเทนต์รู้ล่วงหน้าว่าต้องเตรียมภาพสัดส่วนไหน ไม่ต้องมาครอบใหม่ทีหลัง

## 3. ขั้นตอนการใช้งาน (Workflow)

### สำหรับ Designer
1. เลือกสัดส่วนตามชนิดงาน ดูตารางในข้อ 4.2
2. วาง instance ของ `mockup-media` เลือก kind ratio และ size ให้พอดีช่อง ระหว่างที่ยังไม่มีภาพจริง
3. ยืดขยายให้คงสัดส่วนเสมอ ปรับความกว้างตามคอลัมน์กริดแล้วปล่อยความสูงตามไป
4. **ห้ามใช้หลายสัดส่วนปนกันในกริดเดียวกัน** เพราะความสูงไม่เท่ากันจะทำให้แถวเบี้ยว

### สำหรับ Developer
1. ทำสัดส่วนด้วย `aspect-ratio` แล้วให้ความกว้างยืดตามคอลัมน์ ไม่ต้องกำหนดความสูงเอง
2. ภาพใช้ `object-fit: cover` ให้ตรงกับพฤติกรรมในไฟล์ออกแบบ ซึ่งครอบเต็มกรอบและตัดส่วนเกินทิ้ง
3. ระหว่างที่ยังไม่มีภาพ ใช้ `MockupMedia` ส่ง `ratio` ถ้ากรอบแม่ไม่มีความสูง **ห้ามคัดลอกขนาดในไฟล์ไปใช้เป็นความกว้างจริง** เป็นขนาดตั้งต้นให้ดูเท่านั้น

## 4. โครงสร้างข้อมูลและ UI (Structure)

### 4.1 กรอบสัดส่วน 8 ตัวเดิม (ลบแล้ว 2026-11-12)

เดิมหน้านี้มี component เดี่ยว 8 ตัว คือ `image-16:9` `image-4:3` `image-1:1` `image-9:16` และ `video-*` สัดส่วนเดียวกัน กว้าง 288 ทุกตัว ข้างในเป็นไฟล์ภาพลายหมากรุกและไฟล์วิดีโอ ผูก token ไม่ได้และไม่มีโค้ด
ผู้ใช้ตัดสินเมื่อ 2026-11-12 ให้ย้ายสัดส่วนเข้าแกน ratio ของ `mockup-media` แล้วลบทิ้ง ก่อนลบสลับทุกจุดที่ใช้ 59 จุด (เอกสารหน้า 10, การ์ด 7 ชุดบนหน้า 25 และหน้า Prototype Examples) เป็น `mockup-media` ที่ kind และ ratio ตรงกัน

### 4.1.1 ภาพแทนรูปภาพและวีดีโอ `mockup-media` (เพิ่ม 2026-11-11 แกน ratio 2026-11-12)

ชุดเดียวของหน้านี้ เป็นชุด variant ใช้วางแทนภาพจริงในการ์ด Modal และหน้าจอตัวอย่าง ระหว่างที่ยังไม่มีภาพ บอกผู้ดูได้ว่าตรงนั้นคือรูปหรือวีดีโอ แทนพื้นเทาเปล่า
ไม่มีไฟล์ภาพหรือวีดีโอข้างใน ผูกตัวแปรได้ทุกส่วน และมี component ในโค้ดชื่อ `MockupMedia` (`components/MockupMedia`)

| แกน | ค่า | ผล |
|---|---|---|
| `kind` | `image` `video` | ไอคอน `image` กับคำว่า รูปภาพ หรือไอคอน `videocam` กับคำว่า วีดีโอ |
| `size` | `xs` `sm` `md` `lg` `xl` | ไอคอน 16 20 24 32 40 (`mockup-media/icon-size/*` ยืมจากสเกลไอคอน) ข้อความ body-sm แสดงเฉพาะ lg กับ xl |
| `ratio` | `16:9` `4:3` `1:1` `9:16` | สัดส่วนของกล่อง ขนาดตั้งต้นกว้างตาม size (96 ถึง 448 ส่วน 9:16 กว้าง 54 ถึง 252) ในโค้ดเป็น prop `ratio` ตั้ง aspect-ratio ให้ ไม่ส่งก็ยืดตามกรอบ |

| ส่วน | ตัวแปร |
|---|---|
| พื้น | `color/background/general/secondary` |
| ไอคอน | `icon/general/disable-subtle` |
| ข้อความ | `color/text/general/disabled` |

- กล่องยืดเต็มกรอบที่วาง ขนาดในไฟล์เป็นขนาดตั้งต้นให้ดูเท่านั้น ถ้ากรอบแม่ไม่มีความสูงให้ส่ง ratio
- เลือก size ตามกล่อง กล่องสูงไม่ถึงราว 120 เช่นช่องภาพของการ์ดรายการใช้ md ลงไป
- ไม่มี effect โดยตั้งใจ เพราะวางในการ์ดหรือ Modal ที่มีเงาของตัวเองแล้ว
- ใช้กับ prototype หน้าเอกสาร และสถานะที่ภาพยังไม่มีเท่านั้น ไม่ใช่รูปสำรองตอนภาพโหลดไม่ขึ้นในหน้าจริง

### 4.2 เลือกสัดส่วนอย่างไร

| สัดส่วน | ใช้กับอะไร | ข้อควรระวัง |
|---|---|---|
| **16:9** | ภาพข่าวและวิดีโอแนวนอน ใช้บ่อยที่สุด | ภาพแนวตั้งที่ถูกครอบเข้ากรอบนี้จะเสียส่วนบนล่างไปมาก |
| **4:3** | ภาพจากคลังเก่าและกล้องรุ่นเดิม | อย่าใช้ปนกับ 16:9 ในกริดเดียวกัน |
| **1:1** | การ์ดบนโซเชียลและรูปประจำตัว | ภาพแนวนอนที่ครอบเป็นจัตุรัสมักตัดสิ่งสำคัญริมภาพออก |
| **9:16** | คอนเทนต์แนวตั้งบนมือถือ คลิปสั้นและสตอรี่ | กินพื้นที่แนวตั้งมาก ไม่เหมาะกับกริดบนจอใหญ่ |

## 5. ข้อจำกัดและข้อห้าม (Constraints)

- **ห้ามยืดจนสัดส่วนเพี้ยน** ปรับความกว้างแล้วปล่อยความสูงตามไป
- **ห้ามใช้หลายสัดส่วนปนกันในกริดเดียวกัน**
- **ห้ามวาดกล่องแทนรูปเอง** ให้วาง instance ของ `mockup-media`
- Space Document ของหน้านี้ (`Frame Space`) ครอบชุด mockup-media ซึ่งเป็นชุดเดียวของหน้า
