## 2. วัตถุประสงค์ (Objective & Business Logic)

- **เป้าหมาย** ให้ทุกตารางในเครือใช้เซลชุดเดียวกัน ไม่ใช่ต่างคนต่างจัดระยะเอง
- **Business logic** ตารางเป็นที่ที่ข้อมูลหนาแน่นที่สุดในระบบ ถ้าระยะห่างไม่เท่ากัน สายตาจะไล่ข้อมูลข้ามแถวไม่ได้
- **คุณค่า** เซล 17 ชนิดครอบคลุมของที่ข่าวและหลังบ้านใช้จริง ตั้งแต่ข้อความล้วนไปจนถึงแถบความคืบหน้าและกลุ่มอวาตาร์

## 3. ขั้นตอนการใช้งาน (Workflow)

### สำหรับ Designer

1. เลือกชนิดเซลจากข้อมูลที่จะใส่ ไม่ใช่จากหน้าตาที่อยากได้
2. หยิบ instance จากเอกสาร **Data table** **ห้ามวาดเซลเอง** ตามกฎใช้ของ DS
3. **ห้ามตั้งความสูงแถวตายตัว** ปล่อยให้เนื้อหาเป็นตัวกำหนด
4. จัดชิดตามชนิดข้อมูล (ตัดสิน 2026-10-28) คอลัมน์เงินชิดขวา คอลัมน์ "ที่" (ลำดับแถว) จัดกลาง ที่เหลือชิดซ้ายหมด ทั้งข้อความ วันที่ และตัวเลขทั่วไปอย่างจำนวนข่าวหรือยอดวิว

### สำหรับ Developer

1. ใช้ `components/Table` ซึ่งรับข้อมูลเป็น array แล้วกำหนดคอลัมน์ด้วย config
2. **ต้องเป็น `<table>` `<thead>` `<tbody>` `<th>` `<td>` จริง ห้ามใช้ div สวมรอย** เพราะโปรแกรมอ่านหน้าจออาศัยโครงนี้บอกผู้ใช้ว่าอยู่คอลัมน์ไหนแถวไหน
3. คอลัมน์ที่เรียงได้ต้องมี `aria-sort` และปุ่มเรียงต้องเป็น `<button>` จริง
4. ช่องติ๊กเลือกแถว **ใช้ `Checkbox` ของระบบ ขนาด sm** ห้ามเขียนเอง
5. ตารางที่กว้างเกินจอต้องเลื่อนแนวนอนได้ และกรอบที่เลื่อนต้องโฟกัสด้วยคีย์บอร์ดได้

## 4. โครงสร้างข้อมูลและ UI (Structure)

**เซลอีก 5 ชนิดที่ลงท้ายด้วย `-color-cell` ไม่ใช่ของตารางข้อมูล** เป็นของระบบเอกสารที่ใช้แสดงตารางสี อยู่หน้าเดียวกันเพราะใช้โครงเดียวกัน

### 4.2 ⚠️ ความสูงแถวไม่มีสูตร โดยตั้งใจ

เซลทุกตัวตั้งโหมดขนาดเป็นอัตโนมัติทั้งสองแกน **ความสูงจึงมาจากเนื้อหาข้างใน** ต่างกันตั้งแต่ **40 ถึง 70** ตามชนิดของลูก

สูตรที่บวกกลับได้ทุกตัวคือ

```
ความสูงเซล = 12 (ขอบบน) + ความสูงของลูก + 12 (ขอบล่าง)
```

| ตัวอย่าง | บวกกลับ |
|---|---|
| `select` | 12 + 16 + 12 = 40 |
| `action` | 12 + 18 + 12 = 42 |
| `star` | 12 + 20 + 12 = 44 |
| `number` | 12 + 22 + 12 = 46 |
| `header` | 12 + 24 + 12 = 48 |
| `badge` | 12 + 26 + 12 = 50 |
| `avatar-group` | 12 + 40 + 12 = 64 |
| `text` | 12 + 46 + 12 = 70 |

**ถ้าวันหลังมีคนตั้งความสูงตายตัว ต้องกลับมาทำสูตรให้ ไม่ใช่ปล่อยเป็นตัวเลขลอย**

> **เคยเขียนผิด** เอกสารใน Figma เคยระบุว่าหัวตาราง 44 และเนื้อหา 76 ซึ่งไม่ตรงกับของจริงสักตัว วัดใหม่เมื่อ 2026-10-15 ได้หัวตาราง 48 และช่วง 40 ถึง 70 แก้ข้อความในไฟล์ออกแบบแล้ว

### 4.3 ตัวแปรและไฟล์ที่เกี่ยวข้อง

| ชื่อใน Figma | ชื่อในโค้ด | ค่า | ใช้ตรงไหน |
|---|---|---:|---|
| `table/padding/t` | `--ntg-table-padding-top` | 12px | ระยะขอบบนของเซลทุกชนิด |
| `table/padding/r` | `--ntg-table-padding-right` | 12px | ระยะขอบขวา |
| `table/padding/b` | `--ntg-table-padding-bottom` | 12px | ระยะขอบล่าง |
| `table/padding/l` | `--ntg-table-padding-left` | 12px | ระยะขอบซ้าย |
| `table/gap` | `--ntg-table-gap` | 8px | ระยะระหว่างลูกในเซลที่มีลูกหลายชิ้น เช่น `user` `link` `star` |
| `table/radius/*` | `--ntg-table-radius-*` | 8px | มุมโค้งของกรอบนอกตาราง ทั้ง 4 มุม |

**ระยะขอบ 12 กับระยะภายใน 8 บังเอิญตรงกับขั้น `s2/xs` และ `s1/lg` ของสเกลจัดหน้า แต่ไม่ได้อ้างถึงกัน** เพราะระยะห่างภายในชิ้นงานเป็นของชิ้นงานนั้นเอง (ขอบเขตที่ตัดสิน 2026-08-26)

### 4.4 ⚠️ อย่าสับสนกับ `doc-table`

| | `table` หน้านี้ | `doc-table` |
|---|---|---|
| **คืออะไร** | ตารางข้อมูลของโปรดักต์ | กรอบตารางในระบบเอกสาร |
| **ใครเห็น** | ผู้ใช้ปลายทาง | คนที่อ่านเอกสาร DS |
| **มีโค้ดไหม** | มี `components/Table` | **ไม่ทำโดยตั้งใจ** |

มุมโค้งเท่ากันที่ 8 ก็จริง แต่เจ้าของคนละคน เปลี่ยนแยกกันได้ในอนาคต หลักการเดียวกับที่ `tabs.mjs` แยก `tab/divider` ออกจาก `tab/rail`

### 4.5 API ของฝั่งโค้ด

กำหนดคอลัมน์ด้วย config ไม่ใช่เขียน `<tr>` เอง แต่เปิดช่อง `render` ให้วาดเนื้อในเซลเองได้เมื่อเซลนั้นเป็นของผสม

| กลุ่ม | ที่รับได้ |
|---|---|
| ข้อมูล | `columns` `data` `getRowId` |
| คำอธิบาย | `caption` `captionHidden` `scrollRegionLabel` `emptyMessage` |
| หน้าตา | `zebra` `stickyHeader` |
| เลือกแถว | `selectable` `selectedIds` `defaultSelectedIds` `onSelectionChange` `isRowDisabled` |
| เรียงลำดับ | `sort` `onSortChange` วนเป็น ไม่เรียง แล้วน้อยไปมาก แล้วมากไปน้อย |

### 4.6 หน้า Docs ใน Storybook

`components/Table/Table.stories.tsx` เป็นหน้า Docs 5 หัวข้อ (ส่วนประกอบ ชุด ขนาด สถานะ ควรไม่ควร) ตารางไม่มีชุดในไฟล์ออกแบบ หัวข้อชุดจึงแสดงเซล 17 ชนิดในตารางเดียว เซลผสม (badge tag user avatar-group progress-bar star icon action) ประกอบจาก component ของระบบผ่าน `render` ภาพของ story หลักตรงกับเฟรม Team members ในไฟล์ออกแบบ (หัว 48 แถว 70 ป้ายขนาด md) ตรวจแล้ว 2026-10-27 แถว caption มีเส้นใต้คั่นกับแถวหัว (หัวหน้าตัดสิน 2026-10-27) ทั้งสองฝั่ง ฝั่งไฟล์ออกแบบเป็น component `caption-table-cell` ใน Head cells และ caption-row ในเฟรม Team members

## 5. ข้อจำกัดและข้อห้าม (Constraints)

| # | เรื่อง | รายละเอียด |
|---|---|---|
| 1 | **ห้ามใช้ div สวมรอยเป็นตาราง** | โปรแกรมอ่านหน้าจออาศัยโครงตารางจริงบอกตำแหน่งแถวและคอลัมน์ ถ้าใช้ div ผู้ใช้จะหลงทางทันที |
| 2 | **ห้ามตั้งความสูงแถวตายตัว** | ความสูงมาจากเนื้อหา ถ้าตั้งตายตัวแล้วเนื้อหาสูงกว่า ข้อความจะถูกตัด |
| 3 | **ห้ามวาดเซลเอง** | ใช้ instance ของชุดที่ลงท้ายด้วย `-table-cell` เสมอ |
| 4 | **ห้ามเขียนช่องติ๊กเอง** | ใช้ `Checkbox` ของระบบ ขนาด sm ซึ่งตรงกับที่ `select-table-cell` ผูกไว้ |
| 5 | **จัดชิดตามชนิดข้อมูล** | เงินชิดขวาให้หลักและทศนิยมตรงกัน เปรียบเทียบยอดได้ ลำดับแถวจัดกลาง ที่เหลือชิดซ้ายหมด รวมทั้งตัวเลขทั่วไป (ตัดสิน 2026-10-28) |
| 6 | **ตารางที่เลื่อนได้ต้องโฟกัสด้วยคีย์บอร์ดได้** | ถ้ากรอบเลื่อนไม่รับโฟกัส คนที่ใช้คีย์บอร์ดอย่างเดียวจะเลื่อนดูคอลัมน์ขวาไม่ได้เลย |

## งานค้างของหน้านี้

- **หน้านี้มี token แค่ 9 ตัว ซึ่งไม่พอ** ของที่ขาดคือ ความหนาเส้นขอบตารางและเส้นแบ่งแถว (โค้ดยืม `divider/thickness` ซึ่งค่าตรงแต่เจ้าของเป็นหน้า 28) และสีพื้นแถวตอนชี้ ตอนถูกเลือก แถวสลับสี และแถวปิดใช้งาน ซึ่งเอกสารเขียนแค่ชื่อสถานะ ไม่ได้ระบุค่า
- **ความหนาแน่นแบบแน่นกับโปร่งที่เอกสารพูดถึง ยังไม่มี token รองรับ** ระยะขอบมีค่าเดียวคือ 12 จึงยังไม่ได้ทำฝั่งโค้ด
- **เซล 20 ชิ้นเป็น COMPONENT เดี่ยว ไม่ได้รวมเป็นชุด** ทำให้แผง Assets เป็นรายการยาว ต้องตัดสินว่าจะยุบเป็นชุดที่มีแกนชนิดหรือคงไว้
