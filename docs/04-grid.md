## 2. วัตถุประสงค์ (Objective & Business Logic)

- **เป้าหมาย:** ให้ทุกเว็บในเครือวางองค์ประกอบบนโครงเดียวกัน หน้าตาไม่หลุดกันเมื่อเปลี่ยนคนทำหรือเปลี่ยนหน้าจอ
- **Business logic:** Nation มีเว็บหลายแบรนด์ที่ใช้ layout ร่วมกัน (bangkokbiznews · nationtv · komchadluek · thansettakij · springnews · posttoday) จึงใช้ระบบ **เว็บทั่วไป (Version 2022)** เป็นค่ามาตรฐาน ส่วนโปรเจกต์ **Nation Digital** มีสัดส่วนคอนเทนต์ต่างออกไป (คอลัมน์กว้างกว่า จำนวนน้อยกว่า) จึงแยกอีกชุดโดยไม่แตะของเดิม · ปี 2026 เพิ่มชุด **มือถือรุ่น 2026 (v2026)** ให้ฝั่งเว็บทั่วไป เพื่อเลิกฐาน 5 ที่ใช้อยู่ตัวเดียวบนมือถือ โดยออกเป็นรุ่นคู่ขนานไม่แก้ค่าของรุ่นเดิม
- **คุณค่า:** ค่าอยู่ที่เดียวทั้งฝั่งออกแบบและโค้ด · เปลี่ยนที่ต้นทางแล้วกระจายทั้งระบบ · ลดการกะระยะด้วยตาแล้วไม่ตรงกัน

## 3. ขั้นตอนการใช้งาน (Workflow)

### สำหรับ Designer
1. เลือกระบบให้ตรงโปรเจกต์ **เว็บทั่วไป (Version 2022)** สำหรับเว็บในเครือ · **Nation Digital** สำหรับโปรเจกต์ Nation Digital
2. ถ้าเป็น **งานมือถือชิ้นใหม่ของเว็บทั่วไป** ให้ใช้ชุด **v2026** (grid style `nation-group-2026/mobile(360px)`) ส่วนจอ desktop กับ tablet ใช้ v2022 ตามเดิม ดูเกณฑ์เต็มที่ §4.3
3. เปิดหน้า `04 Grid` ดูภาพเส้นกริดของขนาดจอที่จะออกแบบใน `Grid Specimen ...` แล้วอ่านค่าจากตารางในหน้าเอกสาร
4. ตั้ง Layout grid ในเฟรมงานด้วยค่า columns · gutter · margin ของจอนั้น แล้ววางเนื้อหาให้อยู่ในเส้นคอลัมน์
5. ถ้าต้องอ้างถึงภาพกริดในเอกสาร ให้ใช้ instance จาก `Grid Components` ห้ามวาดใหม่

### สำหรับ Developer
1. ใช้ตัวแปร CSS จาก `tokens/output/css/variables.css` เช่น `--ntg-grid-v2022-desktop-container` แทนการพิมพ์ค่าดิบ
2. ตั้ง breakpoint จาก `--ntg-grid-breakpoint-*` ให้ตรงกับที่ออกแบบไว้
3. ถ้าต้องใช้ในไฟล์ JS/TS import จาก `tokens/output/js/tokens.mjs` (เช่น `GridV2022DesktopColumns`)

### สำหรับการ Sync
1. แก้ค่าที่ **Figma collection `grid`** เสมอ (แหล่งความจริง)
2. อัปเดต `tokens/tokens.json/grid.json` ให้ตรง
3. รัน `npm run tokens:build` แล้วตรวจว่าค่าใน `variables.css` เปลี่ยนตาม

### 4.3 ค่ากริดมือถือรุ่น 2026 (v2026)

รุ่นนี้มี **เฉพาะจอ mobile** เพราะ desktop กับ tablet ไม่มีค่าไหนเปลี่ยน จึงใช้ของ Version 2022 ต่อไปโดยไม่ทำค่าซ้ำไว้สองที่

**แคนวาสอ้างอิงคือ 360x810 (Android large) ไม่ใช่ 375** เหตุผลเต็มอยู่ที่ §5.1 และ [research/grid-column-width.md](research/grid-column-width.md)

| ขนาดจอ | คอลัมน์ | Gutter | Margin | Container | Column width |
|---|---|---|---|---|---|
| Mobile 360 | 4 | 8 px | 24 px | 312 px | 72 px |

**เกณฑ์เลือกใช้**

| งาน | มือถือ | Desktop กับ Tablet |
|---|---|---|
| งานใหม่ของเว็บในเครือ | `v2026` (ฐาน 8) | `v2022` |
| งานที่ประกาศไปแล้ว | `v2022` คงเดิม ไม่ต้องตามแก้ | `v2022` |
| โปรเจกต์ Nation Digital | `nation-digital` | `nation-digital` |

ใน Figma ตั้ง Layout grid ด้วย grid style `nation-group-2026/mobile(360px)` ซึ่งเป็นแบบ **Stretch** และผูก variable ไว้ 3 ฟิลด์ (count gutter margin) ต่างจากชุด `nation-group-2022/*` ที่เป็นแบบ fixed และยังเป็นค่าดิบ

**Container 312 กับ column width 72 ไม่ได้เก็บเป็น token** เป็นค่าที่คำนวณได้ Figma คำนวณให้เองแบบ Stretch ส่วนฝั่งโค้ดใช้ `repeat(4, 1fr)` ตารางด้านบนแสดงไว้เพื่อให้อ่านง่ายเท่านั้น

### 4.5 Tokens และไฟล์ที่เกี่ยวข้อง

| Path | หน้าที่ |
|---|---|
| `tokens/tokens.json/grid.json` | ต้นทางฝั่งโค้ด 53 token (breakpoint 5 v2022 20 v2026 3 nation-digital 25) |
| `tokens/style-dictionary.config.mjs` | ต้องมี path ของ `grid.json` ใน `source` ไม่งั้นไฟล์จะไม่ถูก build |
| `tokens/output/css/variables.css` | ตัวแปร CSS `--ntg-grid-<system>-<screen>-<prop>` |
| `tokens/output/js/tokens.mjs` | ตัวแปรฝั่ง JS เช่น `GridV2022DesktopColumns` |

รูปแบบชื่อ token: `grid/<system>/<screen>/<property>` โดย `<system>` = `breakpoint` \| `v2022` \| `v2026` \| `nation-digital` `<property>` = `columns` \| `gutter` \| `margin` \| `container` \| `column-width` **`v2026` มีเฉพาะ 3 ตัวแรก** เพราะ container กับ column-width เป็นค่าที่คำนวณได้

### 5.1 ทำไมมือถือรุ่น 2026 ใช้ฐาน 8 และย้ายแคนวาสไปที่ 360

`v2022` ใช้ **ฐาน 5** เฉพาะมือถือ (gutter 5 margin 20) ซึ่งเป็นการออกแบบที่ตั้งใจ ไม่ใช่ความมักง่าย เพราะร่องที่เป็นเลขคี่ช่วยแก้พาริตี้ของ 375 ทำให้คอลัมน์ออกมาเป็นจำนวนเต็มพอดี (`(375 - 40 - 15) ÷ 4 = 80`)

**ตัดสิน 2026-08-24 ว่ารุ่นใหม่เลิกใช้ฐาน 5** ให้ทั้งระบบเหลือฐานเดียว เหตุผล

1. ฐานคู่แปลว่าทุกคนต้องจำตลอดไปว่าจอไหนใช้ฐานอะไร และเวลาเพิ่ม component ใหม่ต้องตัดสินค่าสองชุด
2. ตัวเลขที่ลงตัวเป๊ะเป็นเรื่องของ **แคนวาสตอนออกแบบ** ไม่ใช่ของจริงบนเครื่อง เพราะ layout มือถือจริงเป็นแบบยืด คอลัมน์เป็นสัดส่วน และเครื่องจริงกว้าง 360 · 390 · 393 · 412 ปะปนกัน ไม่มีเครื่องไหนกว้าง 375 พอดีทั้งตลาด
3. ในรีโปนี้ไม่มี media query หรือ CSS layout ที่ผูกกับเลข 80 หรือ 165 เลยแม้แต่บรรทัดเดียว การเพิ่มรุ่นใหม่จึงไม่กระทบโค้ดที่มีอยู่

**ทางเลือกที่พิจารณาแล้วไม่เอา**

| ทางเลือก | เหตุผลที่ตกไป |
|---|---|
| แก้ค่ามือถือของ `v2022` ให้เป็นฐาน 8 ตรง ๆ | ทำไปแล้วรอบหนึ่งเมื่อ 2026-08-24 แล้วถอยคืนทั้งหมด เพราะเป็นการเปลี่ยนค่าของรุ่นที่ประกาศไปแล้ว งานเก่าที่อ้างอยู่จะเพี้ยนตามโดยไม่มีใครรู้ |
| คงแคนวาสไว้ที่ 375 แล้วยอมรับคอลัมน์ 79.75 | ทำไปแล้วเมื่อ 2026-08-24 แล้วพบว่าคอลัมน์ทั้ง 4 กว้างไม่เท่ากันบนจอจริง (80/80/79/80) เพราะขอบทุกเส้นตกที่เศษทศนิยมแล้วถูกปัดคนละทาง |
| ทำขอบซ้ายขวาไม่เท่ากันเพื่อไล่ให้คอลัมน์ลงตัว | ไม่พบว่ามี DS เจ้าไหนทำ เป็นการแฮกให้สวยที่จอเดียวแล้วต้องอธิบายความผิดปกตินี้ไปตลอด |
| กลับไปใช้ร่อง 5 บนมือถือ | ได้คอลัมน์จำนวนเต็มก็จริง แต่เท่ากับยกเลิกเหตุผลทั้งหมดของการมี `v2026` |
| ทำ `v2026` ให้ครบทั้ง 4 จอ | จอ desktop กับ tablet ไม่มีค่าไหนต่างจาก `v2022` เลย การทำซ้ำสร้างค่าที่ต้องดูแลสองที่โดยไม่ได้อะไรเพิ่ม (ตัดสิน 2026-08-24 หลังทำไปแล้ว 20 token แล้วตัดออกเหลือ 5) |

### 5.2 ทำไมย้ายแคนวาสจาก 375 ไปที่ 360 (ตัดสิน 2026-08-24 รอบสอง)

รอบแรกตั้งค่าไว้ที่แคนวาส 375 ขอบ 16 ร่อง 8 ได้คอลัมน์ `79.75` แล้วเขียนกำกับว่าห้ามปัดเศษ ต่อมาพบว่า **คอลัมน์ทั้ง 4 กว้างไม่เท่ากันบนจอจริง** เพราะขอบคอลัมน์ตกที่ `16, 103.75, 191.5, 279.25` แล้วถูกปัดลงพิกเซลคนละทาง ออกมาเป็น `80 / 80 / 79 / 80`

**และเศษนี้เลี่ยงไม่ได้ที่ 375** ความกว้างคอลัมน์คือ `(375 - 2m - 3g) ÷ 4` จะเป็นจำนวนเต็มก็ต่อเมื่อ `2m + 3g` หารด้วย 4 เหลือเศษ 3 แต่ `2m` เป็นเลขคู่เสมอ และร่องที่เป็นพหุคูณของ 8 ทำให้ `3g` หารลงตัว จึงไม่มีค่าขอบใดที่ทำให้เป็นจริงได้

ที่แคนวาส **360 ขอบ 24 ร่อง 8** ได้คอลัมน์ **72 เท่ากันครบทั้ง 4** และขอบคอลัมน์ทุกเส้น (`24, 104, 184, 264, 336`) เป็นพหุคูณของ 8 ทั้งหมด ซึ่งเป็นชุดเดียวที่ทำให้เป้าหมาย "ฐานเดียวทั้งระบบ" เป็นจริงจริง

360 ยังเป็น breakpoint มือถือที่ Material ใช้เป็นหลัก จึงไม่ใช่ตัวเลขที่คิดขึ้นเอง งานวิจัยเต็มพร้อมแหล่งอ้างอิงอยู่ที่ [research/grid-column-width.md](research/grid-column-width.md)
