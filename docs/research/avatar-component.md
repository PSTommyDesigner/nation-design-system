# Research Avatar Component ของ Design System เจ้าใหญ่

**วันที่วิจัย:** 2026-08-27
**โจทย์:** ตรวจสอบและปรับปรุงอวาตาร์ของ NTGDS (ชุดขนาด, padding ภายใน, วงแหวน, ชนิดเนื้อหา, ตัวย่อ, จุดบอกสถานะ, กลุ่มอวาตาร์, accessibility)

**ป้ายแหล่ง:** `[ทางการ]` = ไฟล์ต้นทางหรือเอกสารขององค์กรเอง `[กึ่งทางการ]` = พนักงานหรือชุมชนทางการพูดเอง `[แหล่งรอง]` = คนนอก

> **วิธีเก็บข้อมูล:** ค่าตัวเลขเกือบทั้งหมดในเอกสารนี้อ่านจาก **ไฟล์ต้นทางจริง** (GitHub raw หรือแพ็กเกจ npm ที่เผยแพร่แล้ว) ไม่ได้อ่านจากหน้าเว็บที่คนสรุปไว้ ตามบทเรียนใน [spacing-scale.md](spacing-scale.md) และ [shape-radius.md](shape-radius.md) §2 ที่พบว่าเว็บกับโค้ดของเจ้าเดียวกันให้ค่าไม่ตรงกัน ส่วนที่เป็นคำแนะนำเชิงการใช้งาน (เช่น การเขียน alt) อ่านจากหน้าเอกสารทางการ และระบุ URL กำกับทุกข้อ

## 1. สรุปคำตอบ 8 ประเด็น (อ่านหน้าเดียวจบ)

| # | ประเด็น | คำตอบสั้นจากข้อมูลจริง |
|---|---|---|
| 1 | ชุดขนาด | มัธยฐานอยู่ที่ **4 ถึง 7 ขนาด** (Ant 3, Carbon 4, Polaris 5, Primer 7, Atlassian 7, Fluent 14) ฐานที่ใช้จริงคือ **4 ตอนค่าน้อยแล้วขยับเป็น 8 ตอนค่าโต** ตรงกับที่ Primer เขียนเป็นกฎไว้ชัด มีเจ้าเดียวที่ผูกขนาดอวาตาร์กับความสูงปุ่มอย่างเป็นทางการคือ **Ant Design** (`containerSize = controlHeight`) |
| 2 | padding ภายใน | **ส่วนใหญ่ไม่มี padding เป็น token** วงกลมคุมขนาดภายนอก ส่วนเนื้อหาข้างในคุมด้วย **ตารางขนาดไอคอนและ text preset ต่อขนาด** (Fluent ชัดสุด) เจ้าที่มีจริงคือ Ant (`gap` ค่าเริ่มต้น 4px กันตัวย่อชนขอบ) และ Atlassian (padding 2px เฉพาะทรงหกเหลี่ยม เพื่อเว้นที่ให้เส้นขอบ) |
| 3 | วงแหวน | **ทุกเจ้าที่ทำกลุ่มอวาตาร์ต้องมีวงแหวน** และเกือบทุกเจ้าวาดด้วย `box-shadow` หรือ `border` สีพื้นหลัง ไม่ได้วาดด้วย padding ความหนาที่พบคือ **1px** (Primer, Ant, Lightning) และ **2px** (Atlassian, MUI, Fluent) โดย Fluent ขยายเป็น 3px และ 4px เมื่ออวาตาร์ใหญ่ |
| 4 | ชนิดเนื้อหา | รูป, ตัวย่อ, ไอคอน มีครบทุกเจ้า **ส่วน "ตัวเลข" ไม่ใช่ชนิดของอวาตาร์เดี่ยว** แต่เป็นตัวบอกจำนวนที่เหลือของ *กลุ่ม* (Atlassian `more-indicator`, Fluent overflow, MUI surplus, Geist `limit`) ลำดับ fallback ไม่ตรงกันสักเจ้า จุดที่ต่างคือไอคอนมาก่อนหรือหลังตัวย่อ |
| 5 | ตัวย่อ | **2 ตัวอักษร** เป็นมาตรฐาน (Carbon, Lightning, Fluent) Fluent มีอัลกอริทึมละเอียดสุด รวมถึงกลับลำดับให้ภาษา RTL และ **ปฏิเสธชื่อจีน ญี่ปุ่น เกาหลี อาหรับ** แล้วตกไปใช้ไอคอนแทน |
| 6 | จุดบอกสถานะ | มีแค่ **2 ใน 12 เจ้า** ที่ทำ (Atlassian 4 สถานะ, Fluent 8 สถานะ) และ **ทั้งคู่ใช้ตารางค่าตายตัว ไม่ใช่สัดส่วนคงที่** สัดส่วนจริงแกว่งระหว่าง 19% ถึง 50% ของขนาดอวาตาร์ |
| 7 | กลุ่มอวาตาร์ | เพดานก่อนตัดเป็นตัวเลขคือ **4 ถึง 5 คน** (Primer 4, Fluent 5, MUI 5, Atlassian 5 แบบ stack และ 11 แบบ grid) ระยะซ้อนมี 2 สำนัก คือ **ตารางค่าตายตัวตามช่วงขนาด** (Fluent, Atlassian, MUI, Ant) กับ **สัดส่วนของขนาด** (Primer 55%, Geist ประมาณ 30%) |
| 8 | accessibility | ข้อตกลงร่วมคือ **อวาตาร์ที่มีชื่อกำกับอยู่ข้าง ๆ ให้ปิดจากโปรแกรมอ่านหน้าจอ** (`alt=""`) และใส่ข้อความเมื่ออยู่เดี่ยว ๆ เท่านั้น (Polaris เขียนเป็นกฎ 3 ข้อ, Primer พูดตรงกัน) เรื่องจุดบอกสถานะมี 2 แนวคิดตรงข้ามกัน Fluent ผูกป้ายสถานะเข้า `aria-labelledby` ส่วน Atlassian ใส่ `aria-hidden="true"` ให้หายไปทั้งก้อน |

| ประเด็น | สถานะ |

| จุดบอกสถานะ | 6 ขนาด 6, 8, 10, 12, 14, 16 (base 6 step 2) มีสถานะเดียวคือออนไลน์ |
| กลุ่ม | ระยะซ้อน -4, -8, -12 ตามขนาด xs, sm, md รองรับสูงสุด 10 คน มีตัวบอกจำนวนที่เหลือและปุ่มเพิ่มคน |
| ป้ายชื่อ | `avatar-label` สูง 40, 44, 52, 56 คุมด้วย line-height ของ text style ไม่ได้ตั้งตัวเลขเอง |
| padding ภายใน | **พบว่ามีอยู่จริงในไฟล์ (เช่น 2 และ 11 ในชั้นซ้อนกัน) แต่ไม่มีที่มา ไม่มีสูตร และไม่มีเอกสารกำกับ** |
| สถานะการโต้ตอบ | default, hover, focused |
| ทรง | วงกลมเต็มวงทุกชนิดทุกขนาด |

## 3. Material 3 และ Material UI

### 3.1 M3 ไม่มี component ชื่ออวาตาร์

ดึงรายชื่อ component ทั้งหมดจาก sitemap ของ m3.material.io ได้ 37 รายการ **ไม่มี avatar** `[ทางการ]`
รายการที่ได้คือ all-buttons, app-bars, badges, bottom-sheets, button-groups, buttons, cards, carousel, checkbox, chips, date-pickers, dialogs, divider, extended-fab, fab-menu, floating-action-button, icon-buttons, lists, loading-indicator, menus, navigation-bar, navigation-drawer, navigation-rail, progress-indicators, radio-button, search, segmented-buttons, side-sheets, sliders, snackbar, split-button, switch, tabs, text-fields, time-pickers, toolbars, tooltips

อวาตาร์ของ M3 มีฐานะเป็น **ส่วนประกอบภายในของ List** เท่านั้น อ่านค่าจาก token ของ Compose ได้ตรง ๆ `[ทางการ]`

| token | ค่า |
|---|---|
| `ListTokens.ItemLeadingAvatarSize` | 40 dp |
| `ListTokens.ItemLeadingAvatarShape` | `CornerFull` (วงกลม) |
| `ListTokens.ItemLeadingAvatarLabelFont` | `TitleMedium` (ตัวย่อใช้ preset ไม่ใช่ค่าอิสระ) |
| `ListTokens.ItemLeadingAvatarColor` | `PrimaryContainer` และ label ใช้ `OnPrimaryContainer` |
| `ListTokens.ItemLeadingIconSize` | 24 dp (ไอคอนนำ ไม่ใช่ในอวาตาร์) |

**อ่านได้ว่า** M3 ไม่ยอมรับอวาตาร์เป็น component อิสระ แต่ยืนยัน 40dp เป็นขนาดอวาตาร์ในรายการ และตัวย่อผูกกับ typography preset ไม่ใช่ค่าอิสระ ซึ่งตรงกับกฎ preset-only ของเราอยู่แล้ว

### 3.2 Material UI (implementation ที่คนใช้จริง)

| ประเด็น | ค่า |
|---|---|
| ขนาดเริ่มต้น | 40 x 40 px, `font-size` 20px (พอดี 50% ของขนาด), `border-radius: 50%` |
| ชุดขนาด | **ไม่มี** ผู้ใช้กำหนดเองด้วย sx/style |
| ทรง | `circular` (ค่าเริ่มต้น), `rounded`, `square` |
| ลำดับ fallback | children ก่อน, ตามด้วยอักษรตัวแรกของ `alt`, ตามด้วยไอคอนกลาง |
| กลุ่ม | `max` ค่าเริ่มต้น 5, `spacing` medium = -8px, small = -16px, วงแหวน `border: 2px solid palette.background.default` พร้อม `box-sizing: content-box` |
| ตัวเลขที่เหลือ | `+N` เรนเดอร์ผ่าน SurplusSlot |

จุดที่ควรจำคือ MUI ใช้ `content-box` คู่กับ border 2px แปลว่า **วงแหวนขยายกล่องออกไปข้างนอก ไม่กินพื้นที่รูปข้างใน** เป็นวิธีที่ทำให้ขนาดรูปคงที่แม้ใส่วงแหวน

## 4. IBM Carbon (UserAvatar ใน Carbon for IBM Products)

Carbon core ไม่มีอวาตาร์ ตัวที่ใช้จริงคือ `UserAvatar` ในแพ็กเกจ `@carbon/ibm-products` ซึ่งมาแทน `UserProfileImage` เดิม `[ทางการ]`

| ขนาด | token | ค่า | typography |
|---|---|---|---|
| sm | `$spacing-06` | 32 px | `label-01` |
| md (ค่าเริ่มต้น) | `$spacing-07` | 40 px | `body-compact-01` |
| lg | `$spacing-09` | 56 px | `heading-03` |
| xl | `$spacing-10` | 64 px | `heading-04` |

**สังเกต** ขนาดอวาตาร์ Carbon **หยิบมาจากสเกลระยะห่างกลางโดยตรง** ไม่ได้ตั้งสเกลใหม่ และ **4 ค่าของ Carbon ตรงกับของเรา 3 ค่า** (32, 40, 56)

- **padding ภายใน:** ไม่มี ใช้ flex จัดกึ่งกลางแล้วให้ typography preset คุมความสูงตัวย่อ
- **ขอบ:** `border: 0.5px solid transparent` ทุกตัว (เว้นที่ให้ธีมเปลี่ยนเป็นสีจริงได้โดยขนาดไม่ขยับ) และ `border-radius: 100%`
- **โฟกัส:** `outline: 2px solid $focus` โดย `outline-offset: 3px` ปกติ และ 1px เมื่ออยู่ในสถานะ focus-within ของ tooltip
- **ลำดับ fallback:** รูป, ไอคอนที่ส่งเข้ามาทาง `renderIcon`, ตัวย่อจาก `name`, ไอคอน User ของ Carbon
- **กติกาตัวย่อ:** ตัวแรกของคำแรกเป็นตัวใหญ่ ถ้ามีคำเดียวใช้ตัวที่สองของคำนั้นต่อ ถ้าหลายคำใช้ตัวแรกของคำสุดท้าย ผลลัพธ์คือ 2 ตัวใหญ่
- **สี:** สุ่มจากชุด 12 สี (cyan, gray, green, magenta, purple, teal) โดยปรับตามธีมสว่างและมืดอัตโนมัติ
- **accessibility:** `imageDescription` สำหรับบรรยายรูป และ `tooltipText` สำหรับชื่อที่แสดงตอนชี้

## 5. Shopify Polaris

Polaris เป็นเจ้าเดียวในชุดนี้ที่ **อวาตาร์ไม่ใช่วงกลม** แต่เป็นสี่เหลี่ยมมุมมน อ่านจาก `Avatar.module.css` `[ทางการ]`

| ขนาด | ค่า | มุมโค้ง | คำแนะนำการใช้จากเอกสาร |
|---|---|---|---|
| xs | 20 px | 4 px | เลย์เอาต์ที่แน่นมาก |
| sm | 24 px | 6 px | เมื่อ md ใหญ่ไป หรืออวาตาร์สำคัญน้อยลง |
| md (ค่าเริ่มต้น) | 28 px | 6 px | ขนาดมาตรฐาน |
| lg | 32 px | 8 px | เมื่ออวาตาร์เป็นจุดสนใจ เช่นการ์ดลูกค้าเดี่ยว |
| xl | 40 px | 8 px | เมื่ออวาตาร์เป็นจุดสนใจ |

- **padding ภายใน:** ไม่มี ตัวย่อจัดกึ่งกลางด้วย flex และ **ไอคอนสำรองวาดเป็น SVG ใน viewBox 40x40 คงที่** โดยตัวคนกินพื้นที่ประมาณ x=8 ถึง x=32 แปลว่า **ระยะเว้นขอบถูกฝังอยู่ในตัวภาพ ไม่ได้เป็น padding ของกล่อง**
- **ความหนาเส้นไอคอนสำรองแปรตามขนาด** xs = 3, sm ถึง lg = 2.5, xl = 2 เพื่อให้เส้นดูหนักเท่ากันเมื่อย่อขยาย
- **ตัวย่อยาวเกิน 2 ตัว** สลับไปใช้ font-size เล็กลงหนึ่งขั้น (`--p-font-size-400` ไปเป็น `300`)
- **accessibility ที่เขียนเป็นกฎชัดที่สุดในชุดนี้** `[ทางการ]`
  - `alt="ชื่อคน"` เมื่ออวาตาร์แทนคน
  - `alt="ชื่อธุรกิจ"` เมื่ออวาตาร์แทนธุรกิจ
  - `alt=""` เมื่อชื่อคนหรือธุรกิจปรากฏเป็นข้อความอยู่ข้างอวาตาร์แล้ว
- ในโค้ดจริง แท็ก `img` ถูกตั้ง `alt=""` และ `role="presentation"` เสมอ แล้วยกป้ายไปไว้ที่กล่องนอกเป็น `role="img"` พร้อม `aria-label` ถ้าไม่มีป้ายเลย กล่องนอกจะเป็น `role="presentation"` คือหายไปจากโปรแกรมอ่านหน้าจอทั้งก้อน
- กรณีมีแต่ตัวย่อ ป้ายจะถูกอ่านเป็นตัวอักษรแยกกันทีละตัว (เอาตัวย่อมา `split('').join(' ')`) เพื่อไม่ให้โปรแกรมอ่านหน้าจออ่านรวบเป็นคำ

## 6. Atlassian Design System

### 6.1 ขนาดและมุมโค้ง

อ่านจาก `@atlaskit/avatar` เวอร์ชัน 27.2.1 `[ทางการ]`

| ชื่อขนาด | ค่า | มุมโค้งเมื่อเป็นทรงสี่เหลี่ยม |
|---|---|---|
| xxsmall | 16 px | 2 px |
| xsmall | 16 px | 2 px |
| UNSAFE_xsmall | 20 px | 2 px |
| small | 24 px | 2 px |
| medium | 32 px | 3 px |
| large | 40 px | 3 px |
| xlarge | 96 px | 6 px |
| xxlarge | 128 px | 12 px |

ทรงมี 3 แบบคือ circle, square, hexagon (hexagon ใช้กับ agent หรือ AI) วงกลมใช้ `--ds-radius-full` และ square ใช้ `--ds-radius-tile` ที่เท่ากับ 25%

**สังเกตช่องว่าง** ระหว่าง 40 กับ 96 ไม่มีอะไรเลย แปลว่า Atlassian แบ่งเป็น 2 ย่านชัดเจน คือย่าน UI (16 ถึง 40) กับย่านหน้าโปรไฟล์ (96, 128)

### 6.2 วงแหวนและ padding ที่ตรงกับปัญหาของเรา

- **วงแหวนวาดด้วยเงา** `box-shadow: 0 0 0 2px <borderColor>` โดย `borderColor` ค่าเริ่มต้นคือ `--ds-surface` (สีพื้นผิว) นี่คือวิธีคั่นตัวที่ซ้อนกันในกลุ่ม
- **padding ภายในมีจริง แต่มีเฉพาะทรงหกเหลี่ยม** ค่าที่ใช้คือ `padding-inline: var(--ds-border-width-selected, 2px)` แล้วหักกลับด้วย `margin-inline: calc(var(--ds-border-width-selected) * -1)` พร้อมชุดตัวคูณ 0.4, 0.5, 1.12, 1.25 สำหรับด้านบนล่างและมุม
- **อ่านได้ว่า** padding 2px ของ Atlassian **ไม่ใช่ระยะเว้นขอบให้เนื้อหา** แต่คือ **การเว้นที่ให้เส้นขอบของรูปทรงที่ตัดด้วย clip-path ซึ่งใส่ box-shadow ไม่ได้** และเมื่อใส่ padding แล้วต้องหักด้วย margin ติดลบเท่ากันเพื่อไม่ให้ขนาดภายนอกเปลี่ยน
- ทรงวงกลมและสี่เหลี่ยม **ไม่มี padding เลย**

### 6.3 จุดบอกสถานะ (presence) และป้ายสถานะ (status)

Atlassian แยก 2 เรื่องออกจากกัน คือ presence (คนอยู่ไหม) กับ status (สถานะของสิ่งของ เช่น อนุมัติหรือถูกล็อก) โดยแต่ละอันมี wrapper ของตัวเอง

| สถานะ presence | สี |
|---|---|
| online | `#6A9A23` |
| busy | `#C9372C` |
| focus | `#AF59E1` |
| offline | `#6B6E76` |

ขนาดของจุด อ่านจาก `presence-wrapper` และ CSS ที่คอมไพล์แล้ว

| ขนาดอวาตาร์ | ขนาดจุด | สัดส่วน | ตำแหน่ง |
|---|---|---|---|
| small (24) | 12 px (`9pt`) | 50% | ชิดมุมพอดี offset 0 |
| medium (32) | 14 px | 44% | ชิดมุมพอดี offset 0 |
| large (40) | 15 px | 37.5% | เยื้องเข้า 1 px |
| xlarge (96) | 18 px | 19% | เยื้องเข้า 7 px |

**อ่านได้ว่า** ตารางนี้ไม่ใช่สัดส่วนคงที่แน่นอน จุดโตช้ากว่าอวาตาร์มาก เพราะเป้าหมายคือ "ยังมองเห็นได้ตอนเล็ก" ไม่ใช่ "สัดส่วนสวยตอนใหญ่"

**accessibility ที่ต้องรู้** presence wrapper ถูกตั้ง `aria-hidden="true"` แปลว่า **Atlassian ตั้งใจซ่อนจุดสถานะจากโปรแกรมอ่านหน้าจอ** และให้ผู้ใช้ component ไปสื่อสารสถานะด้วยข้อความที่อื่นแทน

### 6.4 กลุ่มอวาตาร์

จาก `@atlaskit/avatar-group` `[ทางการ]`

| ประเด็น | ค่า |
|---|---|
| รูปแบบ | `stack` (ค่าเริ่มต้น) และ `grid` |

|---|---|---|---|
| 16 ถึง 24 | tiny | 6 px | 25% ถึง 37.5% |
| 28 ถึง 36 | extra-small | 10 px | 28% ถึง 36% |
| 40 ถึง 48 | small | 16 px | 33% ถึง 40% |

### 7.5 ตัวย่อ (อัลกอริทึมละเอียดที่สุด)

จาก `getInitials.ts` `[ทางการ]`
- คืน **1 หรือ 2 ตัวอักษร**
- ล้างเนื้อหาในวงเล็บทุกชนิด อักขระพิเศษ ASCII และ Unicode และช่องว่างซ้ำ ออกก่อน
- ภาษา RTL ที่ได้ 2 ตัว จะ **สลับลำดับ** เป็น `chars[1] + chars[0]`
- **ปฏิเสธชื่อจีน ญี่ปุ่น เกาหลี และอาหรับ** (ตรวจเฉพาะ code point ตัวแรก) คืนค่าว่างแล้วตกไปใช้ไอคอนแทน
- ปฏิเสธเบอร์โทรศัพท์ เว้นแต่เปิด `allowPhoneInitials`
- มีตัวเลือก `firstInitialOnly` และ **Avatar เรียกใช้ตัวเลือกนี้อัตโนมัติเมื่อขนาดไม่เกิน 16px**

**ข้อสังเกตสำหรับภาษาไทย** ไทยไม่อยู่ในรายการที่ถูกปฏิเสธ อัลกอริทึมจะตัดอักษรตัวแรกของคำมาใช้ ซึ่งกับไทยจะได้พยัญชนะต้นโดยไม่มีสระ (สระหน้าอย่าง เ แ โ จะถูกหยิบมาแทนถ้าอยู่ต้นคำ) ตรงนี้ **ไม่มีเจ้าไหนในชุดนี้ระบุกติกาภาษาไทยไว้เลย** ถือเป็นช่องว่างที่เราต้องตัดสินเอง

### 7.6 กลุ่มอวาตาร์

| ประเด็น | ค่า |
|---|---|
| รูปแบบ | `spread` (ค่าเริ่มต้นตามเอกสาร), `stack`, `pie` |
| จำนวนสูงสุด | `maxInlineItems` ค่าเริ่มต้น **5** ส่วน pie แสดงได้ 3 |
| ระยะซ้อนแบบ stack | น้อยกว่า 24 ใช้ -2 px, 24 ถึง 47 ใช้ -4 px, 48 ถึง 95 ใช้ -8 px, ตั้งแต่ 96 ใช้ -16 px |

| pie | ใช้ `clip-path` ตัดชิ้นและมีตัวแปรความหนาเส้นคั่นของตัวเอง |

## 10. Ant Design

เจ้าเดียวที่ **ผูกขนาดอวาตาร์เข้ากับความสูงของ control (ปุ่ม, ช่องกรอก) อย่างเป็นทางการ** อ่านจาก `components/avatar/style/index.ts` และ theme seed `[ทางการ]`

| ขนาด | token | ค่าที่ได้ |
|---|---|---|
| small | `controlHeightSM` = `controlHeight * 0.75` | 24 px |
| default | `controlHeight` | 32 px |
| large | `controlHeightLG` = `controlHeight * 1.25` | 40 px |

- ทรงเริ่มต้นวงกลม (`border-radius: 50%`) และแบบสี่เหลี่ยมใช้ `borderRadius`, `borderRadiusLG`, `borderRadiusSM` ตามขนาด
- **มีเส้นขอบโปร่งใสติดมาทุกตัว** `border: 1px solid transparent` แล้วเปลี่ยนสีเป็น `groupBorderColor` เมื่ออยู่ในกลุ่ม แปลว่าขนาดกล่องไม่ขยับตอนใส่วงแหวน
- **`gap` คือ padding ภายในของตัวย่อ** เอกสารนิยามว่า "ระยะจากตัวอักษรถึงขอบซ้ายขวา" ค่าเริ่มต้น **4px** และ component จะย่อขนาดตัวอักษรอัตโนมัติเพื่อรักษาระยะนี้เมื่อตัวย่อยาว
- ขนาดไอคอนคำนวณจาก typography ไม่ใช่ค่าดิบ `iconFontSize = round((fontSizeLG + fontSizeXL) / 2)`
- **ลำดับ fallback** เมื่อรูปโหลดไม่สำเร็จคือ `icon` มาก่อน `children`
- **กลุ่ม** `groupOverlapping = -marginXS` คือ **-8px คงที่ทุกขนาด** และ `groupSpace = marginXXS` คือ 4px สำหรับ popover ตัวที่ล้น จำนวนสูงสุดกำหนดเองผ่าน `max.count`

## 11. Salesforce Lightning (SLDS)

อ่านจาก CSS ที่เผยแพร่ของ `@salesforce-ux/design-system` และเอกสาร `lightning-avatar` `[ทางการ]`

| ขนาด | ค่า | font-size ของตัวย่อ |
|---|---|---|
| x-small | 20 px (1.25rem) | 10 px |
| small | 24 px (1.5rem) | 10 px |
| medium (ค่าเริ่มต้น) | 32 px (2rem) | 14 px |
| large | 48 px (3rem) | 18 px |

- **ทรงเริ่มต้นเป็นสี่เหลี่ยมมุมมน** `border-radius` 4px ผ่าน styling hook `--slds-c-avatar-radius-border` และมี modifier `slds-avatar_circle` ให้เป็นวงกลม
- ตัวย่อจัดกึ่งกลางด้วย flex สูงเต็มกล่อง ไม่มี padding และมี `text-shadow` บาง ๆ เพื่อให้ตัวอักษรอ่านออกบนพื้นสีอ่อน

- **ลำดับ fallback** รูป, ตัวย่อ, ไอคอนสำรอง และถ้าให้มาทั้งตัวย่อกับไอคอน จะแสดงตัวย่อโดยใช้สีพื้นหลังของไอคอน
- **กติกาตัวย่อ** ถ้าชื่อมี 2 คำ ให้ใช้อักษรตัวใหญ่ตัวแรกของแต่ละคำ
- **accessibility** `alternative-text` เป็น `alt` ของรูปและแสดงเป็น hover text ด้วย

## 15. หัวข้อเจาะลึกที่ตอบโจทย์โดยตรง

### 15.1 padding ภายในอวาตาร์ มีไหมและควรเป็นเท่าไหร่

รวบยอดจากทั้ง 12 เจ้า
- **ไม่มีเจ้าไหนมี token ชื่อ "padding ของอวาตาร์" เป็นสเกลหลายขั้น**
- ที่พบว่ามี padding จริง มี 2 กรณีเท่านั้น
  - **Ant Design** `gap` 4px คือระยะกันตัวย่อชนขอบ และเป็นค่าเดียวไม่แปรตามขนาด · เมื่อตัวย่อยาวจะย่อตัวอักษรแทนการลด gap
  - **Atlassian** padding 2px เฉพาะทรงหกเหลี่ยม เพื่อเว้นที่ให้เส้นขอบของรูปทรงที่ใส่เงาไม่ได้ · และหักกลับด้วย margin ติดลบเท่ากันเสมอเพื่อไม่ให้ขนาดภายนอกเปลี่ยน
- ที่เหลือ **แปลง "ระยะเว้นขอบ" ให้กลายเป็นผลลัพธ์ของตารางขนาดเนื้อหา** ที่ชัดที่สุดคือ Fluent (ตารางขนาดไอคอนต่อช่วงขนาดอวาตาร์) รองลงมาคือ Polaris (ฝังระยะไว้ในภาพ SVG viewBox คงที่) และ Carbon กับ Base Web (ให้ typography preset คุม)

**แปลว่าค่า 2 และ 11 ที่เราเจอ มีคำอธิบายที่เป็นไปได้ 2 ทาง** ทางหนึ่งคือเศษที่เหลือจากการวางไอคอนขนาดหนึ่งในวงกลมอีกขนาดหนึ่ง (แบบ Fluent) อีกทางคือระยะเว้นให้วงแหวน (แบบ Atlassian) ทั้งสองทางบอกตรงกันว่า **ไม่ควรมี padding เป็นตัวเลขที่พิมพ์ลงไปเอง**

### 15.2 วงแหวนเกี่ยวกับ padding หรือไม่

เกี่ยวโดยตรง และ **ทางที่ตลาดเลือกคือไม่ใช้ padding**
- Primer, Atlassian, Fluent, MUI ใช้ `box-shadow` หรือ `border` ที่ **ขยายออกนอกกล่อง** จึงไม่กินพื้นที่รูป
- MUI เพิ่ม `box-sizing: content-box` เพื่อให้ border ไม่กินขนาดรูป และ Ant ใช้ border โปร่งใส 1px ติดไว้ล่วงหน้าเพื่อไม่ให้ขนาดขยับตอนเปลี่ยนสี
- Atlassian ยอมใช้ padding **เฉพาะกรณีที่เงาใช้ไม่ได้** คือทรงหกเหลี่ยมที่ตัดด้วย clip-path
- ในระบบของเรา ตรงนี้ตรงกับบันทึกเดิมเรื่องวงแหวนโฟกัส 2 กลไก ที่ว่าปุ่มโปร่งต้องใช้ stroke เพราะเงาใน Figma เกาะพิกเซลจริง อวาตาร์วงกลมทึบใช้ effect style ได้ตามปกติ

### 15.3 จุดบอกสถานะ ตารางหรือสัดส่วน

**ทั้งสองเจ้าที่ทำจริงใช้ตาราง** และสัดส่วนที่ได้ก็ไม่คงที่

| ขนาดอวาตาร์ | Atlassian | Fluent | NTGDS ปัจจุบัน |
|---|---|---|---|
| 24 | 12 px (50%) | 6 px (25%) | 6 px (25%) |
| 32 | 14 px (44%) | 10 px (31%) | 8 px (25%) |
| 40 | 15 px (37.5%) | 16 px (40%) | 10 px (25%) |
| 48 | ไม่รองรับ | 16 px (33%) | 12 px (25%) |
| 56 | ไม่รองรับ | 20 px (36%) | 14 px (25%) |
| 96 | 18 px (19%) | 32 px (33%) | ไม่มีขนาดนี้ |

ข้อสังเกตที่ใช้ตัดสินได้
- Atlassian ให้จุด **ใหญ่มากตอนอวาตาร์เล็ก** (50% ที่ 24px) เพราะถ้าไม่ใหญ่จะมองไม่เห็น
- Fluent เริ่มที่ 25% เท่าเราที่ 24px แต่ **ไต่ขึ้นถึง 40%** ที่ 40px
- ของเราคงที่ 25% ทุกขนาด ซึ่ง **อยู่ที่ขอบล่างของตลาดตลอดสเกล** และเป็นแบบเดียวที่เป็นสัดส่วนเป๊ะ

| 24 | -4 (17%) | -4 (17%) | -4 (17%) | -8 (33%) | -7 (29%) | -13 (55%) |
| 32 | -8 (25%) | -4 (12.5%) | -8 (25%) | -8 (25%) | -10 (31%) | -18 (55%) |
| 40 | -12 (30%) | -4 (10%) | -8 (20%) | -8 (20%) | ประมาณ -12 (30%) | -22 (55%) |

ค่าของ Geist ที่ขนาด 40 เป็นการเทียบเคียงจากสัดส่วน 29% ถึง 31% ที่วัดได้จริงที่ขนาด 16, 24, 32 และ 48 ไม่ได้มีตัวอย่างขนาด 40 ในหน้าเอกสาร

ของเราอยู่ **กลางกลุ่มค่อนไปทางโปร่ง** ที่ขนาดเล็ก และไปตรงกับ Geist ที่ขนาดใหญ่ ไม่มีค่าไหนหลุดกรอบตลาด

## 16. ข้อเสนอสำหรับ NTGDS

> ทุกข้อในหัวข้อนี้เป็น **ข้อเสนอ** ไม่ใช่ข้อเท็จจริงจากงานวิจัย ต้องผ่านการยืนยันก่อนลงมือตามกฎ ask-first

### 16.1 ชุดขนาด 5 ระดับ พอดีแล้ว ไม่ต้องเพิ่มตอนนี้

**สรุป: พอดี** จำนวนขนาดของตลาดคือ 3 (Ant) ถึง 14 (Fluent) โดยมัธยฐานอยู่ที่ 4 ถึง 7 ขนาด ของเรา 5 อยู่กลางพอดี และค่า 32, 40, 56 ตรงกับ Carbon ส่วน 24, 32, 40 ตรงกับ Ant ทั้งชุด

สิ่งที่ควรทำเพิ่มมี 2 อย่าง
1. **เขียนสูตร base 24 step 8 ลง `tokens/scale/avatar.mjs` ให้จบ** ตอนนี้ไฟล์นั้นมีแต่มุมโค้ง ทำให้ขนาดยังเป็นเลขที่พิมพ์มือในไฟล์ออกแบบ ซึ่งขัดกับกฎระบบสเกลใน CLAUDE.md
2. **จองช่องขยายไว้ในสูตร ไม่ต้องสร้างของจริง** สูตรเดิมรองรับ index -1 ได้เป็น 16 และ index 5 ได้เป็น 64 ซึ่งบังเอิญตรงกับ 2 ช่องที่ตลาดใช้มากที่สุดพอดี คือ
   - **16 ถึง 20** สำหรับตารางแน่นและรายการคอมเมนต์ (Primer ตั้งเป็นค่าเริ่มต้นที่ 20, Polaris มี 20, Lightning มี 20, Atlassian มี 16)
   - **64 ขึ้นไป** สำหรับหน้าโปรไฟล์ (Carbon 64, Atlassian 96 และ 128, Fluent ถึง 128)
   - **ยังไม่ต้องสร้างจนกว่าจะมีหน้าจริงมาขอ** ตามบทเรียนใน [shape-radius.md](shape-radius.md) ที่สร้างชั้นกลางไว้ก่อนแล้วไม่มีคนใช้

**เรื่องที่ขนาดตรงกับความสูงปุ่ม** การตัดสินว่าไม่รวมสูตรกันนั้นมีเหตุผลรองรับ เพราะ 11 ใน 12 เจ้าก็ไม่ผูกเหมือนกัน มีแต่ Ant เจ้าเดียวที่ผูก และ Ant ผูกได้เพราะเขามีแค่ 3 ขนาดที่จบที่ 40 พอดี ส่วนของเราไปถึง 56 ซึ่งเลยพ้นย่านความสูงปุ่มแล้ว **ข้อเสนอคือคงคำตัดสินเดิม** และให้เขียนเหตุผลนี้กำกับไว้ในไฟล์สูตร (ตอนนี้เขียนไว้แล้ว ให้เติมหลักฐาน Ant เข้าไป)

### 16.2 padding ที่เจอในไฟล์ ควรตัดทิ้งแล้วแทนด้วยตารางขนาดเนื้อหา

**สรุป: ไม่ควรมี padding เป็นค่าที่ตั้งเอง**

เหตุผลคือไม่มีเจ้าไหนทำ padding เป็นสเกล และ 2 เจ้าที่มี padding จริงก็มีด้วยเหตุผลเฉพาะกิจ (กันตัวย่อชนขอบ 4px ของ Ant และเว้นที่ให้เส้นขอบ 2px ของ Atlassian)

ข้อเสนอ 3 ข้อ
1. **`avatar-icon` ให้กำหนดขนาดไอคอนต่อขนาดอวาตาร์เป็นตาราง** แล้วปล่อยให้ระยะเว้นขอบเป็นผลลัพธ์ ตามวิธี Fluent ค่าที่เสนอเดินตามสูตรได้สวย (ไอคอน base 16 step 4 และระยะเว้นขอบ base 4 step 2)

   | ขนาดอวาตาร์ | ขนาดไอคอน | ระยะเว้นขอบที่ได้ | เทียบ Fluent ที่ขนาดใกล้กัน |
   |---|---|---|---|
   | 24 | 16 | 4 | ตรงกัน (24 ใช้ไอคอน 16) |
   | 32 | 20 | 6 | ตรงกัน (32 ใช้ไอคอน 20) |
   | 40 | 24 | 8 | Fluent ใช้ 20 ได้ระยะ 10 |
   | 48 | 28 | 10 | Fluent ใช้ 24 ได้ระยะ 12 |
   | 56 | 32 | 12 | Fluent ใช้ 28 ได้ระยะ 14 |

2. **`avatar-monogram` ไม่ต้องมี padding** ให้ความสูงและตำแหน่งมาจาก text style preset ตามกฎ typography ของเรา และตั้งเพดานความยาวไว้ที่ 2 ตัวอักษร ถ้าอนาคตต้องรองรับ 3 ตัว ให้ทำแบบ Polaris คือสลับไป preset ที่เล็กลงหนึ่งขั้น **ห้าม override ขนาดตัวอักษรเอง**
3. **ค่า 2 ที่พบ** ถ้าตรวจแล้วพบว่าเป็นการเว้นที่ให้วงแหวน ให้ลบทิ้งแล้วเปลี่ยนไปวาดวงแหวนด้วย effect หรือ stroke แบบ outside แทน ตามวิธีที่ทุกเจ้าใช้ **ส่วนค่า 11 ต้องกลับไปวัดจากของจริงก่อน** ตามกฎในCLAUDE.md ที่ว่าค่า padding ใน Figma เชื่อไม่ได้เมื่อเฟรมเป็นขนาดตายตัว ให้คำนวณจาก `(ขนาดเฟรม - ขนาดลูก) / 2`

### 16.3 ระยะซ้อน -4, -8, -12 สมเหตุสมผล ให้คงไว้แล้วเขียนสูตรกำกับ

**สรุป: สมเหตุสมผล** ทั้งสามค่าอยู่ในกรอบที่ตลาดใช้ (17% ถึง 30% เทียบกับ Fluent 10% ถึง 17%, Ant และ MUI 20% ถึง 33%, Geist ประมาณ 30%) และเป็นแบบ "โตตามขนาด" เหมือน Fluent, Atlassian, Geist ซึ่งเป็นสำนักหลัก

ข้อเสนอ 3 ข้อ
1. **เขียนเป็นสูตรใน `tokens/scale/avatar.mjs`** ค่าปัจจุบันคือ base 4 step 4 พอดี (xs=4, sm=8, md=12) จึงเข้ากับระบบสเกลของเราได้โดยไม่ต้องแก้ตัวเลข
2. **ต้องเพิ่ม token วงแหวนคั่น** ตอนนี้เรายังไม่มี ซึ่งเป็นช่องโหว่ เพราะกลุ่มอวาตาร์ที่ไม่มีวงแหวนจะอ่านไม่ออกว่ามีกี่คนเมื่อรูปสีใกล้กัน **ทุกเจ้าที่ทำกลุ่มมีวงแหวนหมด** เสนอ 2px ผูกกับสีพื้นผิว (ตาม Atlassian, Fluent, MUI) และวาดออกนอกกล่องเพื่อไม่ให้ขนาดรูปเปลี่ยน
3. **เมื่อใส่วงแหวน 2px แล้ว ระยะซ้อน -4 ที่ขนาด 24 จะเหลือเนื้อรูปที่มองเห็นแค่ 2px** เสนอให้ทางใดทางหนึ่ง คือใช้วงแหวน 1px ที่ขนาด xs (แบบ Primer, Ant, Lightning) หรือขยับ xs เป็น -6 **ต้องเลือกก่อนสร้างจริง**

### 16.4 ขนาดจุดบอกสถานะ ควรเป็นตารางค่าต่อไป

**สรุป: ตารางค่าตายตัว ไม่ใช่สัดส่วน** เพราะทั้ง Atlassian และ Fluent ซึ่งเป็นสองเจ้าเดียวที่ทำจริง ใช้ตารางทั้งคู่ และสัดส่วนที่ได้ก็ไม่คงที่เลย เหตุผลคือความอ่านออกที่ขนาดเล็กไม่ได้เป็นเชิงเส้นกับขนาดอวาตาร์

ของเรามีตารางอยู่แล้ว (base 6 step 2) จึงถูกทางแล้ว สิ่งที่ควรทำคือ
1. **ตัดขนาด 16 ทิ้ง หรือประกาศว่าจองไว้สำหรับอวาตาร์ 64** ตอนนี้เรามีจุด 6 ขนาดสำหรับอวาตาร์ 5 ขนาด ตัวที่เกินมาคือของที่ไม่มีใครใช้ ซึ่งเป็นรูปแบบเดียวกับปัญหาชั้นกลางที่ไม่มีคนใช้ใน [shape-radius.md](shape-radius.md)
2. **พิจารณาขยับตัวเล็กขึ้น** 25% ที่ 24px ตรงกับ Fluent พอดี (6px เท่ากัน) แต่ Atlassian ใช้ถึง 12px เพราะเขาใส่ไอคอนในจุด **ถ้าจุดของเราเป็นสีล้วนไม่มีไอคอน 6px ใช้ได้** แต่ถ้าวันหนึ่งจะใส่ไอคอนต้องขยาย
3. **ต้องมีทางสื่อสถานะที่ไม่ใช่สี** เพราะจุดสีล้วนขนาด 6px แยกเขียวกับเทาไม่ออกสำหรับผู้ใช้ตาบอดสี Fluent 2 เตือนเรื่องนี้ไว้ตรง ๆ ที่ขนาด 32px และเล็กกว่า

### 16.5 ควรเพิ่มอะไร

1. **token วงแหวนคั่นกลุ่ม** ตามข้อ 16.3
2. **กฎ alt text เขียนเป็นเอกสาร** ยกแบบ Polaris มาได้เลยเพราะชัดที่สุดและ Primer พูดตรงกัน คือ ใส่ชื่อคนหรือชื่อองค์กรเมื่ออวาตาร์อยู่เดี่ยว และ **ใส่ค่าว่างเมื่อมีชื่อเป็นข้อความอยู่ข้าง ๆ แล้ว** ในบริบทข่าวของเรา อวาตาร์ผู้เขียนมักมีชื่ออยู่ข้าง ๆ เสมอ แปลว่า **กรณีปกติของเราคือปิดจากโปรแกรมอ่านหน้าจอ**
3. **กฎลำดับ fallback** ปัจจุบันเรามี 4 ชนิดแยกกันแต่ไม่มีกฎว่าเลือกอันไหนเมื่อไหร่ เสนอตามเสียงข้างมาก คือ **รูป ไปตัวย่อ ไปไอคอน** (แบบ Carbon, Polaris, Lightning, Fluent) และ **ตัวเลขไม่ใช่ทางเลือกของอวาตาร์เดี่ยว** แต่เป็นของกลุ่มเท่านั้น
4. **กติกาตัวย่อสำหรับภาษาไทย** ไม่มีเจ้าไหนในโลกเขียนไว้ให้ลอก และ Fluent ถึงกับปฏิเสธ CJK และอาหรับไปเลยแล้วใช้ไอคอนแทน **นี่คือช่องว่างที่เราต้องตัดสินเอง** ประเด็นที่ต้องตอบคือ ตัดพยัญชนะต้นแล้วสระลอย (เช่น "เกรียงศักดิ์" จะได้ "เ") และวรรณยุกต์กับสระบนล่างที่หลุดจากตัวอักษร **เสนอให้พิจารณาใช้ไอคอนแทนตัวย่อเป็นค่าเริ่มต้นสำหรับชื่อไทย** จนกว่าจะมีกติกาที่ทดสอบแล้ว
5. **สถานะโฟกัสควรมีเฉพาะอวาตาร์ที่กดได้** ปัจจุบันเรามี default, hover, focused ครบทุกชนิด ซึ่งอวาตาร์ที่เป็นแค่ภาพประกอบไม่ควรรับโฟกัสได้เลย (Fluent 2 ระบุว่าอวาตาร์เป็น static element โดยค่าเริ่มต้น ต้องเพิ่ม tabindex เองเมื่อทำให้กดได้)

### 16.6 ควรตัดอะไร

1. **จุดสถานะขนาด 16** ตามข้อ 16.4 ข้อ 1
2. **เพดาน 10 คนในกลุ่ม** สูงกว่าตลาดทุกเจ้า (Primer 4, Fluent 5, MUI 5, Atlassian stack 5) เสนอให้ **ค่าเริ่มต้นเป็น 5** แล้วเปิดให้ตั้งได้ถึง 10 สำหรับหน้าจอกว้าง ที่สำคัญคือ Atlassian **นับช่องปุ่ม "+N" รวมในเพดานด้วย** ซึ่งเป็นรายละเอียดที่เราควรตัดสินให้ชัดว่านับรวมหรือไม่
3. **`avatar-number` ในฐานะชนิดของอวาตาร์เดี่ยว** ตลาดถือว่าตัวเลขเป็นชิ้นส่วนของกลุ่ม ไม่ใช่อวาตาร์ชนิดหนึ่ง **ถ้าเราไม่มีที่ใช้นอกกลุ่มจริง ๆ ควรย้ายไปเป็นชิ้นส่วนฐาน** ชื่อทำนอง `_avatar/overflow-count` เหมือน `_avatar/add-button` ที่เราทำไว้แล้ว (ข้อนี้ต้องตรวจการใช้งานจริงก่อนตัดสิน)
4. **180 แบบ** เป็นตัวเลขที่สูงมากเมื่อเทียบกับตลาด ตัวเลขนี้มาจากการคูณกันของชนิด 4 แบบ, ขนาด 5 ระดับ, สถานะ 3 แบบ, และมี/ไม่มีจุดสถานะ **ถ้าตัดสถานะ focused ออกจากชนิดที่กดไม่ได้ (ข้อ 16.5 ข้อ 5) จำนวนจะลดลงทันทีโดยไม่เสียความสามารถ**

### 16.7 สิ่งที่ถูกอยู่แล้ว ไม่ต้องแตะ

- **`avatar-label` ที่ความสูงมาจาก line-height ของ preset** ตรงกับกฎในCLAUDE.md ที่ว่าของที่ความสูงคุมด้วย text style ห้ามทำสูตรความสูงให้ และตรงกับ Atlassian ที่ `avatar-item` ไม่ตั้งความสูงเช่นกัน ให้เขียน `$description` กำกับว่าค่ามาจาก preset ไหน
- **มุมโค้งเต็มวงตัวเดียวใน `avatar.mjs`** ถูกต้องตามที่ Spectrum ทำ (ตั้ง radius เท่ากับ block-size) และดีกว่าการใส่ครึ่งหนึ่งของขนาดทีละตัวแบบเดิม
- **ทรงวงกลมล้วน** เป็นเสียงข้างมาก (8 ใน 12 เจ้าใช้วงกลมเป็นหลัก) ส่วนที่ควรรู้ไว้เฉย ๆ คือ Primer และ Fluent ใช้ **ทรงสี่เหลี่ยมสื่อว่าไม่ใช่คน** (องค์กร, ทีม, bot, AI agent) ซึ่งถ้าวันหนึ่งเราต้องแสดงโลโก้สำนักข่าวในเครือหรือ AI agent ในระบบ นี่คือรูปแบบที่มีคนเดินมาก่อนแล้ว

## 17. ข้อจำกัดของงานวิจัยนี้

1. **หน้าเอกสารของ Atlassian, Fluent 2, Spectrum เป็น SPA ที่ดึงเนื้อหาไม่ครบ** ค่าตัวเลขทั้งหมดของ 3 เจ้านี้จึงอ่านจาก source ที่เผยแพร่แล้ว (npm หรือ GitHub) ส่วนคำแนะนำเชิงการใช้งานอ่านจากหน้า usage เท่าที่ดึงได้
2. **Spectrum มี 2 ชุดค่าในไฟล์เดียวกัน** ดึงป้ายกำกับ desktop กับ mobile ออกมาไม่ได้ในรอบนี้ จึงรายงานเป็นสองชุดโดยไม่ฟันธง
3. **Carbon UserAvatar** หน้า usage ทางการอยู่ที่ `pages.github.ibm.com` ซึ่งเป็นเครือข่ายภายใน IBM เข้าไม่ได้ ค่าทั้งหมดจึงมาจาก scss และ tsx ในรีโปสาธารณะ
4. **ค่าระยะซ้อนของ Geist** อ่านจาก inline style ที่ render ในหน้าเอกสารจริง ไม่ใช่ไฟล์ token จึงเป็นค่าที่ถูกต้อง ณ วันที่ดึง แต่ไม่ใช่การประกาศสูตรอย่างเป็นทางการ
5. **ไม่พบสเปกอวาตาร์สาธารณะของสำนักข่าวรายใหญ่** ข้อสรุปเรื่องฝั่งสื่อจึงอ้างได้แค่ NewsKit ที่ไม่มีอวาตาร์แต่มี Byline
6. **ตัวเลขในข้อเสนอ §16 เป็นข้อเสนอ** ยังไม่ผ่านการทดสอบกับหน้าจริงของเรา และค่า padding 11 ที่พบในไฟล์ยังไม่ได้ยืนยันว่ามาจากอะไร ต้องวัดจากไฟล์ออกแบบจริงก่อนตัดสิน
