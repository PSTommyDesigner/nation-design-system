## 2. วัตถุประสงค์ (Objective & Business Logic)

- **เป้าหมาย:** ให้ทุกเว็บในเครือใช้ชุดมุมโค้งเดียวกัน และแก้ค่าที่เดียวมีผลทุกที่
- **Business logic:** มุมโค้งบอกบุคลิกของแบรนด์แบบเงียบ ๆ ยิ่งโค้งมากยิ่งอ่านว่าเป็นมิตร ยิ่งคมยิ่งอ่านว่าจริงจัง ถ้าปล่อยให้แต่ละหน้าจอพิมพ์ตัวเลขเอง เว็บเดียวกันจะให้ความรู้สึกไม่เหมือนกัน
- **คุณค่า:** สลับสเกลทั้งชุดต่อแบรนด์ได้ในอนาคตโดยไม่ต้องแก้ชิ้นงานทีละตัว · ตรวจได้ว่าไม่มีค่าดิบหลุดเข้ามา

## 3. ขั้นตอนการใช้งาน (Workflow)

### สำหรับ Designer
1. หาตัวแปรของ component ที่ทำอยู่ ใน collection **component** เช่นการ์ดใช้ `card/radius/*` แท็กใช้ `tag/radius/*`
2. ผูกตัวแปรเข้ากับมุมทั้ง 4 ของชิ้นงาน **ห้ามพิมพ์ตัวเลขเอง**
3. ถ้าเป็นทรงแคปซูลให้ใช้ตัว `full` ของ component นั้น ไม่ใช่พิมพ์ 9999 เอง
4. ถ้า component ที่ทำยังไม่มีตัวแปร **แจ้งก่อน** อย่าพิมพ์ค่าดิบไปก่อน เพราะต้องไปนิยามในโค้ดให้เรียบร้อยแล้วค่อย generate ออกมา
5. กล่องที่ซ้อนกันให้คำนวณตามสูตรในข้อ 5 ก่อน

### สำหรับ Developer
1. เรียกตัวแปรจาก CSS เช่น `border-radius: var(--ntg-card-radius-top-left);`
2. ปุ่มใช้ตัวที่แยกตามขนาด เช่น `var(--ntg-button-radius-top-left-md)`
3. **ห้ามคัดลอกตัวเลข** ตัวเลขในเอกสารมีไว้ตรวจว่าสองฝั่งตรงกันเท่านั้น
4. ต้องการเปลี่ยนค่า ให้แก้ที่ `tokens/scale/` แล้วรัน `npm run tokens:build` ไม่ใช่แก้ที่ Figma
5. ห้ามใช้ `corner-shape: squircle` เพราะเบราว์เซอร์ยังรองรับไม่ทั่วถึง

## 4. โครงสร้างข้อมูลและ UI (Structure)

### 4.1 สามชั้น และชั้นไหนกลายเป็นตัวแปร

```
โค้ด   1. RADIUS_SCALE            none 0 · xs 2 · sm 4 · md 8 · lg 12 · xl 16 · full 9999
โค้ด   2. การเลือกและสูตรต่อ component   การ์ดเลือก sm · ปุ่มใช้สูตร base 6 step 1
         ↓ npm run tokens:build
Figma  3. ตัวแปรที่ผูกได้จริง        card/radius/top-left · button/radius/top-left/md
```

**ชั้น 1 กับ 2 ไม่กลายเป็นตัวแปรและไม่ออกมาเป็น CSS variable** เป็น input ของสูตรเท่านั้น เหตุผลอยู่ในข้อ 6

### 4.2 ตัวแปรจริงทั้งหมด 93 ตัว (ณ 2026-08-24)

| component | จำนวน | ค่า | หมายเหตุ |
|---|---|---|---|
| `button` | 21 | 6, 7, 8, 9, 10 ตาม xs ถึง xl + `full` | มาจากสูตร `base 6 + i x 1` |
| `icon-button` | 21 | เท่ากับปุ่ม | ใช้สูตรร่วมกับปุ่ม |
| `link-button` | 20 | 0 ทุกขนาด | ไม่มีพื้นหลังจึงไม่มีมุมโค้ง |
| `card` | 5 | 4 (4 มุม) + `full` 9999 | `full` ใช้กับ badge ที่ฝังในการ์ด |
| `tag` | 5 | 4 (4 มุม) + `full` 9999 | 2 ทรง ปกติกับแคปซูล |
| `badge` | 5 | 4 (4 มุม) + `full` 9999 | 2 ทรง ปกติกับกลม |
| `input` | 4 | 8 (4 มุม) | text field และ text area |
| `info-card` | 4 | 12 (4 มุม) | การ์ดข้อมูลในระบบเอกสาร ต้นฉบับอยู่หน้า 27 Card |
| `doc-table` | 4 | 8 (4 มุม) | กรอบตารางในเอกสาร (`token-table`) 11 จุด ใน 7 หน้า รวม template |
| `table` | 4 | 8 (4 มุม) | ตารางข้อมูลของโปรดักต์ หน้า 26 Table |

### 4.3 สเกลกลางในโค้ด

| ขั้น | ค่า | ใครใช้อยู่ |
|---|---|---|
| `none` | 0 | link-button |
| `xs` | 2 | ยังไม่มีใครใช้ สงวนไว้สำหรับของจิ๋ว |
| `sm` | 4 | **card tag badge** ค่าที่ใช้มากที่สุดในไฟล์ |
| `md` | 8 | input doc-table table |
| `lg` | 12 | info-card |
| `xl` | 16 | ยังไม่มีใครใช้ |
| `full` | 9999 | ทรงแคปซูลของ tag badge card button |

ค่าทั้งหมดมาจากการสำรวจของจริงในไฟล์ Figma เมื่อ 2026-08-20 ไม่ใช่ตัวเลขที่ตั้งขึ้นเอง

### 4.4 กฎกล่องซ้อนกล่อง (ตั้ง 2026-08-24)

**กรอบนอก = กล่องใน + 8** ระยะขอบมาตรฐานระหว่างกล่องซ้อนคือ 8 กลับสูตรได้เป็น กล่องใน = กรอบนอก ลบ 8 ถ้าติดลบให้ใช้ 0

| กรณีจริงในระบบ | กรอบนอก | ระยะขอบ | กล่องใน | หมายเหตุ |
|---|---|---|---|---|
| ภาพชิดขอบบนการ์ดข่าว | 4 | 0 | **4** | ไม่มีระยะขอบจึงเท่ากรอบนอก |
| กล่องข้างใน info-card | 12 | 8 | **4** | 12 ลบ 8 |
| ภาพในการ์ดที่มีระยะขอบ | 4 | 8 | **0** | ติดลบจึงใช้ 0 ปล่อยเป็นมุมฉาก |

## 5. ข้อควรระวังและปัญหาที่พบบ่อย (Constraints)

| # | ข้อควรระวัง | เหตุผล / วิธีปฏิบัติ |
|---|---|---|
| 1 | ห้ามสร้างตัวแปร radius ชั้นกลางใน Figma | ไฟล์นี้เคยมีมาแล้ว 2 รุ่นและถูกลบทั้งคู่ เหลือของค้าง 3,467 จุด (ดูข้อ 6) |
| 2 | ห้ามพิมพ์ตัวเลขมุมโค้งลงชิ้นงาน | ต้องผูกตัวแปรเสมอ ถ้าไม่มีให้แจ้งเพื่อไปนิยามในโค้ดก่อน |
| 3 | ห้ามแก้ค่าที่ Figma | Figma เป็นผลลัพธ์ แก้แล้วรอบหน้าที่ generate จะถูกทับ |
| 4 | **กล่องซ้อนกัน กรอบนอก = กล่องใน + 8** | ระยะขอบมาตรฐานระหว่างกล่องซ้อนคือ 8 มุมโค้งกล่องในจึงเท่ากับกรอบนอกลบ 8 ถ้าติดลบให้ใช้ 0 **ยกเว้นกรณีชิดขอบ** (ไม่มีระยะขอบ) กล่องในต้องใช้ค่าเท่ากรอบนอก เช่นภาพที่ชิดขอบบนการ์ด |
| 5 | corner smoothing ต้องเป็น 0 เสมอ | `corner-shape: squircle` ใน CSS ยังไม่รองรับทั่วถึง ถ้าเปิดไว้ไฟล์ออกแบบกับโค้ดจะไม่ตรงกัน |
| 6 | ห้ามใช้มุมโค้งเป็นสัญญาณเดียวที่สื่อความหมาย | คนที่มองเห็นไม่ชัดแยกความต่างของมุมไม่ออก ต้องมีสีหรือข้อความประกอบ |
| 7 | instance ของ component อื่นอย่าไป override | เช่นแท็กที่อยู่ในช่องกรอก ให้ไปแก้ที่ต้นทางของแท็ก ไม่ใช่ override ที่ instance |

## 6. ทำไมถึงจัดการตัวแปรแบบนี้ (บันทึกการตัดสินใจ 2026-08-20)

### สิ่งที่เจอในไฟล์

ตอนสำรวจเพื่อจะทำระบบใหม่ พบว่าไฟล์เคยมีสเกลกลางใน Figma **อย่างน้อย 2 รุ่น** และ **ถูกลบทิ้งทั้งคู่** โดยที่ชิ้นงานยังผูกอยู่

| รุ่น | ตัวอย่างชื่อ | จุดที่ยังผูกค้าง |
|---|---|---|
| รุ่นเก่า | `Shape/Btn/full` `Shape/Txf/lg` | 331 |
| รุ่นถัดมา | `size/radius/sm` `size/radius/full` | 3,136 |

รวม **3,467 จุด** ที่ผูกกับตัวแปรที่ไม่มีอยู่แล้ว ค่ายังแสดงผลได้เพราะ Figma จำค่าสุดท้ายไว้ แต่แก้ตรงกลางยังไงก็ไม่ขยับ และมองจากรายชื่อตัวแปรไม่เห็น ต้องไล่ดูจาก binding ของ node ถึงจะเจอ

### บทเรียนที่ได้

1. **ชั้นกลางที่ไม่มีใครใช้จะถูกลบ** และตอนถูกลบมันพาของที่ผูกอยู่ตายไปด้วยแบบเงียบ ๆ · ระหว่างทำงานนี้เองก็เพิ่งสร้างชั้นกลาง 16 ตัวแล้วต้องถอยออก เพราะสร้างไว้ก่อนที่จะมีชิ้นงานมาใช้
2. **ที่เก็บการตัดสินใจควรมีที่เดียว** ก่อนหน้านี้มี 2 ที่คือค่าใน Figma กับสูตรในโค้ด และไม่มีใครประกาศว่าใครเป็นเจ้าของ พอ radius ถูกพิมพ์ตายไว้ใน Figma แล้วก๊อปมาที่โค้ด สองฝั่งจึงหลุดจากกันโดยไม่มีใครรู้
3. **ตัวแปรที่ปลอดภัยที่สุดคือตัวที่มีชิ้นงานผูกตั้งแต่วันแรก** ทุกตัวใน 93 ตัวปัจจุบันมีชิ้นงานผูกจริง

### ทางที่เลือก

**ตัวเลขทั้งหมดโค้ดเป็นคนตัดสินโดยคำนวณจากสเกล Figma เป็นผลลัพธ์** และ **ตัวแปรใน Figma มีชั้นเดียวคือระดับ component**

ผลที่ตามมาคือไม่มีตัวแปรที่ไม่มีคนใช้ได้อีก เพราะตัวแปรจะถูกสร้างก็ต่อเมื่อมี component ที่ต้องใช้มันจริง และการเปลี่ยนบุคลิกทั้งระบบยังทำได้ด้วยการสลับสเกลในโค้ดที่เดียว

### ทางที่ไม่เลือก และเหตุผล

| ทางเลือก | ทำไมไม่เลือก |
|---|---|
| ทำชั้น primitive กับ semantic ใน Figma ให้ครบ | เคยทำมาแล้ว 2 รุ่นและตายทั้งคู่ รอบล่าสุดทำแล้วถอยออกภายในวันเดียวเพราะไม่มีชิ้นงานผูก |
| ให้ Figma เป็นเจ้าของค่าตัวเลข | ขัดกับระบบสเกลของความสูงและระยะห่างที่โค้ดเป็นเจ้าของอยู่แล้ว จะได้ 2 โมเดลในระบบเดียว |
| ตั้งชื่อ radius ด้วย xs sm md lg xl ในชั้นที่ผูกได้ | ชนกับชื่อขนาดของ component ที่ใช้อยู่ ทำให้สื่อสารผิดทันที |
