# [DS]-[Docs] Design เอกสารภาพรวมระบบ docs README

## รายละเอียดงาน

**Problem ปัญหาคืออะไร ? :**

- ไม่มีไฟล์ docs/README.md ทั้งที่กติกาของโปรเจกต์สั่งให้อ่านทุกครั้งก่อนเริ่มงาน
- คนเข้ามาใหม่ไม่มีจุดเริ่มต้น ต้องเดาเองว่าความจริงอยู่ที่ไหน ค่าไหลอย่างไร และเอกสารแต่ละฉบับอยู่ตรงไหน

**Goal ทำเพื่ออะไร ? :**

- มีเอกสารภาพรวมที่อ่านจบแล้วรู้ว่าระบบประกอบด้วยอะไร ใครเป็นเจ้าของความจริงของแต่ละชั้น และจะไปอ่านต่อที่ไหน

**Requirements ขอบเขตงาน**

1. อธิบายชั้นของระบบและเจ้าของความจริงของแต่ละชั้น
2. อธิบายทางเดินของค่าจากไฟล์ออกแบบไปเป็นโค้ด และด่านตรวจตอนสร้างไฟล์
3. รวมคำสั่งที่ใช้บ่อยและกฎที่ห้ามฝ่าฝืน
4. ทำสารบัญเอกสารทั้งหมด ทั้งกติกา เอกสารประจำหน้า และงานวิจัย พร้อมบอกว่าหน้าไหนยังไม่มีเอกสาร

**Figma File :**

- ไม่มี เป็นงานเอกสารฝั่งโค้ด

**Reference ตัวอย่างงานที่ชอบ :**

- docs/rules/page-doc-template.md ที่วางโครงเอกสารประจำหน้าไว้แล้ว

#### **worklog 1**

- เขียนไฟล์ภาพรวมระบบใหม่ทั้งไฟล์ ให้เป็นจุดเริ่มต้นของเอกสารทั้งหมดในโปรเจกต์ จากเดิมที่ไม่มีเลยทั้งที่กติกาสั่งให้อ่านทุกครั้งก่อนเริ่มงาน
- อธิบายชั้นของระบบ พร้อมบอกว่าใครเป็นเจ้าของความจริงของแต่ละชั้น
- อธิบายทางเดินของค่าจากไฟล์ออกแบบไปเป็นตัวแปรที่เอาไปใช้จริง และบันทึกไว้ว่าการดึงผ่าน REST ใช้ไม่ได้บนแพลนปัจจุบัน
- รวมด่านตรวจตอนสร้างไฟล์ คำสั่งที่ใช้บ่อย และกฎที่ห้ามฝ่าฝืน ไว้ที่เดียว
- ทำสารบัญเอกสารทั้งหมด พร้อมบอกชัดว่าหน้าไหนยังไม่มีเอกสาร

#### **ผลตรวจ**

- ชั้นของระบบ 6 ชั้น ระบุเจ้าของความจริงครบทุกชั้น
- ด่านตรวจ 3 ด่าน คือ มุมโค้ง ระยะห่าง และค่าซ้ำในสเกลกลาง
- กฎที่ห้ามฝ่าฝืน 7 ข้อ และคำสั่งที่ใช้บ่อย 5 คำสั่ง
- สารบัญครอบคลุมหน้าทั้งหมด 37 หน้า ระบุว่ามีเอกสารแล้ว 17 หน้า
- ตรวจลิงก์ทั้งไฟล์ ลิงก์เสีย 0
