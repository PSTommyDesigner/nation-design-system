# [DS]-[Core] Design ท่อสร้าง CSS ของ component จากไฟล์ออกแบบ

## รายละเอียดงาน

**Problem ปัญหาคืออะไร ? :** CSS ของ component เขียนมือจากการอ่านไฟล์ออกแบบด้วยตา token บอกแค่ว่ามีตัวแปรอะไรค่าเท่าไร แต่ไม่บอกว่าชั้นไหนใช้ตัวแปรไหน จึงผิดจากไฟล์ออกแบบซ้ำ ๆ (เส้นขอบอยู่ผิดชั้น มุมโค้งไม่ตัดลูก สีกล่องตัวเลขผูกผิด สีโหมดเทาผิด ไม่มีเงา) และด่านตรวจค่าทั้งหมดจับไม่ได้ เพราะทุกตัวแปรมีจริงและค่าตรง แค่ใช้ผิดที่ หัวหน้าทัก 2026-10-22 ว่าระบบไม่ได้เชื่อมต่อกัน อ่านด้วยตาทำไมทั้งที่ไฟล์ออกแบบบอกอยู่ว่าใช้อะไรตรงไหน**Goal ทำเพื่ออะไร ? :** ไฟล์ออกแบบเป็นต้นทางของทั้งค่าและโครง CSS ส่วนที่เป็นค่าของทุก component ถูกสร้างจาก spec ชั้นที่ดึงจาก Figma ไม่ใช่เขียนมือ แก้ไฟล์ออกแบบแล้วสั่งคำสั่งเดียวได้ CSS ใหม่ที่ถูกต้อง และมีด่านฟ้องเมื่อมีคนแก้ CSS มือ ชั้นที่ไม่รู้จัก สีดิบ หรือ token ที่ไม่มี**Requirements ขอบเขตงาน**
1. สคริปต์ดึง spec ชั้นจาก Figma ผ่าน REST (แพลน pro) เก็บเป็น tokens/figma-layers/<component>.json พร้อมตรวจ drift ระหว่างตระกูลและขนาด และ map id ตัวแปรเป็นชื่อ (ทำแล้ว 2026-10-22 สำหรับ Tag)
2. สคริปต์สร้าง CSS จาก spec มีตารางจับคู่ ชุด→คลาส และ ชั้น→ช่อง ตรวจว่าทุก token มีจริง ส่วนวิธีวาดแยกเป็น <Name>.base.css ที่ไม่มีชื่อ token และด่าน npm run verify:css (ทำแล้วสำหรับ Tag)
3. ขยายไป Badge, Button, IconButton, LinkButton แล้วไล่ component ที่เหลือทีละตัว ทุกตัวต้องถ่ายภาพ Storybook เทียบไฟล์ออกแบบก่อนถือว่าตรง
4. รายงาน drift ที่สคริปต์พบในไฟล์ออกแบบให้หัวหน้าตัดสิน แล้วแก้ที่ Figma ไม่ใช่ที่โค้ด (หน้า 21 ตัดสินแล้ว 4 เรื่อง 2026-10-26)
5. ไม่รวมในรอบนี้: ท่อเขียนค่ากลับเข้า Figma จากฝั่ง dev ทำแยกทีหลัง
**Figma File :** [หน้า 21 Tags](https://www.figma.com/design/QgmoT5Uuvv3elB96F4nsTq/?node-id=7121-7240) เป็นหน้าแรกที่ใช้ท่อนี้ แล้วไล่ไปหน้า 22 Badge และ 12 Buttons**Reference ตัวอย่างงานที่ชอบ :** ไม่มี ใช้ tokens/figma-layers/tag.json กับ scripts/generate-component-css.mjs ที่ทำแล้วเป็นต้นแบบ
