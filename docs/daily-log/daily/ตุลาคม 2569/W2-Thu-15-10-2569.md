### ที่รายงานผิดแล้วแก้

- รายงานไปว่ามี 4 ตัวในโค้ดที่ไม่มีต้นทางในไฟล์ออกแบบ ซึ่งไม่จริง ของจริงคือโฟลเดอร์เปล่า 0 ไฟล์ ผมนับจากชื่อโฟลเดอร์แล้วสรุปว่าเป็นโค้ดโดยไม่ได้เปิดดูข้างใน ของจริงโค้ดมี 16 ตัว ไม่ใช่ 20 และทุกตัวมีต้นทางในไฟล์ออกแบบครบ ไม่มีเรื่องโค้ดนำหน้าไฟล์ออกแบบเลย
- บทเรียนเดียวกับที่เจอเมื่อวาน คือนับของจากชื่อแล้วสรุป โดยไม่เปิดดูของจริง รอบนี้ลามไปถึงข้อสรุปของงานวิจัยหนึ่งใบที่เขียนไว้ตั้งแต่ก่อนหน้า

- เขียน Table เสร็จ ใช้โครงตารางจริงครบ caption colgroup thead tbody th scope ไม่มี div สวมรอย ช่องติ๊กหยิบ Checkbox ที่เพิ่งเขียนมาใช้ ไม่ได้เขียนเอง รองรับเรียงลำดับพร้อม aria-sort และเลื่อนแนวนอนที่เข้าถึงด้วยคีย์บอร์ดได้
- ตรวจซ้ำเองทุกตัว typecheck 0 error สีดิบ 0 px ดิบนอกข้อยกเว้น 0 ขีดยาว 0 และไล่เช็คทุกชื่อใน var ว่ามีจริง ได้ 0 ชื่อผี

### หัวหน้าทักว่างานไม่เรียบร้อย แก้แล้ว

- ชุด icon-tag ทั้ง 33 ชุดถูกวางลงในกริดของชุดอื่น เช่น icon-tag ไปอยู่ในกริดของ checkbox-tag และ link-icon-tag ไปอยู่ในกริดของ link-tag ทำให้ไม่มี section ของตัวเอง ไม่มีหัวข้อ ไม่มีคำอธิบาย
- สาเหตุคือตอนสร้างผมสั่งวางที่ src.parent ซึ่งคือกริดของชุดต้นแบบ โดยไม่ได้ดูโครงจริงของหน้าก่อนว่าแต่ละชนิดมี row กับ section ของตัวเอง
- ชุดที่สร้างยังไม่ได้จัด layout เลย คือ layoutMode เป็น NONE ไม่มีระยะขอบ ไม่มีพื้น ไม่มีกรอบประ ต่างจากชุดอื่นที่เป็นแนวนอนตัดบรรทัด ระยะขอบ 40 ช่องไฟ 24 พื้นผูกตัวแปร และกรอบประ 10 เว้น 5
- แก้โดยสร้าง icon-tag-row ให้ทุกตระกูล ข้างในมี section ของ icon-tag กับ pill-icon-tag ส่วน link-icon-tag ไปอยู่ใน link-tag-row ตามแบบที่หน้านี้ใช้อยู่ ทุก section มี header ที่มีหัวข้อกับคำอธิบาย และ grid ที่มีชุดกับบรรทัดนับจำนวน

### ปิดช่องโหว่ของด่านตรวจไฟล์ออกแบบกับโค้ด

### ปิดช่อง semantics ที่เหลือ และเจอของจริง

### เขียน components/Tag ให้ทันไฟล์ออกแบบ

- เพิ่ม prop leftIcon ตรงกับ left-icon กับ left-icon-swap ออกแบบให้ส่งไอคอนเข้ามาเท่ากับเปิด ไม่ส่งเท่ากับปิด จึงไม่ต้องมีตัวเปิดปิดแยกให้ซ้ำซ้อน
- เพิ่ม prop iconOnly กับ icon กับ label สำหรับโหมดไอคอนล้วน ตรงกับชุด icon-tag และ circular-icon-tag และ link-icon-tag
- เพิ่มทรง circular เข้า TagShape และบังคับเข้าโหมดไอคอนล้วนให้เอง เพราะไฟล์ออกแบบมีแต่ชุดไอคอนล้วนในทรงนี้
- เพิ่ม closeIcon ตรงกับ right-icon-swap ส่วนชื่อ prop เดิม closable เก็บไว้ เพราะคู่กับ onClose และอ่านเข้าใจง่ายกว่าในโค้ด เขียนกำกับไว้ว่าตรงกับ right-icon ในไฟล์ออกแบบ
- ยกเว้นชนิด indicator ไม่ให้มีไอคอนซ้าย ตรงกับที่ไฟล์ออกแบบยกเว้นไว้ เพราะช่องซ้ายเป็นของจุดสถานะ
- เพิ่ม CSS ของโหมดไอคอนล้วน 15 บล็อก คือ 3 ทรงคูณ 5 ขนาด ผูก token ของทรงกลม 30 จุด
- แก้ขนาดไอคอนของชนิดที่ชนขอบ 20 จุด ให้ใช้ token ของชนิดนั้นเอง ไม่ใช่ของชุดฐาน ตรงกับที่ผูกไว้ในไฟล์ออกแบบ
- เพิ่มคลาสซ่อนแบบเข้าถึงได้ เพราะโหมดไอคอนล้วนไม่มีข้อความบนจอ ถ้าไม่มีชั้นนี้โปรแกรมอ่านหน้าจอจะอ่านไม่ออกว่าแท็กนี้คืออะไร
- ตรวจแล้ว typecheck 0 error สีดิบ 0 px ดิบนอกข้อยกเว้น 0 ขีดยาว 0 ชื่อ var ที่ไม่มีจริง 0 และคลาสที่ TSX เรียกแต่ CSS ไม่มี 0 จากทั้งหมด 38 คลาส
- อัปเดต README ของ Tag ครบทั้งตาราง props และข้อควรระวัง

### ด่านที่สี่ เทียบแกนในไฟล์ออกแบบกับ props ในโค้ด

- สร้าง scripts/verify-component-api.mjs กับคำสั่ง npm run verify:api เก็บแกนและคุณสมบัติจากไฟล์ออกแบบไว้ที่ tokens/figma-components.json แล้วเทียบกับ props จริงที่ถอดจากไฟล์ tsx
- ตัวถอด props อ่าน interface ของ component โดยนับวงเล็บปีกกา ไม่ใช่หาวงเล็บปิดตัวแรก กันกรณีมี object ซ้อน และอ่านชนิดข้อมูลแบบ union เพื่อเทียบว่าค่าในแกนครบไหม
- ตารางจับคู่เขียนด้วยมือโดยตั้งใจ เพราะชื่อสองฝั่งต่างกัน เช่น default-gray คู่กับ defaultGray ส่วนแกนที่ไม่มีคู่ให้ใส่ accepted พร้อมเหตุผล เช่น แกน state ที่โค้ดใช้ pseudo-class ของ CSS แทน
- ทดสอบว่าจับได้จริง แกล้งถอด prop leftIcon ออก และแกล้งตัดค่า xl ออกจากแกนขนาด ด่านฟ้องครบ 3 จุด คือค่าไม่ครบ 1 และขาด prop 2 และคืนรหัสออก 1 แล้วคืนไฟล์กลับ เทียบแล้วเหมือนเดิมทุกไบต์
- เก็บข้อมูลได้แค่ Tag ตัวเดียว เพราะ Figma ติดโควตาการเรียกของแพลนที่ใช้อยู่ อีก 21 ตัวด่านจะขึ้นเตือนว่ายังไม่ได้เก็บ ไม่ได้แกล้งทำเป็นผ่าน
- บันทึกกฎลง CLAUDE.md แล้วว่าแก้แกนใน Figma ต้องอัปเดตไฟล์เก็บข้อมูลแล้วรันด่านนี้

### เก็บงานก่อนขึ้น git และตั้ง git

- ลบ CL.md ทิ้งตามที่หัวหน้าสั่ง เป็นไฟล์ที่ไม่มีใครอ้างถึงแล้ว
- เขียน .gitignore ใหม่ โดยเอาเรื่องความลับขึ้นก่อนเป็นหัวข้อแรก คือ .env และ .env ทุกรูปแบบ เพราะในนั้นมีโทเค็นของ Figma และ Asana ถ้าหลุดขึ้นไปแม้ commit เดียวจะอยู่ในประวัติตลอดไป ลบทีหลังไม่หาย ต้องเพิกถอนโทเค็นแล้วออกใหม่เท่านั้น
- เขียนหมายเหตุกำกับไว้ด้วยว่าอะไรที่ตั้งใจไม่ใส่ในรายการกัน คือ tokens/output และไฟล์ลายนิ้วมือสองใบ เพราะทีมอื่นต้องหยิบไปใช้ และด่านตรวจต้องรันได้โดยไม่ต้อง build ก่อน
- สแกนหาความลับ 3 ชั้นก่อน commit คือไล่ชื่อไฟล์ ไล่เนื้อหาหารูปแบบของโทเค็น และไล่รายการไฟล์ที่ git จะเก็บจริง ไม่พบความลับหลุดสักจุด
- ตั้ง git แล้ว commit แรก 583 ไฟล์
- แก้ชื่อผู้เขียน commit ให้เป็นบัญชีที่จะใช้จริงคือ PSTommyDesigner กับอีเมลบริษัท ตั้งเฉพาะโปรเจกต์นี้ ไม่แตะค่ากลางของเครื่อง แล้วเขียน commit ทับให้ชื่อผู้เขียนถูกตั้งแต่ใบแรก
- เตรียมขั้นตอนสร้าง repo แบบส่วนตัวบนเว็บให้หัวหน้าแล้ว ยังไม่ได้สร้างและยังไม่ได้ push
- พบว่า SSH key ในเครื่องผูกอยู่กับบัญชี tommyyps ไม่ใช่ PSTommyDesigner และ GitHub ไม่ยอมให้ key เดียวอยู่สองบัญชี จึงต้องเลือกว่าจะใช้โทเค็นหรือสร้าง key ใหม่

### หยุดงาน git เพราะหัวหน้าทักว่าสีหลุดในไฟล์ออกแบบ

- หัวหน้าส่งภาพหน้า 21 Tags ตระกูล Brown มาว่าสีหลุด จึงหยุดงาน git ทันทีแล้วไปตรวจ
- ยืนยันว่าหลุดจริง 45 จุด อยู่ที่ตระกูล Brown ตระกูลเดียว อีก 10 ตระกูลผ่านหมด และไม่มีสีดิบแม้แต่จุดเดียว
- สาเหตุคือชุด icon-tag กับ circular-icon-tag กับ link-icon-tag ของ Brown ถูกโคลนมาจากตระกูล Blue แล้วไม่ได้เปลี่ยนสีไอคอน กล่องกับขอบเปลี่ยนเป็นน้ำตาลครบแล้ว แต่ไอคอนยังผูกตัวแปรสีน้ำเงินค้างอยู่
- หลักฐานคือตารางสีของ Brown กับ Blue ในสามชุดนี้เหมือนกันทุกช่อง ซึ่งเป็นไปไม่ได้ถ้าทาสีเอง
- ผิดแค่ 3 ช่องของแกน คือ secondary ไม่เทา สถานะปกติ และ secondary ไม่เทา สถานะชี้ และ secondary เทา สถานะชี้ แต่ผิดทุกขนาด จึงได้ชุดละ 15 จุด รวมสามชุดเป็น 45
- หาค่าที่ถูกต้องจากสีตัวอักษรของ semi-rounded-tag กับ link-tag ของตระกูล Brown เอง ไม่ได้เดา ได้ว่าต้องเปลี่ยนน้ำเงิน 400 เป็นน้ำตาล 400 และน้ำเงิน 500 เป็นน้ำตาล 500 และน้ำเงิน 600 เป็นน้ำตาล 600
- ช่อง primary กับช่องปิดใช้งานถูกอยู่แล้ว เพราะใช้สีกลางที่ไม่แยกตระกูล
- ยังไม่ได้แก้ หัวหน้าสั่งให้ไว้ทำพรุ่งนี้
- บทเรียนคือด่านตรวจทั้งสี่ด่านที่ทำวันนี้จับเรื่องนี้ไม่ได้เลย เพราะทุกจุดผูกตัวแปรถูกต้องตามกฎ แค่ผูกผิดตระกูล ด่านที่มีดูแต่ชื่อกับค่าของ token ไม่ได้ดูว่าสีที่ใช้ตรงกับตระกูลที่มันอยู่ไหม
