## 1. หน้า 13 Input ทำให้โค้ดกับไฟล์ออกแบบตรงกัน

ค้างมาจากที่ user แก้ค่าตัวแปรใน Figma ไว้แล้วยังไม่ได้เทียบกับโค้ด

### ที่ตรวจเจอ

เทียบทั้ง 3 ชนิดในหน้าเดียวกันแล้วเห็นกติกาที่ใช้อยู่จริง คือ **ซ้ายขวาใช้ตัวแปรกลางร่วมกัน ส่วนบนล่างใช้ตัวแปรเฉพาะชนิด**

ภายใต้กติกานี้ **ขนาด sm ของ tag-field เป็นตัวเดียวที่หลุด** ผูกซ้ายขวาไปที่ตัวแปรเฉพาะแทนตัวกลาง ค่าที่ออกมาจริงจึงเป็น 6, 12, 14 ซึ่งไม่ใช่ทั้งชุด 6, 8, 12 และไม่ใช่ชุด 10, 12, 14

### ที่ตัดสิน

| ข้อ | ผล |
|---|---|
| ระยะขอบบนล่างของ tag-field | ยึด Figma เป็น 0 โค้ดเปลี่ยนจาก 4, 6, 8 |
| ระยะขอบซ้ายขวาของ tag-field | 6, 8, 12 ทั้ง 3 ขนาด แก้ md จาก 12 และ lg จาก 14 |
| ความสูงขั้นต่ำ | ผูกกับ `input/height` เลิกเป็นค่าดิบ |
| ระยะขอบบนล่างของ text-field | ผูกกับ `input/padding/top` และ `bottom` |

**ข้อระยะขอบซ้ายขวาเป็นการกลับคำจากที่ตัดสินไว้เมื่อ 1 กันยายน** ซึ่งตอนนั้นบันทึกว่าย้ายไปใช้ค่ากลาง 10, 12, 14 เขียนกำกับไว้ในเอกสารแล้วว่ากลับคำเพราะอะไร

### เปลี่ยนกลไก ไม่ใช่แค่เปลี่ยนตัวเลข

เดิมใช้ระยะขอบดันให้แท็กไปอยู่กลางช่อง ตอนนี้ใช้ความสูงขั้นต่ำเท่าความสูงช่องบวกจัดกึ่งกลางแนวตั้ง ผลที่ตาเห็นเหมือนเดิม แต่ความสูงถูกกำหนดตรง ๆ และเวลาแท็กขึ้นบรรทัดใหม่กล่องจะโตตามเนื้อหาโดยไม่มีระยะขอบค้างมาบวกซ้ำ

ผูกเพิ่มใน Figma 120 จุด ตรวจค่าจริงทั้ง 24 แบบของ tag-field ไม่มีแบบไหนหลุดจากเป้า สแกนหน้า 13 แล้วสีดิบ 0 เส้นดิบ 0 em-dash 0 จุดกลาง 0

## 2. ตอบคำถามเรื่องชื่อ ควรเปลี่ยน input เป็น text field ไหม

**สรุปว่าไม่ควร** เหตุผลหลักไม่ใช่ต้นทุน แต่เป็นโครงสร้าง

`input` เป็นชื่อตระกูลที่มีลูก 3 ชนิด คือ text-field, text-area และ tag-field ถ้าเปลี่ยนตระกูลเป็น text-field จะได้ตระกูลชื่อเดียวกับลูกของตัวเอง และ tag-field ไม่ใช่ช่องข้อความ มันคือตัวเลือกหลายค่า จะอยู่ผิดบ้านทันที

ต้นทุนถ้าจะเปลี่ยนคือตัวแปร 59 ตัว จุดผูก 1,292 จุดใน 3 หน้า (13 Input 1,208 · 36 Templates 80 · 06 Shape 4) บวกชื่อในโค้ดและเอกสารทั้งชุด

## 4. สองเรื่องที่ผมสรุปผิดแล้วแก้แล้ว

### 4.1 การสแกนหน้า 14 ถึง 17 พลาด

รอบแรกรายงานว่าไม่มี component เลย เพราะไล่แต่ลูกที่อยู่ในเฟรม แต่หน้าเหล่านั้นวาง COMPONENT_SET ไว้ที่ระดับบนสุดของหน้า จึงถูกข้ามหมด ของจริงมีครบทุกหน้า

### 4.2 button ไม่ได้แตกเป็น 3 namespace อย่างที่บอก

`button/*` กับ `icon-button/*` **ไม่ใช่ค่าคนละชุด แต่เป็นชั้นชื่อที่ชี้กลับมาที่สูตรเดียวกัน**

```
--ntg-button-size-md       → var(--ntg-space-button-height-md) → 40px
--ntg-icon-button-size-md  → var(--ntg-space-button-height-md) → 40px
```

เป็นโครง 2 ชั้นที่ถูกต้องอยู่แล้ว **และทำให้ข้อที่จดไว้ว่าโค้ดปุ่ม drift ต้องตัดออกจากรายการงานค้าง** เพราะโค้ดได้ค่าจากสูตรถูกต้องผ่าน alias ไม่ได้ค้างกับค่าเก่า

## 5. งานค้างใหม่ที่เจอวันนี้

- **`button/title-padding` ซ้ายขวา 4px ยังเป็นค่าดิบ ไม่อยู่ในไฟล์สูตร** โค้ดกับ Figma ตรงกัน (ต่างจากปุ่มลิงก์ที่ไม่ตรง) แต่ยังไม่มีใครอธิบายว่าทำไมถึงเป็น 4 และแก้ที่เดียวไม่ได้ **ต้องตัดสินด้วยว่าทำไมกรอบข้อความต้องมีระยะขอบเพิ่มอีก 4 ทั้งที่ตัวปุ่มมีอยู่แล้ว และทับซ้อนกับ gap 6 หรือไม่**
- **หน้า 14 ถึง 17 มี component แล้วแต่ไม่มี token สักตัว** ขนาดทุกอย่างเป็นค่าดิบ และชื่อยังไม่ผ่านกฎ เช่น `Text Toggle` `Text Checkbox` มีทั้งตัวใหญ่และเว้นวรรค
- **หน้า 22 Badge ชื่อไม่ตรงกฎใหม่** ไม่มีตัวไหนลงท้ายด้วย `-badge` และมี `icon-icon` ที่คำซ้ำในชื่อเดียว

## 7. หน้า 14 Toggles ตัดสิน 7 ข้อ แล้วลงมือทำระบบสเกลกับ component

การ์ด `[DS]-[Toggles] Design เอกสารและระบบสเกล หน้า 14 Toggles` (1218145396616701)

### ที่ตัดสิน

| ข้อ | ผล |
|---|---|
| ชุดสวิตช์พร้อมข้อความ | ยุบเป็นคุณสมบัติของชุดหลัก ไม่คงเป็นชุดแยก |
| โครงสเกล | สองชั้นแบบ Adobe Spectrum ภาพสวิตช์อิสระ แถวที่กดได้อ้างสเกลกลาง |
| ความกว้างราง | 36 เป็น 40 และ 44 เป็น 48 ให้ได้สัดส่วน 2.00 คงที่ |
| สถานะกด | ไม่ใส่ในรอบนี้ เพราะทั้งระบบยังไม่มีสถานะนี้ที่ไหนเลย |
| hover | เก็บไว้ |
| กลไกบอกสถานะไม่พึ่งสี | ไม่ทำเพิ่ม ปุ่มกลมขยับตำแหน่งผ่านเกณฑ์อยู่แล้ว |
| ขอบเขต | ครบรอบเดียว ทั้ง token component และเอกสาร |

### ที่ทำ

สร้าง `tokens/scale/toggle.mjs` ค่าตั้งต้นมีตัวเดียวคือความสูงราง ที่เหลือเป็นผลลัพธ์ พร้อมด่านตรวจสี่ข้อที่จะไม่ยอมให้สร้างไฟล์ถ้าค่าบวกกลับไม่ตรง สร้างตัวแปรใน Figma 13 ตัว แปลง component ทั้ง 16 แบบเป็นโครงสองชั้น ผูกตัวแปรครบทุกมิติ ยุบชุดที่สองเข้าชุดหลักเป็นคุณสมบัติเปิดปิดข้อความ ย้าย instance 6 ตัว แล้วลบชุดเดิม ตั้งชื่อทั้งชุดเป็นตัวเล็กตามกติกา

### สามเรื่องที่เจอตอนสำรวจ

- **มุมโค้ง 12 และระยะขอบใน 2 เป็นค่าดิบ** ไม่ผูกตัวแปรมาตลอด ตอนนี้เป็น token แล้ว และเปลี่ยนมุมโค้งเป็นค่าเต็มวงเพราะ 12 ทำให้ขนาดเล็กถูกบีบอยู่แล้ว
- **ทั้ง Design System ไม่มีสถานะกดเลยสักตัว** มีคำลงท้ายบอกสถานะอยู่คำเดียวคือ hover จำนวน 102 ตัว เปิดการ์ดแยกไว้แล้ว (1218146975973583)
- **สถานะปิดกับสถานะปิดใช้งานใช้สีเดียวกันเป๊ะ** ตรวจค่าจริงแล้วเหมือนกันทุกพิกเซล user สั่งให้ปล่อยไว้ จดเป็นข้อจำกัดที่รู้ตัวในเอกสารแล้ว

### ที่รายงานผิดแล้วแก้

รายงานว่า `Table / Cell / Avatar` มีสวิตช์สูง 66 ล้นออกนอกเซลล์ 44 **ไม่จริง** สวิตช์ตัวนั้นถูกซ่อนอยู่ เป็นตัวเลือกสำรองที่วางซ้อนไว้พร้อม Checkbox กับ Radio ตอนสำรวจอ่านแค่ขนาดกับลำดับชั้น ไม่ได้เช็ค visible เปิดการ์ดไปแล้วจึงปิดเป็น Cancelled พร้อมคอมเมนต์อธิบาย
