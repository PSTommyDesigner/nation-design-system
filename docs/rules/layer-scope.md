# ขอบเขตของแต่ละชั้นในไฟล์ออกแบบ และสิ่งที่เราตั้งใจไม่ทำ

> ตัดสิน 2026-10-12 · อ่านไฟล์นี้ก่อนถามว่า "ทำไมไฟล์ออกแบบไม่มี component ของ organism หรือ template"

## 1. สรุปสั้น

ไฟล์ออกแบบเก็บ **เฉพาะชั้น Atom กับ Molecule** เป็น component จริง ส่วนชั้น **Organism กับ Template เหลือไว้แค่หน้าหัวข้อ ไม่มี component** และชั้น **Page (Prototype) ลบทิ้งทั้งชั้นแล้ว**

การประกอบของชั้นบนจะไปทำที่ **เว็บของระบบออกแบบฝั่งโค้ด** ซึ่งผู้ใช้หยิบ atom กับ molecule มาต่อกันเองได้เหมือนกล่องทราย

## 2. แต่ละชั้นคืออะไร

คำอธิบายเดิมที่เคยอยู่บนหน้าปกของแต่ละชั้นในไฟล์ออกแบบ เก็บไว้ที่นี่เพื่อไม่ให้หายไปพร้อมหน้า

| ชั้น | คืออะไร | สถานะในไฟล์ออกแบบ |
|---|---|---|
| **Atoms (Identity)** | ส่วนที่เล็กที่สุดของการออกแบบส่วนต่อประสาน เช่น สี ตัวอักษร ไอคอน เงา มุมโค้ง ระยะห่าง ตารางกริด โลโก้ ลำพังตัวเดียวยังไม่เป็นรูปเป็นร่าง แต่เป็นฐานของทุกอย่าง | **มี component จริง** หน้า 00 ถึง 09 |
| **Molecules (Element)** | การรวมตัวของ atom จนได้ของที่ใช้งานได้จริงหนึ่งชิ้น เช่น ปุ่ม ช่องกรอก แท็ก แถบความคืบหน้า ตัวแบ่งหน้า | **มี component จริง** หน้า 10 ถึง 28 |
| **Organisms (Component)** | การรวมตัวของ atom กับ molecule หรือ molecule หลายตัวมาต่อกันจนใหญ่และซับซ้อนขึ้น เช่น ส่วนหัวของเว็บไซต์ที่รวมโลโก้ ปุ่ม และช่องค้นหาเข้าด้วยกัน | **ไม่มี component** เหลือแค่หน้าหัวข้อ |
| **Template (Composition)** | การรวม organism หลายตัวเป็นผังของหน้า เป็นโครงที่ยังไม่ใส่เนื้อหาจริง | **ไม่มี component** เหลือแค่หน้าหัวข้อ |
| **Page (Prototype)** | การเอา template มาใส่เนื้อหาจริงจนเป็นหน้าที่ผู้ใช้เห็น | **ลบ component ทั้งชั้นแล้ว** เหลือหน้าหัวข้อที่มีเอกสาร 2 ใบ |

## 3. ทำไมไฟล์ออกแบบไม่ทำ component ของสองชั้นบน

### 3.1 ตลาดก็ไม่ทำ

งานวิจัยที่ทำระหว่างปี 2569 (ดู `docs/research/`) พบตรงกันว่า DS เจ้าใหญ่ **ส่ง atom กับ molecule เป็น component** ส่วน organism กับ template **ส่งเป็นเอกสารบวกตัวอย่างโค้ด** ไม่ใช่ component ในไฟล์ออกแบบ

### 3.2 ชั้นบนดริฟต์เร็วที่สุด

ของที่ประกอบจากหลายชิ้น เวลาชิ้นใดชิ้นหนึ่งเปลี่ยน ของที่ประกอบไว้จะตามไม่ทัน แล้วกลายเป็นตัวอย่างที่ผิด **ซึ่งอันตรายกว่าไม่มีตัวอย่างเลย** เพราะคนเชื่อว่ามันถูก

ตัวอย่างจริงที่เจอในไฟล์นี้

- หน้า 36 Templates เคยมีตัวแบ่งหน้าที่ **ฝังระยะขอบไว้ในตัว component** ทำให้ตอนเปลี่ยนไปใช้ชุดใหม่ต้องห่อกรอบให้ใหม่ เพราะระยะขอบแบบนั้นเป็นของ layout ไม่ใช่ของชิ้นงาน
- หน้า 33 Sidebars ใช้ของจากหน้า Lists (เลขเดิม 27 ยุบไปแล้ว) ถึง **235 จุด** ซึ่งเป็นการพึ่งพาข้ามหน้าที่ไม่มีใครเห็นภาพรวม

### 3.3 สิ่งที่ Figma ทำไม่ได้ แต่โค้ดทำได้

งานวิจัยหลายหน้าพบว่า Figma แสดงพฤติกรรมจริงไม่ได้ เช่น **ผูกตัวแปรกับมุมของส่วนโค้งไม่ได้** (หน้า 23) **ผูกความกว้างสูงสุดของชั้นข้อความไม่ได้** (หน้า 20) และ **แสดงการตอบสนองต่อขนาดจอไม่ได้ถ้าไม่ทำเป็นแบบแยก** (หน้า 24) ซึ่งทั้งสามเรื่องเป็นหัวใจของชั้น organism ขึ้นไป

## 4. ⚠️ สิ่งที่ต้องระวังที่สุด ชื่อชั้นไม่ได้บอกว่าของข้างในเป็นอะไร

ตอนสำรวจเพื่อลบสองชั้นนี้ **พบว่า 5 หน้าที่อยู่ในชั้น Organism กับ Template จริง ๆ แล้วเก็บชิ้นส่วนพื้นฐานที่ทั้งระบบพึ่งพาอยู่** ทั้งหมดถูกย้ายขึ้นชั้น Molecule แล้ว

| หน้าเดิม | ของที่อยู่ข้างใน | ถ้าลบไปจะพัง |
|---|---|---|
| Header (เลขเดิม 34) | `_document-header` หัวเอกสารที่ใช้ในเอกสารทุกใบ | **198 จุด ทั่วทั้งไฟล์** |
| Lists (เลขเดิม 27) | รายการและแผงที่ dropdown กับ sidebar ใช้ | **237 จุด** |
| 28 Dividers | เส้นคั่นที่หน้า 13 Input ใช้ | **72 จุด** |
| 26 Table | ชุดที่ลงท้ายด้วย `-table-cell` ที่ตารางในเอกสารทุกหน้าใช้ | ตารางทุกเอกสาร |
| 27 Card | `info-card / do` `don't` `how-to-read` ที่เอกสารทุกหน้าใช้ | การ์ดในเอกสารทุกหน้า |

**บทเรียน** ก่อนลบหน้าใดก็ตาม **ต้องสแกนหาคนใช้ก่อนเสมอ** อย่าเชื่อว่าชื่อชั้นบอกความจริง ชื่ออย่าง Header ฟังดูเหมือนส่วนหัวของเว็บไซต์ แต่จริง ๆ คือที่อยู่ของหัวเอกสาร

## 5. ของที่ลบไปแล้ว

ลบเมื่อ 2026-10-12 หลังสแกนยืนยันว่าไม่มีหน้าไหนใช้ของจากหกหน้านี้เลย

| หน้า | component |
|---|---:|
| 36 Templates | 132 |
| Image And Carousel (เลขเดิม 26) | 82 |
| 32 Modals | 49 |
| 33 Sidebars | 44 |
| 30 Panels | 6 |
| 35 Footer | 0 |
| **รวม** | **313** |

บวกหน้า Desktop และ Mobile ของชั้น Prototype ซึ่งว่างเปล่าทั้งคู่

**⚠️ ในยอด 82 ของหน้า Image And Carousel มีแคโรเซล 4 ชุด 66 แบบที่เพิ่งย้ายมาจากหน้า 24 รวมอยู่ด้วย** ย้ายมาเช้าวันเดียวกันแล้วถูกลบพร้อมหน้าตอนบ่าย **ผู้ใช้ตัดสินเมื่อ 2026-10-14 ว่าไม่กู้จากประวัติรุ่น** ให้ออกแบบใหม่ตอนเปิดงานแคโรเซลจริง บทเรียนคือ ก่อนลบหน้าต้องรายงานของที่อยู่ข้างในก่อนเสมอ แม้จะมีคำสั่งให้ลบแล้วก็ตาม

### 5.1 ยุบหน้า Lists (เลขเดิม 27) ทั้งหน้า เข้าหน้า 25 Dropdowns

ทำเมื่อ 2026-10-12 สองรอบ รอบแรกลบ `Lists Template / *` **14 ชิ้นระดับบนสุด รวม 26 component** ซึ่งเป็นแม่แบบรายการที่ประกอบไว้ล่วงหน้า รอบสองยุบทั้งหน้า

**ทำไมยุบได้** สแกนทั้ง 44 หน้าแล้วพบว่า **ไม่มีหน้าไหนนอกหน้า 27 ใช้ของจากหน้า 27 เลยสักจุด** ของที่ยังมีคนใช้อยู่ 24 จุดคือตระกูล Sidebar ซึ่งถูกใช้บนหน้า 27 เองทั้งหมด เพราะหน้า 33 Sidebars ที่เคยใช้ถึง 235 จุดถูกลบไปก่อนหน้านี้แล้ว

**ตระกูลของ list item ที่มีจริง 5 ตระกูล 18 ชุด 101 component**

| ตระกูล | ชุด | แบบ | คนใช้ | ผลตัดสิน |
|---|---|---:|---:|---|
| แถวของ dropdown | `List Item / Dropdown` `List Item / Dropdown&Check` | 36 | 0 | **ยกความสามารถเข้า `_dropdown-option`** แล้วลบ |
| แถวหน้าตั้งค่า | `Default` `Radio` `Checkbox` `Toggle` | 24 | 0 | ตัดทิ้ง ไม่ใช่ตัวเลือกใน dropdown เพราะมีสวิตช์กับเส้นคั่นและสูงสองบรรทัด dropdown เลือกแล้วปิด แต่สวิตช์ต้องค้างให้กดต่อ |
| แถบข้างและเมนู | `Sidebar` `Lvl.1` `Lvl.2` `Lvl.3` `Menu Item` | 27 | 24 จุดบนหน้าตัวเอง | ตัดทิ้ง ปลายทางคือหน้า 33 ซึ่งลบไปแล้ว และยังอ้างไอคอนชุด `Material design(2)` ที่เลิกใช้ |
| ผังต้นไม้กับเปอร์เซ็นต์ | `Hierarchy Header` `Hierarchy Item` `Person` | 10 | 0 | ตัดทิ้ง เป็นของเฉพาะงาน org roll-up ที่ยังไม่เริ่ม ไม่ใช่ของกลางของระบบ |
| หัวเรื่องและเส้นเวลา | `Header / Sidebar` `Header / User` `Header / Text` `Timeline` | 4 | 0 | ตัดทิ้ง หัวกลุ่มย้ายไปเป็น `_dropdown-group-header` ในแผงแทน |

**สิ่งที่ยกเข้าหน้า 25 คือความสามารถ ไม่ใช่ component** เพราะ `_dropdown-option` ครอบโครงของเก่าหมดแล้ว ขาดแค่สี่อย่าง คือ ไอคอนนำหน้า อวาตาร์นำหน้า ข้อความรอง และช่องติ๊กเลือกหลายค่า ทั้งสี่ทำเป็นปุ่มเปิดปิด จำนวนแบบจึงไม่เพิ่ม บวกหัวกลุ่มกับเส้นคั่นในแผงอีกสองอย่าง รายละเอียดอยู่ที่ `docs/25-dropdowns.md`

**จุดสีนำหน้าตัดทิ้ง** (ผู้ใช้ตัดสิน) เพราะไม่มี component ไหนใน DS ทำหน้าที่นี้ และสีอย่างเดียวสื่อความหมายไม่ได้ตามเกณฑ์การเข้าถึง

**ผลพลอยได้** ชุด `_Scroll bar` บนหน้า 25 ที่เคยมีคนใช้ 11 จุด เหลือ 0 เพราะผู้ใช้ทั้งหมดอยู่บนหน้า 27 จึงลบได้ด้วย ไฟล์เหลือ 43 หน้า

## 6. แล้วจะดูตัวอย่างการประกอบที่ไหน

**เว็บของระบบออกแบบฝั่งโค้ด** ซึ่งยังไม่ได้ทำ เป็นงานที่รอหลังตั้งระบบเก็บรุ่นของโค้ดเสร็จ

ข้อกำหนดที่ตกลงไว้แล้ว

- **ต้องสร้างจาก token กับ component ชุดเดียวกับที่ใช้งานจริง** ไม่ใช่หน้าที่เขียนมือ ไม่งั้นจะกลายเป็นของที่ดริฟต์อีกชั้นหนึ่ง ซึ่งเป็นปัญหาเดิมที่เรากำลังหนี
- ผู้ใช้ต้องหยิบ atom กับ molecule มาต่อกันเองได้ เหมือนกล่องทราย
- ลำดับงานคือ ทำชั้น Molecule ให้ครบก่อน แล้วตั้งระบบเก็บรุ่นของโค้ด แล้วจึงทำเว็บ

### 6.2 เส้นแบ่งที่ใช้ตัดสินในสองหัวข้อ อะไรไม่นับ

| ชั้น | ถ้าเข้าข้อไหนข้อหนึ่ง แปลว่าไม่นับ |
|---|---|
| **organism** | ทำงานเรื่องเดียวถึงจะมีหลายปุ่ม เช่น แถบตัวแบ่งหน้า · ไม่มีความหมายเมื่ออยู่ลำพัง เช่น แถวตัวเลือกในแผง · เป็นชิ้นงานสำเร็จที่ระบบส่งมาให้แล้ว เช่น แบนเนอร์ |
