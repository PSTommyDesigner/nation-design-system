# Worklog Standard Nation Design System

> ทุกวันที่มีงาน ต้องมีบันทึก 1 ชุด ไฟล์ในเครื่องเป็นต้นทาง ส่วน Asana เป็นปลายทางที่หัวหน้าอ่าน

## 1. เก็บที่ไหน

| ที่เก็บ | เนื้อหา | ใครอ่าน |
|---|---|---|
| `docs/daily-log/daily/<เดือนไทย ปีพ.ศ.>/W{สัปดาห์}-{Day}-{DD}-{MM}-{พ.ศ.}.md` | สรุปรายวันเต็ม ทุกการ์ดรวมกัน (ต้นทางเดียว) | สคริปต์ เรา หัวหน้า |
| Asana | comment | หัวหน้า |
| Obsidian vault โฟลเดอร์ `Worklog <ปี ค.ศ.>/` | สำเนาที่สคริปต์สร้างให้ รายวัน สรุปรายเดือน และหน้าหลักของปี (ดู §7) | เรา อ่านย้อนหลังรายเดือน |

**สัปดาห์เริ่มนับ W1 ใหม่ทุกเดือน** (W1 = สัปดาห์ที่มี worklog แรกของเดือนนั้น) ปี พ.ศ. = ค.ศ. + 543 คั่นวันที่ด้วย `-` เพราะ `/` ใช้ในชื่อไฟล์ไม่ได้

**ไฟล์ประกอบ**
- `docs/daily-log/_template.md` แม่แบบ 4 หัวข้อ (สคริปต์ `worklog:new` สร้างไฟล์ตามนี้)
- **`scripts/worklog-path.mjs` เป็นตัวเดียวที่รู้กติกาชื่อไฟล์** สคริปต์อื่นต้อง import จากที่นี่ ห้ามคำนวณเอง

**เคยมีโฟลเดอร์ `detail/` เก็บฉบับเต็มเชิงเทคนิค ลบแล้ว 2026-08-25** เพราะเป็นภาพถ่ายของสถานะที่ไม่มีอยู่แล้ว (รหัส node กับตัวเลขอ้างของที่เปลี่ยนไปหมดแล้ว) และไม่เคยถูกเปิดใช้จริง **ต่อไปเขียนบันทึกรายวันให้จบในไฟล์เดียว ไม่ต้องแยกฉบับเต็ม**

**เคยมีสำเนา `.txt` ที่ `Worklog/` ราก ยกเลิกแล้ว 2026-08-25** เพราะเนื้อหาเหมือนกันทุกไบต์ ต่างแค่นามสกุล ไม่ได้ให้อะไรเพิ่ม แลกมาด้วยการก๊อปด้วยมือทุกวันและความเสี่ยงที่สองฝั่งหลุดกัน สิ่งที่มีค่าคือวิธีตั้งชื่อ ซึ่งยกมาใช้กับ `.md` แล้ว

## 2. เขียนยังไง

**4 หัวข้อคงลำดับเสมอ** `งานค้าง` `งานที่ทำวันนี้` `ผลลัพธ์` `ติดปัญหา`

**สไตล์ (สำคัญที่สุด)**
- ย่อ กระชับ ภาษาไทยเข้าใจง่าย **เน้นหลักการ ไม่ใช่ศัพท์โปรแกรมมิ่ง**
- แต่ละ bullet บอก **ทำอะไร + เพื่ออะไร + ได้ผลยังไง**
- เลี่ยงชื่อไฟล์ ชื่อโค้ด รหัสชิ้นงาน (ถ้าจำเป็นต้องเก็บ ให้แยกไปไฟล์ `archive/`)
- อ่านจบใน 10 วินาที
- **ห้ามใช้ขีดยาว** ตาม Definition of Done ใน CLAUDE.md ใช้เว้นวรรคแทน · **`·` ใช้ได้เฉพาะในบรรทัดที่เป็นรายการ** ห้ามใช้ในย่อหน้าและตาราง (ตัดสิน 2026-08-26)

**หัวข้อ `ติดปัญหา` เขียนตรง ๆ** สิ่งที่พลาด สาเหตุ และบทเรียน ไม่ใช่รายการอุปสรรคภายนอก

## 3. ส่งขึ้น Asana

**การบันทึกงานลง Asana มี 3 รูปแบบเท่านั้น** (user สรุปและยืนยัน 2026-09-07)

| # | รูปแบบ | ปลายทาง | เมื่อไหร่ | ต้องขออนุมัติไหม |
|---|---|---|---|---|
| **1** | **อัปเดต Task** | comment บนการ์ดงานใบนั้น | ก่อนปิดการ์ด และเมื่อมีเรื่องต้องบันทึกระหว่างทาง | **ต้องรอ user คอนเฟิร์มก่อนเสมอ** |
| **2** | **อัปเดตงานที่ทำแต่ละวัน** | comment ใน subtask `01 งานที่ทำ` ของการ์ดประจำเดือน | 16:30 ทุกวัน อัตโนมัติ | **ไม่ต้อง** push แล้วรายงานให้ทราบ |
| **3** | **อัปเดตงานค้างแต่ละวัน** | comment ใน subtask `02 งานค้าง` ของการ์ดประจำเดือน | 16:30 ทุกวัน อัตโนมัติ | **ไม่ต้อง** |

- รูปแบบ 1 = เฉพาะงานของการ์ดนั้น **ห้ามปนการ์ดอื่น**
- รูปแบบ 2 และ 3 = ภาพรวมทั้งวันข้ามทุกการ์ด อ่านจากไฟล์ worklog ในเครื่อง
- **ห้ามถามซ้ำเรื่อง push รูปแบบ 2 และ 3** user สั่งไว้แล้วว่าไม่ต้องรอคอนเฟิร์ม

### 3.1 รูปแบบข้อความ บังคับใช้กับทั้ง 3 รูปแบบ

> ข้อนี้เคยอยู่ใต้หัวข้อย่อยจนอ่านได้ว่าใช้เฉพาะ subtask ทำให้ comment บนการ์ดถูกส่งเป็นข้อความล้วนมาตลอด (พบ 2026-09-07) **ย้ายขึ้นมาเป็นกฎกลาง ใช้กับทุกคอมเมนต์ใน Asana ไม่มีข้อยกเว้น**

- **ต้องส่ง `html_text` เสมอ ห้ามส่ง `text`** ส่ง `text` ที่มี tag อยู่ข้างใน Asana จะโชว์ tag ดิบทั้งใบ (เคยพลาด 2026-08-24)
- tag ที่ใช้ได้ `<h2>` `<strong>` `<ul><li>` `<ol><li>` `<a href>` `<hr>` และขึ้นบรรทัดใหม่
- **ห้ามใช้ `<p>` `<b>` `<br>`** จะได้ 400 หรือไม่ render
- **ต้องมีลำดับหัวข้อ** ใช้ `<h2><strong>` เป็นหัวข้อ แล้ว `<ul><li>` เป็นรายละเอียด ไม่งั้นตัวอักษรขนาดเดียวกันหมด แยกไม่ออก
- ลิงก์การ์ด `<a href="https://app.asana.com/0/1212508564439334/{gid}">ชื่อการ์ด</a>`

**API**
- โพสต์ `POST /tasks/{gid}/stories` body `{"data":{"html_text":"<body>...</body>"}}`
- แก้ `PUT /stories/{gid}` ส่ง `html_text`
- ลบ `DELETE /stories/{gid}`

### 3.2 รูปแบบที่ 1 อัปเดต Task ในคอมเมนต์

> **↩️ เคยทำด่านตรวจแล้วถูกสั่งยกเลิก (2026-09-14)** เคยสร้างสคริปต์ที่ปฏิเสธไม่ยอมโพสต์ถ้าผิดกติกา บวกกฎห้ามยิง API ตรง แต่ user สั่งยกเลิกหลังเห็นข้อเสีย คือด่านตรวจได้แค่รูปแบบไม่ได้ตรวจเนื้อหา จึงสร้างความมั่นใจปลอม · กฎห้ามยิงตรงปิดทางแก้คอมเมนต์ใบเดิมซึ่งจำเป็นจริง · และบังคับหัวข้อผลตรวจกับคอมเมนต์ทุกชนิดซึ่งเข้มเกินไป
>
> **ให้ยิง API ตรงตามเดิม** และยึดรูปแบบในหัวข้อนี้ด้วยการอ่านก่อนเขียนทุกครั้ง **อย่าเสนอทำด่านตรวจอีกจนกว่า user จะขอ**


**ชนิดของคอมเมนต์** ให้ระบุชนิดไว้ในหัวข้อแรกเสมอ จะได้รู้ว่าคอมเมนต์ใบนั้นทำหน้าที่อะไรโดยไม่ต้องอ่านจนจบ

| ชนิด | ใช้เมื่อ |
|---|---|
| `worklog` | สรุปงานของการ์ดนั้นก่อนปิด |
| `แก้คำรายงานผิด` | เคยรายงานอะไรผิดไว้แล้วต้องแก้ให้ตรง |
| `เพิ่มขอบเขต` | เจอของที่ต้องทำเพิ่มระหว่างทาง |
| `ยกเลิกขอบเขต` | ตัดข้อใดข้อหนึ่งใน Requirements ออก พร้อมเหตุผล |

**โครงบังคับ**

```html
<body>
<h2><strong>ชนิด เช่น worklog ตามด้วยเลขลำดับ</strong></h2>
<ul><li>รายการสิ่งที่ทำ บอกทำอะไร เพื่ออะไร ได้ผลยังไง</li></ul>
<h2><strong>ผลตรวจ</strong></h2>
<ul><li>ตัวเลขที่ยืนยันได้ เช่น สีดิบ 0 · variant 40 แบบ · instance 30 ตัวไม่พัง</li></ul>
</body>
```

- **หัวข้อ `ผลตรวจ` ต้องมีตัวเลข** ห้ามเขียนว่าตรวจแล้วเรียบร้อย ต้องบอกว่าตรวจอะไรได้เท่าไร
- ถ้ามีเรื่องที่ไม่ได้ทำตาม Requirements ให้เพิ่มหัวข้อ `<h2><strong>ที่ไม่ได้ทำตามที่เขียนไว้</strong></h2>` พร้อมเหตุผล
- สไตล์การเขียนใช้กติกาเดียวกับ §2 คือกระชับ เน้นหลักการ ไม่ใช่ศัพท์โปรแกรมมิ่ง

**⚠️ หัวข้อต้องลงท้ายด้วยเลขลำดับของคอมเมนต์ในการ์ดนั้น** (user สั่ง 2026-09-11) คอมเมนต์ใบแรกของการ์ดลงท้ายด้วย `1` ใบที่สองลงท้ายด้วย `2` ไล่ไปเรื่อย ๆ นับแยกต่อการ์ด ไม่ใช่นับรวมทั้งโปรเจกต์

- ใช้กับหัวข้อทุกชนิด ไม่ใช่เฉพาะ `worklog` เช่น `ตัดสิน 1` `เพิ่มขอบเขต 1` `แก้คำรายงานผิด 2` `worklog 3`
- เลขคือลำดับของคอมเมนต์ ไม่ใช่ลำดับของชนิด ถ้าใบที่ 3 เป็น worklog ใบแรกของการ์ด ก็ยังลงท้ายด้วย `3`
- **ก่อนโพสต์ต้องนับคอมเมนต์ที่มีอยู่ในการ์ดก่อนเสมอ** แล้วใช้เลขถัดไป
- หัวข้อรองในใบเดียวกัน เช่น `ผลตรวจ` ไม่ต้องใส่เลข ใส่เฉพาะหัวข้อแรกของคอมเมนต์

## 4. วงจรวันที่ของการ์ด (3 วัน คนละหน้าที่)

| วัน | เก็บที่ | ตั้งเมื่อ |
|---|---|---|
| วันสร้างการ์ด | custom field **Assign Date** `1212991461878509` | ตอนสร้าง |
| วันที่หยิบมาทำ | **Start date** (`start_on`) | ตอนเริ่มลงมือ พร้อมย้ายสถานะเป็น In Progress |
| วันที่เสร็จ | **Due date** (`due_on`) | **หลัง push worklog ลงคอมเมนต์แล้ว** แล้วค่อยปิดการ์ด |

- **การ์ดที่ไม่มี due date จะตกไปล่างสุดของบอร์ด หาไม่เจอ**
- **ปิดการ์ด = ไปค้างที่ `Internal Review / Feedback`** ไม่ใช่ `Complete / Done` (ตัวหลังใช้ตอนตรวจผ่านจริงแล้ว)

**⚠️ Asana ตั้ง Start date เดี่ยว ๆ ไม่ได้** (เจอ 2026-09-10) ยิง `start_on` มาอย่างเดียวจะได้ 400 `start_on_requires_due_on_or_due_at` ต้องส่ง `due_on` มาคู่กันเสมอ วิธีใส่วันจึงแยกเป็น 2 กรณี (user ยืนยัน 2026-10-27)

| กรณี | ตอนเปิดการ์ด | ตอนปิดการ์ด |
|---|---|---|
| **การ์ดที่เริ่มทำตอนเปิด** | ยิง `start_on` เป็นวันที่เริ่มทำ คู่กับ `due_on` ชั่วคราว | แก้ `due_on` เป็นวันที่เสร็จจริง |
| **การ์ดที่เปิดย้อนหลัง** | ไม่ใส่วัน | ยิง `start_on` กับ `due_on` พร้อมกัน |

Assign Date เป็น custom field คนละตัว ใส่ตอนสร้างได้ตามปกติทั้ง 2 กรณี

**⚠️ เช็คลิสต์ตอนปิดการ์ด ต้องไล่ทุกข้อ** (ตั้ง 2026-09-07 หลังพบว่า Start date หายตอนปิดโดยไม่มีอะไรฟ้อง)

1. เขียน comment รูปแบบที่ 1 ตามโครงใน §3.2 แล้วรอ user คอนเฟิร์ม
2. ตรวจว่ามี **Assign Date** ครบ
3. ตรวจว่ามี **Start date** ครบ **ยิง `due_on` แล้วต้องอ่านค่ากลับมาดูว่า `start_on` ยังอยู่** เพราะเคยหายไปเงียบ ๆ
4. ตั้ง **Due date** เป็นวันที่ปิดจริง
5. ปิดการ์ดแล้ว **อ่านค่ากลับมาตรวจ** ว่าสถานะเป็น `Internal Review / Feedback` และวันที่ครบทั้งสาม

| `npm run worklog:asana [YYYY-MM-DD] [--dry]` | แปลงเป็น rich text แล้วโพสต์ขึ้นการ์ดปัจจุบัน `--dry` พรีวิวไม่โพสต์ |
| `npm run worklog:remind` | เตือน 16:00 ผ่าน notification (จ ถึง ศ) |
| `npm run worklog:schedule-on` / `-off` | เปิด ปิดตัวเตือน |
| `npm run worklog:obsidian [-- --dry]` | สำเนา worklog ทั้งหมดไป Obsidian พร้อมสรุปรายเดือน (ดู §7) |
| `npm run one-cms:obsidian [-- --dry]` | สำเนากฎโปรเจกต์และงานรายวันของ One CMS ไป vault ของโปรเจกต์ (ดู §8) |

- การ์ดปัจจุบันเก็บที่ `scripts/worklog-current-task.json` เปลี่ยนงานใหม่ต้องอัปเดตไฟล์นี้
- worklog ที่อยู่คนละการ์ด ต้องสำรอง config เขียน gid ใหม่ push แล้วคืนค่า
- ถ้า worklog วันนั้นว่าง (ไม่มี bullet จริง) สคริปต์จะข้าม ไม่โพสต์ comment เปล่า

## 6. ที่มาของกฎในไฟล์นี้

รวมจาก 3 ที่ที่เคยกระจายกันอยู่ `CLAUDE.md` (โครงสร้าง 3 ที่ push 16:30 วงจรวันที่) `docs/daily-log/_template.md` (สไตล์การเขียน) memory `worklog-asana-workflow.md` (gid กฎ `html_text`) แก้ที่ไฟล์นี้เป็นหลัก แล้วให้ที่อื่นชี้มาที่นี่

## 7. สำเนาไป Obsidian (เพิ่ม 2026-10-27)

> user ขอให้มี worklog รายเดือนเปิดอ่านใน Obsidian ได้ นอกจากไฟล์ใน repo **ไฟล์ใน repo ยังเป็นต้นทางที่เดียว** vault เป็นปลายทางไว้อ่าน

| ส่วน | ของจริง |
|---|---|
| สคริปต์ | `scripts/worklog-obsidian.mjs` สร้างใหม่ทั้งชุดจาก worklog ในเครื่องทุกครั้ง รันซ้ำได้ผลเดิม และเขียนเฉพาะไฟล์ที่เนื้อหาเปลี่ยน |
| คำสั่งมือ | `npm run worklog:obsidian` หรือ `npm run worklog:obsidian -- --dry` เพื่อดูว่าจะเขียนไฟล์ไหน |
| อัตโนมัติ | `worklog-month.mjs` เรียกก่อนส่ง Asana ทุก 16:30 ถ้าสำเนาพังจะเตือนใน log แล้วส่ง Asana ต่อตามปกติ |
| vault ที่ใช้ | `--vault <path>` ก่อน แล้ว `OBSIDIAN_VAULT` ใน `.env` แล้วค่อยค่าตั้งต้น `~/Documents/Obsidian Vault` |

**โครงใน vault** (user กำหนด 2026-10-27) สคริปต์เป็นเจ้าของโฟลเดอร์ `Worklog <ปี ค.ศ.>/` ไม่แตะส่วนอื่นของ vault

```
Worklog 2026/
├─ หน้าหลัก.md
└─ 10 October/
   ├─ Summarize 10 October.md
   ├─ Oct Week4 Mon26.md
   └─ Oct Week4 Tue27.md
```

- 1 ปี 1 โฟลเดอร์บนสุด ขึ้นปีใหม่สคริปต์สร้าง `Worklog 2027/` เอง หน้าหลักของแต่ละปีลิงก์หากัน
- ชื่อเดือนคือเลขเดือนกับชื่อเดือนภาษาอังกฤษ ชื่อรายวันคือ `<ชื่อย่อเดือน> Week<เลขสัปดาห์> <ชื่อวัน><วันที่>` เช่น `Oct Week4 Wed28` (ชื่อย่อเดือนเพิ่ม 2026-10-28 ตามที่ user สั่ง) ไม่มีปีทั้งคู่ เพราะปีอยู่ที่โฟลเดอร์บนสุดแล้ว
- เลขสัปดาห์มาจาก `weekOfMonth()` ใน `worklog-path.mjs` ตรงกับ `W` ในชื่อไฟล์ของ repo ชื่อใน vault ใช้เฉพาะใน vault ชื่อไฟล์ใน repo ยังตาม §1
- ชื่อโน้ตซ้ำกันได้ข้ามเดือนข้ามปี ลิงก์ที่สคริปต์สร้างจึงใส่ path เต็มจากราก vault เสมอ
- `หน้าหลัก.md` ลิงก์บันทึกล่าสุด งานค้างล่าสุด ทุกเดือน (เดือนใหม่อยู่บน) และรายชื่อ tag พร้อมจำนวนวัน
- บันทึกรายวันมี frontmatter `date` `day` `task` `month` `source` ตัดหัวข้อใหญ่บรรทัดแรกของต้นฉบับออกเพราะชื่อโน้ตบอกวันที่อยู่แล้ว
- สรุปเดือนมี 3 หัวข้อ `งานค้าง` จากวันล่าสุดของเดือน (ตรงกับ subtask `02`) · `งานที่ทำ` ทุกวันเรียงตามวันที่พร้อมผลลัพธ์ (ตรงกับ subtask `01`) · `ติดปัญหา` รวมทั้งเดือน ตัดรายการ "ไม่มี" ออก
- รหัสสีอย่าง `#fee4e2` ในเนื้อหาถูกครอบเป็นโค้ด ไม่งั้น Obsidian อ่านเป็น tag

**tag สำหรับค้นหา** (เพิ่ม 2026-10-27) ใส่ใน frontmatter ของบันทึกรายวันเท่านั้น สรุปเดือนกับหน้ารวมไม่ใส่ ผลค้นหาตาม tag จึงได้แต่วันที่ทำงานนั้นจริง

| หมวด | มาจาก |
|---|---|
| `project/` | ชื่อโปรเจกต์ `Nation-Design-System` ตั้งใหม่ได้ด้วย `WORKLOG_PROJECT` ใน `.env` |
| `system/` | `[System]` ในชื่อการ์ด DS กับ Design System กับ Global และการ์ดรุ่นเก่าที่ขึ้นต้นด้วยเลขหน้า รวมเป็น `Design-System` วันที่ไม่มีชื่อการ์ดก็ได้ค่านี้ |
| `feature/` | `[Feature]` ในชื่อการ์ด และหน้าในไฟล์ออกแบบที่เขียนแบบ "หน้า 21 Tags" Document เป็น Docs ส่วนพหูพจน์ของชื่อ component เป็นเอกพจน์ |
| `component/` | component ที่ถูกพูดถึงในบันทึกวันนั้น จับจากชื่อโฟลเดอร์ใน `components/` ทั้งแบบ `TagField` และ `tag-field` component ใหม่ได้ tag เองไม่ต้องแก้สคริปต์ |

- อยากให้วันไหนได้ tag ระบบกับฟีเจอร์ถูก ให้เขียนบรรทัด `> Task:` ตามชื่อการ์ดจริงและเรียกหน้าในไฟล์ออกแบบแบบ "หน้า NN ชื่อหน้า"
- `หน้าหลัก.md` มีรายชื่อ tag ทุกตัวพร้อมจำนวนวัน

**กติกา**

- **ห้ามแก้โน้ตใน vault** แก้ที่ไฟล์ใน repo แล้วรันสคริปต์ ของที่แก้ใน vault จะถูกเขียนทับรอบถัดไป
- เขียนหรือแก้ worklog หลัง 16:30 แล้ว ให้รัน `npm run worklog:obsidian` เอง ไม่งั้น vault จะตามทันในรอบ 16:30 ของวันทำงานถัดไป
- สคริปต์ลบได้เฉพาะไฟล์ที่ตัวเองเคยสร้าง (มีข้อความ "สร้างอัตโนมัติจาก worklog รายวัน") ซึ่งรอบนี้ไม่ได้สร้างแล้ว และโฟลเดอร์เดือนที่ว่าง ไฟล์ที่เขียนเองใน vault ไม่ถูกแตะ **ห้ามแก้ข้อความนี้ในสคริปต์** เพราะใช้แยกไฟล์ก่อนลบ
- เปลี่ยนชื่อไฟล์หรือโฟลเดอร์ใน `Worklog <ปี>/` ด้วยมือไม่ได้ผล รอบถัดไปสคริปต์จะสร้างชื่อเดิมกลับมาแล้วลบชื่อที่เปลี่ยน ต้องแก้ที่สคริปต์
- วันที่ของไฟล์อ่านจากหัว `# Worklog YYYY-MM-DD` ก่อน ไฟล์เก่าก่อนกลางเดือนตุลาคม 2569 บางวันหัวเป็นภาษาไทย สคริปต์จึงอ่านจากชื่อไฟล์แทนแล้วให้ `fileName()` ยืนยัน
- **⚠️ macOS กันโฟลเดอร์ Documents ไว้** ถ้าใน `docs/daily-log/.schedule.log` ขึ้นว่าสำเนาไป Obsidian ไม่สำเร็จพร้อม `Operation not permitted` ให้อนุญาตโปรแกรม node ที่ใช้รัน ใน System Settings หัวข้อ Privacy & Security แล้ว Files and Folders หรือย้าย vault ไปไว้นอก Documents แล้วตั้ง `OBSIDIAN_VAULT`
- vault ตอนนี้คือ `~/Documents/UXUI Worklog` ตั้งไว้ที่ `OBSIDIAN_VAULT` ใน `.env` (เปลี่ยนชื่อ 2026-10-27)

## 8. vault แยกของโปรเจกต์ One CMS (เพิ่ม 2026-10-28)

> user ขอให้ One CMS มี vault ของตัวเอง แยกจาก worklog vault เก็บทั้งกฎโปรเจกต์และงานรายวัน ต้นทางยังอยู่ใน repo ที่เดียวเหมือน §7

| ส่วน | ของจริง |
|---|---|
| สคริปต์ | `scripts/one-cms-obsidian.mjs` ใช้ตัวอ่าน worklog และกติกาการเขียนชุดเดียวกับ `worklog-obsidian.mjs` |
| คำสั่งมือ | `npm run one-cms:obsidian` หรือ `npm run one-cms:obsidian -- --dry` |
| อัตโนมัติ | `worklog-month.mjs` เรียกต่อจาก §7 ทุก 16:30 ถ้าพังจะเตือนใน log แล้วส่ง Asana ต่อตามปกติ |
| vault ที่ใช้ | `--vault <path>` ก่อน แล้ว `ONE_CMS_VAULT` ใน `.env` แล้วค่อยค่าตั้งต้น `~/Documents/One CMS` |

**โครงใน vault** สคริปต์เป็นเจ้าของ `หน้าหลัก.md` กับโฟลเดอร์ `Rules/` และ `Worklog <ปี ค.ศ.>/` ไม่แตะไฟล์อื่น

```
หน้าหลัก.md
Rules/
└─ กฎโปรเจกต์.md          จาก context/features/one-cms/AGENTS.md
Worklog 2026/
└─ 10 October/
   ├─ Oct Week4 Tue27.md
   └─ Oct Week4 Wed28.md
```

- `Rules/` คัดลอกไฟล์ `.md` ทุกไฟล์ใน `context/features/one-cms/` ตาม path เดิม `AGENTS.md` ใช้ชื่อ `กฎโปรเจกต์.md` ไฟล์ใน `pages/` `flows/` `decisions/` ที่จะมีต่อไปตามมาเอง
- บันทึกรายวันเก็บเฉพาะรายการระดับบนสุดที่มีคำว่า `One CMS` หรือ `one-cms` รายการย่อยใต้รายการนั้นติดไปด้วย ครบทั้ง 4 หัวข้อ ชื่อปี เดือน วัน แบบเดียวกับ §7
- วันที่มีแต่งานค้างของ One CMS (ยกต่อมาจากวันก่อน) ไม่นับเป็นวันที่ทำงาน จึงไม่มีโน้ต
- `หน้าหลัก.md` ลิงก์กฎ งานค้างล่าสุด และทุกวันที่มีงาน (วันใหม่อยู่บน)
- tag: `one-cms/worklog` ในบันทึกรายวัน `one-cms/rules` ในกฎ

**กติกา**

- **เขียน worklog ของงานนี้ให้มีคำว่า One CMS ทุกรายการ** รายการที่ไม่มีคำนี้จะไม่ขึ้นใน vault นี้ (ยังอยู่ครบใน worklog vault)
- ห้ามแก้โน้ตใน vault แก้ที่ repo แล้วรันสคริปต์ แก้ worklog หรือกฎหลัง 16:30 ให้รัน `npm run one-cms:obsidian` เอง
- สคริปต์ลบได้เฉพาะไฟล์ที่มีข้อความ "สร้างอัตโนมัติจาก repo nation-design-system สำหรับโปรเจกต์ One CMS" **ห้ามแก้ข้อความนี้ในสคริปต์**
- ปัญหา macOS กันโฟลเดอร์ Documents แก้แบบเดียวกับ §7
