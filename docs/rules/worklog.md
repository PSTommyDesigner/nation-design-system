# Worklog Standard Nation Design System

> ทุกวันที่มีงาน ต้องมีบันทึก 1 ชุด ไฟล์ในเครื่องเป็นต้นทาง ส่วน Obsidian เป็นปลายทางไว้อ่าน เลิกใช้ Asana แล้วตั้งแต่ 2026-11-03

## 1. เก็บที่ไหน

| ที่เก็บ | เนื้อหา | ใครอ่าน |
|---|---|---|
| `docs/daily-log/daily/<เดือนไทย ปีพ.ศ.>/W{สัปดาห์}-{Day}-{DD}-{MM}-{พ.ศ.}.md` | สรุปรายวันเต็ม ทุกการ์ดรวมกัน (ต้นทางเดียว) | สคริปต์ เรา หัวหน้า |
| `docs/daily-log/tasks/<ชื่องาน>.md` | บันทึกของแต่ละงาน 1 ไฟล์ต่อ 1 งาน (ดู §3) | สคริปต์ เรา หัวหน้า |
| Obsidian vault โฟลเดอร์ `Worklog <ปี ค.ศ.>/` | สำเนาที่สคริปต์สร้างให้ รายวัน สรุปเดือน 2 โน้ต บันทึกของงาน และหน้าหลักของปี (ดู §7) | เรา อ่านย้อนหลังรายเดือน |

**สัปดาห์เริ่มนับ W1 ใหม่ทุกเดือน** (W1 = สัปดาห์ที่มี worklog แรกของเดือนนั้น) ปี พ.ศ. = ค.ศ. + 543 คั่นวันที่ด้วย `-` เพราะ `/` ใช้ในชื่อไฟล์ไม่ได้

**ไฟล์ประกอบ**
- `docs/daily-log/_template.md` แม่แบบ 4 หัวข้อ (สคริปต์ `worklog:new` สร้างไฟล์ตามนี้)
- **`scripts/worklog-path.mjs` เป็นตัวเดียวที่รู้กติกาชื่อไฟล์** สคริปต์อื่นต้อง import จากที่นี่ ห้ามคำนวณเอง

**เคยมีโฟลเดอร์ `detail/` เก็บฉบับเต็มเชิงเทคนิค ลบแล้ว 2026-08-25** เพราะเป็นภาพถ่ายของสถานะที่ไม่มีอยู่แล้ว (รหัส node กับตัวเลขอ้างของที่เปลี่ยนไปหมดแล้ว) และไม่เคยถูกเปิดใช้จริง **ต่อไปเขียนบันทึกรายวันให้จบในไฟล์เดียว ไม่ต้องแยกฉบับเต็ม**

**เคยมีสำเนา `.txt` ที่ `Worklog/` ราก ยกเลิกแล้ว 2026-08-25** เพราะเนื้อหาเหมือนกันทุกไบต์ ต่างแค่นามสกุล ไม่ได้ให้อะไรเพิ่ม แลกมาด้วยการก๊อปด้วยมือทุกวันและความเสี่ยงที่สองฝั่งหลุดกัน สิ่งที่มีค่าคือวิธีตั้งชื่อ ซึ่งยกมาใช้กับ `.md` แล้ว

## 2. เขียนยังไง

**4 หัวข้อคงลำดับเสมอ** `งานค้าง` `งานที่ทำวันนี้` `ผลลัพธ์` `ติดปัญหา`

**สไตล์ (สำคัญที่สุด)**
- ย่อ กระชับ ภาษาไทยเข้าใจง่าย **เน้นหลักการ ไม่ใช่ศัพท์โปรแกรมมิ่ง**
- แต่ละ bullet บอก **ทำอะไร + เพื่ออะไร + ได้ผลยังไง**
- เลี่ยงชื่อไฟล์ ชื่อโค้ด รหัสชิ้นงาน (ถ้าจำเป็นต้องเก็บ ให้แยกไปไฟล์ `archive/`)
- อ่านจบใน 10 วินาที
- **ห้ามใช้ขีดยาว** ตาม Definition of Done ใน CLAUDE.md ใช้เว้นวรรคแทน · **`·` ใช้ได้เฉพาะในบรรทัดที่เป็นรายการ** ห้ามใช้ในย่อหน้าและตาราง (ตัดสิน 2026-08-26)

**หัวข้อ `ติดปัญหา` เขียนตรง ๆ** สิ่งที่พลาด สาเหตุ และบทเรียน ไม่ใช่รายการอุปสรรคภายนอก

## 3. บันทึกของงาน (แทนการ์ด Asana ตั้งแต่ 2026-11-03)

> **เลิกใช้ Asana ทั้งหมด** (user สั่ง 2026-11-03) ไม่สร้างการ์ด ไม่โพสต์คอมเมนต์ และไม่ส่งสรุปรายวันขึ้น Asana อีก บันทึกของการ์ดเก่า 100 ใบ 159 คอมเมนต์ดึงมาไว้ที่ `docs/daily-log/tasks/` แล้ว กฎเดิมของ Asana เก็บไว้ดูย้อนหลังที่ `docs/legacy/worklog-asana.2026-11-03.md`

**บันทึกมี 3 แบบ ทั้งหมดอยู่ในโปรเจกต์ แล้วสำเนาไป Obsidian**

| # | แบบ | ต้นทาง | ใน Obsidian | เมื่อไหร่ | ต้องขออนุมัติไหม |
|---|---|---|---|---|---|
| **1** | บันทึกของงาน | `docs/daily-log/tasks/<ชื่องาน>.md` | `Worklog <ปี>/Tasks/` | ระหว่างทาง และก่อนปิดงาน | **ต้องรอ user คอนเฟิร์มก่อนเสมอ** (คงไว้จากกฎเดิม) |
| **2** | งานที่ทำแต่ละวัน | worklog รายวัน หัวข้อ `งานที่ทำวันนี้` | `01 งานที่ทำ <เดือน>` 1 วัน 1 หัวข้อ | สำเนาตอน 15:30 อัตโนมัติ | ไม่ต้อง |
| **3** | งานค้าง | worklog รายวัน หัวข้อ `งานค้าง` | `02 งานค้าง <เดือน>` รายการเดียว ยกข้ามเดือน | สำเนาตอน 15:30 อัตโนมัติ | ไม่ต้อง |

- แบบ 1 เฉพาะงานนั้น **ห้ามปนงานอื่น**
- แบบ 2 และ 3 เป็นภาพรวมทั้งวันข้ามทุกงาน อ่านจากไฟล์ worklog รายวัน
- งานค้างที่เสร็จแล้ว ลบออกจากหัวข้อ `งานค้าง` ของไฟล์วันนั้น ข้อที่ยังไม่เสร็จเขียนต่อไปเรื่อย ๆ จนข้ามเดือน

### 3.1 ไฟล์ของงาน

- สร้างด้วย `npm run worklog:task -- "<ชื่องาน>"` สคริปต์สร้างไฟล์จากแม่แบบและตั้งเป็นงานปัจจุบัน
- ชื่องานตั้งตาม `docs/rules/task-naming.md` ชื่อไฟล์คือชื่องานที่ตัดวงเล็บเหลี่ยมออก เพราะวงเล็บทำให้ลิงก์ใน Obsidian ขาด
- หัวไฟล์ (frontmatter) เก็บ `name` `status` `project` `assign_date` `start` `due` `created` การ์ดที่ดึงจาก Asana มี `asana` เป็นลิงก์เดิมด้วย
- `status` ใช้ค่า `In Progress` ตอนทำ `Internal Review` ตอนส่งให้ตรวจ `Done` เมื่อตรวจผ่าน `On Hold` เมื่อพัก `Cancelled` เมื่อยกเลิก
- หัวข้อ `รายละเอียดงาน` ใช้แม่แบบ 5 หัวข้อ `Problem` `Goal` `Requirements` `Figma File` `Reference`
- หัวข้อ `บันทึกงาน` เพิ่มบันทึกต่อท้ายทีละครั้ง ห้ามแก้ของเดิมเว้นแต่เป็นการแก้คำรายงานผิด

### 3.2 รูปแบบบันทึกของงาน

**ชนิดของบันทึก** ระบุไว้ในหัวข้อเสมอ

| ชนิด | ใช้เมื่อ |
|---|---|
| `worklog` | สรุปงานก่อนปิด |
| `แก้คำรายงานผิด` | เคยรายงานอะไรผิดไว้แล้วต้องแก้ให้ตรง |
| `เพิ่มขอบเขต` | เจอของที่ต้องทำเพิ่มระหว่างทาง |
| `ยกเลิกขอบเขต` | ตัดข้อใดข้อหนึ่งใน Requirements ออก พร้อมเหตุผล |

**โครง**

```markdown
### 2026-11-03 worklog 2

- สิ่งที่ทำ บอกทำอะไร เพื่ออะไร ได้ผลยังไง

#### ผลตรวจ

- ตัวเลขที่ยืนยันได้ เช่น สีดิบ 0, variant 40 แบบ, instance 30 ตัวไม่พัง
```

- หัวข้อคือ `### <วันที่> <ชนิด> <เลขลำดับ>` เลขคือลำดับของบันทึกในงานนั้น นับแยกต่องาน ใช้กับทุกชนิด
- **หัวข้อ `ผลตรวจ` ต้องมีตัวเลข** ห้ามเขียนว่าตรวจแล้วเรียบร้อย
- ถ้ามีเรื่องที่ไม่ได้ทำตาม Requirements ให้เพิ่มหัวข้อ `#### ที่ไม่ได้ทำตามที่เขียนไว้` พร้อมเหตุผล
- สไตล์การเขียนใช้กติกาเดียวกับ §2

### 3.3 รอบ 15:30 อัตโนมัติ

| ส่วน | ของจริง |
|---|---|
| สคริปต์ | `scripts/worklog-month.mjs` เรียก `scripts/worklog-auto.mjs` เขียน worklog ที่ขาด แล้วสำเนาไป Obsidian ทั้ง 2 vault (§7 กับ §8) |
| คำสั่งมือ | `npm run worklog:month` |
| ตั้งเวลา | `com.nation.worklog-month` ทำงาน จ-ศ 15:30 (เปิด/ปิดด้วย `npm run worklog:month-on` / `worklog:month-off`) |
| log | `docs/daily-log/.schedule.log` |

**⚠️ สคริปต์อ่านหัวข้อแบบเป๊ะ** ต้องมี `## งานที่ทำวันนี้` และ `## งานค้าง` ในไฟล์ worklog และอ่านเฉพาะบรรทัดที่ขึ้นต้นด้วย `-` หรือ `*`

**เขียน worklog อัตโนมัติ** (ผู้ใช้สั่ง 2026-11-04 หลังวันที่ 3 ไม่มีบันทึก)
- ถ้ามีไฟล์ของวันนั้นแล้ว ข้าม ไม่เขียนทับ
- ถ้ายังไม่มี ดูว่าวันนั้นมีเซสชันการทำงานไหม จากข้อความของผู้ใช้ในบันทึกเซสชัน Claude ของโปรเจกต์ (รวม worktree) และ commit ของวันนั้น ไม่มีทั้งสองอย่างก็ข้าม
- ถ้ามี ส่งข้อความของผู้ใช้ สรุปท้ายรอบ และ commit ให้ `claude -p` ร่างตามกฎนี้และแม่แบบ โดยให้เครื่องมืออ่านไฟล์อย่างเดียว สคริปต์ตรวจว่าครบ 4 หัวข้อตามลำดับและไม่มีขีดยาวก่อนเขียนไฟล์
- ไฟล์ที่เขียนอัตโนมัติมีบรรทัด `> หมายเหตุ: เขียนอัตโนมัติจากรอบ 15:30` ให้ตรวจและแก้ในวันทำงานถัดไป
- คำสั่งมือ `npm run worklog:auto` (เพิ่ม `-- --dry` ดูโดยไม่เรียก Claude, `-- --date YYYY-MM-DD` เขียนย้อนหลัง)
- ข้อจำกัด: ใช้โควตา Claude ทุกวันที่มีงาน เครื่องต้องเปิดอยู่ตอน 15:30 และงานหลัง 15:30 ไม่อยู่ในบันทึก ให้เขียนเพิ่มเองแล้วรัน `npm run worklog:obsidian`

## 4. วันที่ของงาน (3 วัน คนละหน้าที่)

| วัน | เก็บที่ | ตั้งเมื่อ |
|---|---|---|
| วันมอบหมาย | `assign_date` | ตอนสร้างไฟล์ |
| วันที่หยิบมาทำ | `start` | ตอนเริ่มลงมือ พร้อมตั้ง `status` เป็น `In Progress` |
| วันที่เสร็จ | `due` | หลังเขียนบันทึก `worklog` และ user คอนเฟิร์มแล้ว |

**เช็คลิสต์ตอนปิดงาน**

1. เขียนบันทึก `worklog` ตามโครงใน §3.2 แล้วรอ user คอนเฟิร์ม
2. ตั้ง `due` เป็นวันที่เสร็จจริง และ `status` เป็น `Internal Review` (`Done` ใช้เมื่อตรวจผ่านจริงแล้วเท่านั้น)
3. ตรวจว่า `assign_date` กับ `start` ครบ
4. รัน `npm run worklog:obsidian` แล้วเปิดดูว่าโน้ตของงานใน vault อัปเดตแล้ว

## 5. สคริปต์

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run worklog:new` | สร้างไฟล์ worklog วันนี้จากแม่แบบ |
| `npm run worklog:task -- "<ชื่องาน>"` | สร้างไฟล์ของงานใหม่และตั้งเป็นงานปัจจุบัน |
| `npm run worklog:month` | รอบ 15:30 สำเนาไป Obsidian ทั้ง 2 vault |
| `npm run worklog:remind` | เตือน 16:00 ผ่าน notification (จ ถึง ศ) |
| `npm run worklog:schedule-on` / `-off` | เปิด ปิดตัวเตือน |
| `npm run worklog:obsidian [-- --dry]` | สำเนา worklog สรุปเดือน และบันทึกของงานไป Obsidian (ดู §7) |
| `npm run one-cms:obsidian [-- --dry]` | สำเนากฎโปรเจกต์และงานรายวันของ One CMS ไป vault ของโปรเจกต์ (ดู §8) |

- งานปัจจุบันเก็บที่ `scripts/worklog-current-task.json` ใช้เป็นบรรทัด `Task:` ของ worklog รายวัน `worklog:task` ตั้งให้เอง

## 6. ที่มาของกฎในไฟล์นี้

รวมจาก 3 ที่ที่เคยกระจายกันอยู่ `CLAUDE.md` (โครงสร้าง 3 ที่ push 16:30 วงจรวันที่) `docs/daily-log/_template.md` (สไตล์การเขียน) memory `worklog-asana-workflow.md` (gid กฎ `html_text`) แก้ที่ไฟล์นี้เป็นหลัก แล้วให้ที่อื่นชี้มาที่นี่

## 7. สำเนาไป Obsidian (เพิ่ม 2026-10-27)

> user ขอให้มี worklog รายเดือนเปิดอ่านใน Obsidian ได้ นอกจากไฟล์ใน repo **ไฟล์ใน repo ยังเป็นต้นทางที่เดียว** vault เป็นปลายทางไว้อ่าน

| ส่วน | ของจริง |
|---|---|
| สคริปต์ | `scripts/worklog-obsidian.mjs` สร้างใหม่ทั้งชุดจาก worklog ในเครื่องทุกครั้ง รันซ้ำได้ผลเดิม และเขียนเฉพาะไฟล์ที่เนื้อหาเปลี่ยน |
| คำสั่งมือ | `npm run worklog:obsidian` หรือ `npm run worklog:obsidian -- --dry` เพื่อดูว่าจะเขียนไฟล์ไหน |
| อัตโนมัติ | `worklog-month.mjs` เรียกทุก 15:30 ถ้าสำเนาพังจะบันทึกใน log |
| vault ที่ใช้ | `--vault <path>` ก่อน แล้ว `OBSIDIAN_VAULT` ใน `.env` แล้วค่อยค่าตั้งต้น `obsidian/UXUI Worklog` ใน repo |

**โครงใน vault** (user กำหนด 2026-10-27) สคริปต์เป็นเจ้าของโฟลเดอร์ `Worklog <ปี ค.ศ.>/` ไม่แตะส่วนอื่นของ vault

```
Worklog 2026/
├─ หน้าหลัก.md
└─ 10 October/
   ├─ 01 งานที่ทำ 10 October.md
   ├─ 02 งานค้าง 10 October.md
   ├─ Oct Week4 Mon26.md
   └─ Oct Week4 Tue27.md
```

- 1 ปี 1 โฟลเดอร์บนสุด ขึ้นปีใหม่สคริปต์สร้าง `Worklog 2027/` เอง หน้าหลักของแต่ละปีลิงก์หากัน
- ชื่อเดือนคือเลขเดือนกับชื่อเดือนภาษาอังกฤษ ชื่อรายวันคือ `<ชื่อย่อเดือน> Week<เลขสัปดาห์> <ชื่อวัน><วันที่>` เช่น `Oct Week4 Wed28` (ชื่อย่อเดือนเพิ่ม 2026-10-28 ตามที่ user สั่ง) ไม่มีปีทั้งคู่ เพราะปีอยู่ที่โฟลเดอร์บนสุดแล้ว
- เลขสัปดาห์มาจาก `weekOfMonth()` ใน `worklog-path.mjs` ตรงกับ `W` ในชื่อไฟล์ของ repo ชื่อใน vault ใช้เฉพาะใน vault ชื่อไฟล์ใน repo ยังตาม §1
- ชื่อโน้ตซ้ำกันได้ข้ามเดือนข้ามปี ลิงก์ที่สคริปต์สร้างจึงใส่ path เต็มจากราก vault เสมอ
- `หน้าหลัก.md` ลิงก์บันทึกล่าสุด งานค้างล่าสุด ทุกเดือน (เดือนใหม่อยู่บน) และรายชื่อ tag พร้อมจำนวนวัน
- บันทึกรายวันมี frontmatter `date` `day` `task` `month` `pending` `source` ตัดหัวข้อใหญ่บรรทัดแรกของต้นฉบับออกเพราะชื่อโน้ตบอกวันที่อยู่แล้ว
- สรุปเดือนแยกเป็น 2 โน้ต แทน subtask 01 กับ 02 ของ Asana เดิม (user สั่ง 2026-11-03) ทั้งคู่ลิงก์ไปบันทึกรายวัน
  - `01 งานที่ทำ <เดือน>` 1 วัน 1 หัวข้อ เรียงตามวันที่ พร้อมผลลัพธ์ และหัวข้อ `ติดปัญหา` ท้ายโน้ต
  - `02 งานค้าง <เดือน>` รายการเดียว ใช้งานค้างของวันล่าสุดที่เขียนไว้ ข้อที่เสร็จหายไปเองเพราะไฟล์รายวันลบข้อที่เสร็จออก ถ้าทั้งเดือนยังไม่มีงานค้าง จะยกรายการจากเดือนก่อนมาและบอกว่ายกมาจากวันไหน
- รหัสสีอย่าง `#fee4e2` ในเนื้อหาถูกครอบเป็นโค้ด ไม่งั้น Obsidian อ่านเป็น tag

**tag สำหรับค้นหา** (เพิ่ม 2026-10-27) ใส่ใน frontmatter ของบันทึกรายวันเท่านั้น สรุปเดือนกับหน้ารวมไม่ใส่ ผลค้นหาตาม tag จึงได้แต่วันที่ทำงานนั้นจริง

| หมวด | มาจาก |
|---|---|
| `project/` | ชื่อโปรเจกต์ `Nation-Design-System` ตั้งใหม่ได้ด้วย `WORKLOG_PROJECT` ใน `.env` |
| `system/` | `[System]` ในชื่อการ์ด DS กับ Design System กับ Global และการ์ดรุ่นเก่าที่ขึ้นต้นด้วยเลขหน้า รวมเป็น `Design-System` วันที่ไม่มีชื่อการ์ดก็ได้ค่านี้ |
| `feature/` | `[Feature]` ในชื่อการ์ด และหน้าในไฟล์ออกแบบที่เขียนแบบ "หน้า 21 Tags" Document เป็น Docs ส่วนพหูพจน์ของชื่อ component เป็นเอกพจน์ |
| `component/` | component ที่ถูกพูดถึงในบันทึกวันนั้น จับจากชื่อโฟลเดอร์ใน `components/` ทั้งแบบ `TagField` และ `tag-field` component ใหม่ได้ tag เองไม่ต้องแก้สคริปต์ |

- อยากให้วันไหนได้ tag ระบบกับฟีเจอร์ถูก ให้เขียนบรรทัด `> Task:` ตามชื่อการ์ดจริงและเรียกหน้าในไฟล์ออกแบบแบบ "หน้า NN ชื่อหน้า"
- `หน้าหลัก.md` มีรายชื่อ tag ทุกตัวพร้อมจำนวนวัน

**กติกา**

- **ห้ามแก้โน้ตใน vault** แก้ที่ไฟล์ใน repo แล้วรันสคริปต์ ของที่แก้ใน vault จะถูกเขียนทับรอบถัดไป
- เขียนหรือแก้ worklog หลัง 15:30 แล้ว ให้รัน `npm run worklog:obsidian` เอง ไม่งั้น vault จะตามทันในรอบ 15:30 ของวันทำงานถัดไป
- สคริปต์ลบได้เฉพาะไฟล์ที่ตัวเองเคยสร้าง (มีข้อความ "สร้างอัตโนมัติจาก worklog รายวัน") ซึ่งรอบนี้ไม่ได้สร้างแล้ว และโฟลเดอร์เดือนที่ว่าง ไฟล์ที่เขียนเองใน vault ไม่ถูกแตะ **ห้ามแก้ข้อความนี้ในสคริปต์** เพราะใช้แยกไฟล์ก่อนลบ
- เปลี่ยนชื่อไฟล์หรือโฟลเดอร์ใน `Worklog <ปี>/` ด้วยมือไม่ได้ผล รอบถัดไปสคริปต์จะสร้างชื่อเดิมกลับมาแล้วลบชื่อที่เปลี่ยน ต้องแก้ที่สคริปต์
- วันที่ของไฟล์อ่านจากหัว `# Worklog YYYY-MM-DD` ก่อน ไฟล์เก่าก่อนกลางเดือนตุลาคม 2569 บางวันหัวเป็นภาษาไทย สคริปต์จึงอ่านจากชื่อไฟล์แทนแล้วให้ `fileName()` ยืนยัน
- vault ตอนนี้คือ `obsidian/UXUI Worklog` ใน repo (ย้ายจาก `~/Documents/UXUI Worklog` เมื่อ 2026-11-02 ตามที่ user สั่ง) ไม่ต้องตั้ง `OBSIDIAN_VAULT` แล้ว โฟลเดอร์ `obsidian/` อยู่ใน `.gitignore` ไม่ขึ้น git
- เปิดใน Obsidian ด้วย Open folder as vault แล้วเลือก `~/nation-design-system/obsidian/UXUI Worklog`
- vault อยู่นอก Documents แล้ว ปัญหา macOS กันโฟลเดอร์ Documents (`Operation not permitted` ใน `docs/daily-log/.schedule.log`) จึงไม่เกิดกับ vault นี้อีก

## 8. vault แยกของโปรเจกต์ One CMS (เพิ่ม 2026-10-28)

> user ขอให้ One CMS มี vault ของตัวเอง แยกจาก worklog vault เก็บทั้งกฎโปรเจกต์และงานรายวัน ต้นทางยังอยู่ใน repo ที่เดียวเหมือน §7

| ส่วน | ของจริง |
|---|---|
| สคริปต์ | `scripts/one-cms-obsidian.mjs` ใช้ตัวอ่าน worklog และกติกาการเขียนชุดเดียวกับ `worklog-obsidian.mjs` |
| คำสั่งมือ | `npm run one-cms:obsidian` หรือ `npm run one-cms:obsidian -- --dry` |
| อัตโนมัติ | `worklog-month.mjs` เรียกต่อจาก §7 ทุก 15:30 ถ้าพังจะบันทึกใน log |
| vault ที่ใช้ | `--vault <path>` ก่อน แล้ว `ONE_CMS_VAULT` ใน `.env` แล้วค่อยค่าตั้งต้น `obsidian/One CMS` ใน repo (ย้ายจาก `~/Documents/One CMS` เมื่อ 2026-11-02) |

**โครงใน vault** สคริปต์เป็นเจ้าของ `หน้าหลัก.md` กับโฟลเดอร์ `Rules/` และ `Worklog <ปี ค.ศ.>/` ไม่แตะไฟล์อื่น

```
หน้าหลัก.md
Rules/
└─ กฎโปรเจกต์.md          จาก context/features/one-cms/AGENTS.md
Worklog 2026/
└─ 10 October/
   ├─ Oct Week4 Tue27.md
   └─ Oct Week4 Wed28.md
```

- `Rules/` คัดลอกไฟล์ `.md` ทุกไฟล์ใน `context/features/one-cms/` ตาม path เดิม `AGENTS.md` ใช้ชื่อ `กฎโปรเจกต์.md` ไฟล์ใน `pages/` `flows/` `decisions/` ที่จะมีต่อไปตามมาเอง
- บันทึกรายวันเก็บเฉพาะรายการระดับบนสุดที่มีคำว่า `One CMS` หรือ `one-cms` รายการย่อยใต้รายการนั้นติดไปด้วย ครบทั้ง 4 หัวข้อ ชื่อปี เดือน วัน แบบเดียวกับ §7
- วันที่มีแต่งานค้างของ One CMS (ยกต่อมาจากวันก่อน) ไม่นับเป็นวันที่ทำงาน จึงไม่มีโน้ต
- `หน้าหลัก.md` ลิงก์กฎ งานค้างล่าสุด และทุกวันที่มีงาน (วันใหม่อยู่บน)
- tag: `one-cms/worklog` ในบันทึกรายวัน `one-cms/rules` ในกฎ

**กติกา**

- **เขียน worklog ของงานนี้ให้มีคำว่า One CMS ทุกรายการ** รายการที่ไม่มีคำนี้จะไม่ขึ้นใน vault นี้ (ยังอยู่ครบใน worklog vault)
- ห้ามแก้โน้ตใน vault แก้ที่ repo แล้วรันสคริปต์ แก้ worklog หรือกฎหลัง 15:30 ให้รัน `npm run one-cms:obsidian` เอง
- สคริปต์ลบได้เฉพาะไฟล์ที่มีข้อความ "สร้างอัตโนมัติจาก repo nation-design-system สำหรับโปรเจกต์ One CMS" **ห้ามแก้ข้อความนี้ในสคริปต์**
- vault อยู่ใน `obsidian/` ของ repo ไม่ขึ้น git เหมือน §7 เปิดใน Obsidian จาก `~/nation-design-system/obsidian/One CMS`
